## 1. 错在哪（必须先讲清楚，否则会重犯）

| | 错误的做法 | 正确的做法 |
|---|---|---|
| 谁持有计划 | **DSH 会话**（外部） | **harness 自己** |
| 谁触发 | 外部提醒到点弹出来 | **harness 内部的时间/事件触发** |
| 谁做规划 | 外部 agent 来推 | **harness 规划它自己** |
| 结果存在哪 | DSH 的会话里 | **harness 自己的状态目录（append-only）** |

**为什么这个区别是本质的**：
- 外部提醒 = **别人催它**；它自己没有任何变化，关掉提醒它就停了。
- 自身能力 = **它自己知道"我该做什么、做到哪了、下次从哪继续"** ——
  这正是 Peter 反复说的「**对自己的规划**」，也是"世界模型"里**关于自身的那一部分**。

> **一句话**：**计划是它的，不是我们的。**

## 2. 设计：harness 自身的能力，三个部件

```
┌───────────────────────────────────────────────────────────────┐
│ ① 自身状态 Self-State（本机持久，append-only）                  │
│    · 我是谁：能力清单（从代码机械导出，VHS-PLAN-001 SK）           │
│    · 我打算做什么：**目标队列 + 计划 + 进度**（← 本次新增的核心）    │
│    · 我做过什么：轨迹 + 决策日志                                 │
│    · 我做错过什么：失败记录 + 用户纠正                           │
└───────────────────────────────────────────────────────────────┘
        │ 读
        ▼
┌───────────────────────────────────────────────────────────────┐
│ ② 自规划器 Self-Planner（走 default 通道）                       │
│    输入：Self-State + 目标                                        │
│    输出：**我接下来的计划**（步骤化、只用真实能力、含"做不到"的判断） │
│    写入：Self-State 的"我打算做什么"                              │
└───────────────────────────────────────────────────────────────┘
        │ 触发
        ▼
┌───────────────────────────────────────────────────────────────┐
│ ③ 自复盘 Self-Review（走 learn 通道，低频）                       │
│    输入：这一期的失败与纠正                                        │
│    输出：可复用规则 → 写回（**唯一写回入口**，ASR-MODEL-02 L2）     │
│    同时产出：**下一期的目标与计划**（回到 ①）                      │
└───────────────────────────────────────────────────────────────┘
```

**三者的关系**：**复盘产出计划，计划驱动行动，行动的失败又成为复盘的输入。**
这才叫闭环——而它**整个长在 harness 里**。

## 3. 触发机制（harness 内部，不是外部提醒）

| 触发类型 | 何时 | 走哪条通道 |
|---|---|---|
| **时间触发** | 每隔 N（天/周）由 **harness 自己的调度器**发起 | `learn` |
| **事件触发 A** | 一次任务失败 | `diagnose` |
| **事件触发 B** | 用户纠正了它（改字/否认/换说法） | 记入待学习队列 → 下次 `learn` |
| **事件触发 C** | 连续 N 次同类失败 | `diagnose` + 标记为待学习 |
| **手动触发** | 用户说「复盘一下」 | `learn` |

**硬要求**：
- 调度器**在 harness 进程内**（或其自身的服务里），**不依赖任何外部 agent**
- 状态落**它自己的数据目录**（append-only，JSON/JSONL，与 ASR 线一致的规范）
- 关机重启后**能接着做**（不是内存里的定时器）

## 4. 判据（全部应先红）

### SS 自身状态
| # | 判据 | 该做的 | 不该做的 |
|---|---|---|---|
| **SS-1** | 状态可持久 | 计划/进度落盘，**重启后仍在** | 只存内存 |
| **SS-2** | 状态可审计 | 每次计划变更可追溯（何时、为什么） | 覆盖式写入 |
| **SS-3** | 不重复劳动 | 知道"这件事我做过/做到哪了" | 每次从零开始 |

### SP 自规划
| # | 判据 | 该做的 | 不该做的 |
|---|---|---|---|
| **SP-1** | 计划只用真实能力 | 每步映射到能力清单内 | 出现不存在的工具 |
| **SP-2** | **做不到就说做不到** | 明确拒绝并说明缺什么 | 编一个执行不了的计划 |
| **SP-3** | 计划可续 | 中断后能从中断点继续 | 每次重头 |
| **SP-4** | 计划有依据 | 每步能说出"为什么现在做这个" | 无理由的步骤 |

### SR 自复盘
| # | 判据 | 该做的 | 不该做的 |
|---|---|---|---|
| **SR-1** | **自主触发** | 到点/到条件**自己发起**，无人催 | 等人说"你复盘一下" |
| **SR-2** | 产出可复用规则 | 输出**规则**而不是日志摘要 | 只写"这次错了" |
| **SR-3** | **写回可验证** | 写回的知识**下次真的命中且正确** | 写回即宣称学到 |
| **SR-4** | 唯一入口 | 只有 `learn` 通道写回（L2） | 在线通道偷偷写 |
| **SR-5** | 可回滚 | 学错了能撤销 | 不可逆污染 |

> **SR-1 与 SR-3 是这条线的灵魂**：
> **自己发起**（不靠人催）+ **写回后下次真的对了**（不是自我宣称）。

## 6. 诚实边界

- **本文件零实现。** harness 现在**没有** Self-State、没有自规划器、没有自复盘、没有内部调度器。
  所以 SS/SP/SR 三组**全部应先红**。
- **风险必须写明**：一个能**自主发起**并**自主写回**的系统，是这套设计里**最需要护栏**的部分。
  因此 `ASR-MODEL-02` 的 **L2/L3/L4（唯一写回入口、必须有证据来源、可关可审计可回滚）**
  是本文件的**前置条件**，不是配套建议。
- **未定义**：周期多长（需 Peter 定）、目标从哪来（Peter 给还是它自己提）、
  自主到什么程度（能否自己新增目标）——这三条是**产品判断**。
- 我**没有**验证过任何一条判据（因为能力不存在）。

## 7. 为什么这条比前面所有都重要

回头看这一个会话：Peter 纠正了几十次，DSH 修了 9 条缺口、改了 5 次判据、
澄清了 4 次角色——**所有这些"改进"，都发生在 harness 外面。**

> **harness 自己，从头到尾没有规划过任何一件事，也没有从任何一次纠正里学到任何东西。**

这条线就是把这件事**搬进它自己身上**：
**让它知道自己在做什么、做到哪了、做错了什么、下次怎么办。**
