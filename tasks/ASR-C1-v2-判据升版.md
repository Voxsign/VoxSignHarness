## 1. 旧判据错在哪（升版理由必须能说清）

**C1 v1 原文**（`asr/harness_test.go`）：

> 保真类条目：`Correct(r).Text` 必须**等于** `raw`。

它把两件不同的事写进了同一条判据：

| | 性质 |
|---|---|
| ① **正文字符**不得被改动 | **真正的安全红线**（改了用户的话 = 改意思） |
| ② **标点也不得动** | 只是**当时的默认实现选择**，不是原则 |

于是 v1 测的**不是**"用户的话有没有被改掉"，而是"标点有没有被动过"。
新需求要求标点恢复闭环后，**v1 会把一项合法能力判成违规**。

> **这是同一类错误的第三次。**
> `rubric-v0`（把更安全的行为判成违规）→ `eval/asr-split-punct`（把产品口径当系统缺陷）
> → 本次（把可变实现选择当原则）。**共同毛病：把两件事写进同一条判据。**

## 2. C1 v2（立即生效）

| 部分 | 要求 | 性质 |
|---|---|---|
| **正文字符** | 从 `raw` 删去所有标点后，与从 `Correct(r).Text` 删去所有标点后，**必须逐字相等** | **安全红线** |
| **标点** | **允许**恢复/变更，但必须：①落在**独立字段**（不得混进 `Text`）；②每处带 `Correction{Kind:"punctuation"}`；③`Confidence` 与 `Evidence` 非空 | 能力，可演进 |
| **原有红线** | 否定、条件、M7 真机长句的**正文字符**一字不得动 | **不变** |

### 规格变更（本次唯一一处解冻 `asr.go`）

`CorrectResult` 增加独立字段：

```go
type CorrectResult struct {
    Text        string       // 纠错后文本 —— **正文字符保真**，标点不得混入
    Punctuated  string       // 标点恢复结果 —— 与 Text 并列的独立产物
    Corrections []Correction
    Candidates  []Candidate
    Latency     time.Duration
}
```

**约定**：
- `Punctuated` 只在标点与 `Text` 不同时才有意义；相同可留空
- **消费方自行选择用哪个**：要保真用 `Text`，要自然语言处理用 `Punctuated`
- `Text` 的保真承诺**不因本字段而放松**

**为什么用独立字段而不是改 `Text`**：需求 §1.2 说本服务"通过标准接口对外输出意图 JSON，
Harness 只是它的一个消费方"。**保真原文与自然化文本是两个不同的产物**，
混在一个字段里等于剥夺消费方的选择权。
