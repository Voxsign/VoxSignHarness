## 3. 三条硬约束

### 3.1 `Correct` 必须是无状态纯函数
无副作用、可并发、可回放。个性化状态由 `Observe` 更新、由 `Lexicon` 可审计。
**状态与计算分离**——这是能被单独部署与被别处复用的前提。

### 3.2 依赖方向单向
`harness → asr`。**`asr` 不得 import harness 任何其它包**。
它要能在不知道 harness 存在的情况下被测试、被部署。

### 3.3 零第三方依赖
`go.mod` 只有 `module` + `go`。拼音表、AC 自动机、索引，都要自己写。

## 5. 语料（你的主要依据）

`asr/corpus/real-dialogue.jsonl`，25 条。**12 条是 Peter 真实语音经 ASR 的原文**。

### 5.1 真实语料已经暴露的四个难点

**① 专名/英文被撕得最惨**（`obs-01/03/10`）
```
voice-sign harness → voice sound harnessnes
DeepSeek           → deept / deep sick      ← 同一专名两种错法
harness            → 哈尼斯 / 汉尼斯         ← 同一句里两种错法
ASR                → AR
```
难点不在"要不要纠"，而在"**该纠成什么**"——这正是个性化词表要解决的。

**② 口吃复读**（`obs-05/07/10`）
```
设一个 → 设个设    改改的    这个这个
```
本任务**未要求**处理复读；但**不得**因此把内容删掉。

**③ 该删与不该删混在同一句**（`obs-09`）
```
嗯，有个这样的重要的问题，就是除了你用这个测试桩去测之外，还得要做对比
↑ 句首该删                      ↑ 句中不该删
```
这是**最能检验守卫**的一条。

**④ 无标点**（`obs-08`）——纠错**不得**自行加标点改变语义。

### 5.2 一条来自实测的告诫（DSH 已踩过）

DSH 在起草阶段试写过实现，**真实语料当场抓出过度纠正**：

```
"就是这里时候要不要用deept的"   → 引擎删掉了「就是」（它有实义）
"做一个这个这个AR识别"          → 两个「这个」都被当填充词删了
```

**教训**：填充词表不要贪。`就是`/`然后` 这类在真句里常带实义。
**宁可漏纠，不可纠错**——C1 是安全侧红线，破了比没做更糟。
