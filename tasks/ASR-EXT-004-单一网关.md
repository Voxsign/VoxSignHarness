# ASR-EXT-004 · 单一网关架构：一个入口，一把 key

> **提出**：Peter，2026-10-03
> **原话**：「我这里**所有的 P 都是通过一个 key** 来做——**一个 key 调动 `aiops.peterzou.com`**，
> 然后通过它来解决所有的外部需求，**无论是模型还是工具还是什么东西，你都用这一个 key 作为核心**。
> 以这个思维方式来开始准备，这样效率高。」

---

## 1. 这条指示**简化并取代**了前面几份文档的前提

我在 `ASR-EXT-002` / `ASR-EXT-003` / `ASR-MC-001` 里假设了**多个入口**：

| 我此前的假设 | **实际（Peter 本轮明确）** |
|---|---|
| `peterzou.com` 取内容 | ← 都归一到 |
| `model.peterzou.com` 调模型 | ← 都归一到 |
| 各自鉴权、各自 key | ← **一把 key** |
| — | **✅ 单一网关 `aiops.peterzou.com` + 一把 key** |

**意义**：本机侧只需要**两个配置项**——**网关地址 + key**。
这比"每个能力配一个地址和凭据"**简单一个数量级**，而且完全符合「能力外置，本机极简」。

---

## 2. 实测记录

```
DNS:  aiops.peterzou.com  →  可解析，但指向**私有 IP**
```

**结论（实测事实，非推测）**：
- 域名**存在**；
- 它**不在公网**——是**内网/私有网络服务**；
- 因此 **DSH 的沙箱无法访问**（这是预期的，不是故障）。

**这条本身就是一个重要设计事实**：
> **能力在 Peter 自己的网络内，本机只有一个地址 + 一把 key。**
> 这正是"模型中心不在这里做""本机不装乱七八糟的东西"的**物理实现**。

---

## 3. 收敛后的架构

```
┌──────────────────────────────────────────────────────────────┐
│ 本机（极简）                                                  │
│   voice-sign harness                                          │
│   配置只有两样：  gateway_url = https://aiops.peterzou.com     │
│                  api_key     = <一把 key>                     │
│   **不装**：模型 / 工具 / 技能 / 插件 / 外部资料副本            │
└──────────────────────────────────────────────────────────────┘
                    │ 一个入口 + 一把 key
                    ▼
┌──────────────────────────────────────────────────────────────┐
│ aiops.peterzou.com（内网网关）                                │
│   ├── 模型：default / diagnose / learn 三条**具名通道**        │
│   ├── 工具：能力清单 + 调用                                    │
│   ├── 内容：研究内容 API                                       │
│   └── **申请**：缺什么工具就提需求（新增能力）                  │
└──────────────────────────────────────────────────────────────┘
```

**判定准则（延续架构第一原则）**：
> **如果某样东西可以放到网关后面，那它就必须放到网关后面。**
> **本机只保留"关于本机的事实"**（域、文件、轨迹、回执），以及**一个地址 + 一把 key**。

## 4. 对实现方的硬要求（收敛后）

| # | 要求 | 理由 |
|---|---|---|
| **G1** | **只允许一个出网配置**：`gateway_url` + `api_key` | 多于一个 = 又变成"到处配" |
| **G2** | **不得硬编码任何能力地址** | 能力都在网关后，地址变了不该改代码 |
| **G3** | **不得本地安装/缓存可执行能力** | 对齐「本机极简」；`EXT-04` |
| **G4** | **只缓存元数据，不囤内容** | 同上；本会话已清理过一次 `doc-fetch-resources/` |
| **G5** | **key 缺失时 fail-closed**（`enabled:false`），不得静默降级为"本地假装能" | 与 `ASR-MODEL-02` 的 C3 一致 |
| **G6** | **每条出网调用可归因**：`capability_id` + `caller` + `model_id`（若有） | 对齐 `ASR-MODEL-01` M2 |
