# ASR-MODEL-02 · 模型中心三条调用通道（含「学习调用」）

> **提出**：Peter，2026-10-03
> **原话**：「模型中心设了三个模型的调用：一个叫**异常调用**；
> 第二个叫**默认调用**——以后默认，类似 DeepSeek V4.1 flash 这种；
> 还有一个叫**学习调用**——**你把学习调用这件事情要跟他讨论进去，让他有这个意识，让他规划进去**。
> 这个我觉得这个很有价值。」
>
> **性质**：**硬性接口规范**。凡是"能反思、能变好"的能力，都必须走这三条通道之一，不得旁路。

---

## 1. 三条通道

| 通道 | 什么时候用 | 期望特性 | 现状 |
|---|---|---|---|
| **默认调用** `default` | 常规推理：意图仲裁、自然语言理解、规划 | 快、便宜、模型固定（`deepseek-v4.1-flash`） | 设计存在，**未落地** |
| **异常调用** `diagnose` | 出错/失败时：问题定位（Jev 的诊断面） | 能分析根因，输出 cause 类 + 自愈动作 | 有接口，**M8 自报仍是模拟桩** |
| **学习调用** `learn` | **事后**：把一次真实使用变成**可复用的知识** | 慢、可以贵、**有写回** | **完全不存在** ← 本次新增 |

### 1.1 为什么"学习调用"是三者中最关键的

我在第 17 轮如实回答过 Peter：**这个 harness 没有学习回路。**

证据（当时的 grep，`memory/` `cache/` `ground/` `pipeline/`）：

```
Observe | Learn | Feedback | 回写 | 学习   →  结果为空
```

唯一窄的写回是「用户确认指代 → 别名固化进词典」。

**最能说明问题的事实**：那一整轮里 Peter 纠正了几十次、DSH 修了 9 个输入层缺口——
**每一条修复都是人去改 Go 代码，系统本身一件没学到。**

`学习调用` 就是补这个洞的**唯一入口**。

### 1.2 三条通道的分工（不要混）

```
默认调用  ── 向前看：现在该做什么        （在线，延迟敏感）
异常调用  ── 出了事：为什么坏了、怎么救   （在线，失败触发）
学习调用  ── 回头看：这次学到什么、怎么固化（离线/事后，可慢可贵）
```

> **关键区别**：前两条**不写回**持久知识；**只有学习调用写回**。
> 这样"系统变好"这件事就有了**唯一的、可审计的、可关掉的**入口。

## 2. 硬性规定

| # | 规定 | 违反时 |
|---|---|---|
| **L1** | 三条通道在配置里**具名固定**：`default` / `diagnose` / `learn`；每条的底层模型由 Peter 指定 | 未具名 = 无法归因 |
| **L2** | **只有 `learn` 通道可以写回持久知识**（词典、偏好、模式、知识库） | 在线通道写回 = 不可审计的漂移 |
| **L3** | `learn` 写出任何东西之前，**必须有证据来源**（哪次输入、谁确认的、结果如何） | 无来源的写回 = 幻觉固化 |
| **L4** | `learn` 的产出**可关、可审计、可回滚** | 不可回滚的学习 = 不可逆污染 |
| **L5** | 评测时**三条通道的模型都必须记录 `model_id`**（延续 `ASR-MODEL-01`） | 缺失 = 结论作废 |
| **L6** | `learn` **不得在关键路径上同步阻塞**用户请求 | 拖慢主链 |

## 3. 学习调用要解决的"越用越准"如何可测

Peter 反复强调"越用越准"。可测量的形式（写进 `VHS-COG`）：

```
① 同批语料重跑 → 正确率变化
② 每周新增 observed 语料量
③ **试金石**：上次判错的那类输入，这次判对了没有
```

**③ 是唯一真正的"学到"定义**——不是"模型变强了"，是"**同一个坑，没掉第二次**"。

**"学到"的完整链路**（缺一环就等于没学）：

```
用户纠正  →  记下（含上下文与原因）  →  学习调用抽取可复用规则
        →  写回（带来源与版本）      →  下次同类输入命中  →  验证真的对了
```

**注意最后两环**：写回**不等于**学到——**必须下次命中且正确**，才算学到。
否则只是把日志存了一遍。

## 4. 与自规划的关系（Peter 同时强调的两件事在这里合流）

Peter 说要让 harness「**能对自己的规划**」——把"我们对它的规划"变成"它自己的规划"。

**三条通道正好是自规划的输入**：

```
自规划器需要知道：
  · 我现在有什么能力        ← 能力清单（VHS-PLAN-001 SK）
  · 我过去做错过什么        ← 学习调用的产出
  · 我这次为什么失败        ← 异常调用的产出
  · 我该用哪条通道          ← **它必须自己判断**：常规走 default，
                              出错走 diagnose，**事后主动发起 learn**
```

> **"有学习意识"的可测形式**：给它一段真实使用记录，
> 它**自己判断出"这里该发起一次学习调用"**——而不是等人告诉它。

这条应作为判据：**`LEARN-01`：能从使用记录中主动识别值得学习的片段**（先红）。
