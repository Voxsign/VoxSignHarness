## 2. 对 harness 的考察标准：**输出必须是"差异"，不是"声明"**

Peter 的疑问本质是：**"我怎么知道它真学到了？"**

### 2.1 三种"输出"，只有一种可考察

| 形态 | 例子 | **可考察吗** |
|---|---|---|
| ❌ **声明** | "我已学习"、"记忆已更新" | **不可考察**——无法证伪 |
| ❌ **日志** | "本次处理了 14 条事件" | **不可考察**——量了活动，没量变化 |
| ✅ **差异** | **同一输入，前后的输出有什么不同** | **可考察** |

> **学习的输出 = 一份 diff。**
> **不是"我学到了什么"，而是"因为学到，某样东西变了"。**

### 2.2 可考察输出的四个要求（**这是本文的核心**）

| # | 要求 | 说明 |
|---|---|---|
| **O1** | **有 before/after** | 同一输入，学习前后的产物都在，可逐字对比 |
| **O2** | **有因果指针** | 这次输出里的每处差异，指到**哪条知识**、**哪次经历** |
| **O3** | **有可读产物** | 是一个**能打开看的文件/字段**，不是内部状态 |
| **O4** | **有可证的下一步** | 该知识**在下一次同类输入时被命中**（`SR-3`） |

**O1 是最关键的**：**没有 before/after，就无法判断"到底怎么样"** —— 这正是 Peter 说的那句。

### 2.3 落地形态：**学习台账（learn ledger）**

```
data/learn/
  ledger.jsonl              # 每次 learn 产出一条，append-only
  snapshots/
    <before>/plan.json      # 学到之前的产物
    <after>/plan.json       # 学到之后的产物
```

`ledger.jsonl` 每条：
```json
{ "op_id": "…", "at": "…",
  "trigger": { "kind": "user_correction|task_failure|manual", "evidence": "<轨迹 id>" },
  "learned": "…规则文本…",
  "destination": "criterion|guard|model",        // U1：必须指派去向
  "diff": { "before": "snapshots/a/plan.json",
            "after":  "snapshots/b/plan.json",
            "changed": ["plan.steps[2].tool"] },  // O1
  "caused_by": ["<证据 id>"],                     // O2
  "verified": { "at": "…", "hit": true, "correct": true }  // O4，可为 null
}
```

**考察时只看两样**：
1. **`diff.changed` 非空吗**？（空 = 没变化 = 没学到）
2. **`verified` 有值且 `hit && correct` 吗**？（无 = 还没证明学到）

## 3. 这条标准立刻暴露的三个问题

### 问题一：**现有 LEARN-01 的输出不可考察**

`LEARN-01` 的产出是**候选列表**（"这 14 条里该学 6 条"）。
**它是一个判定，不是一个差异。** 它证明了"检测器能跑"，**不证明"系统变了"**。

→ **要补 `LEARN-09`：同一输入，学后的输出必须与学前不同，且差异可追溯到学到的条目。**

### 问题二：**项目模型是快照，没有 before/after 链**

`eval/projmodel/*.json` 每次是**覆盖式快照**。
**没有历史 → 无法回答"它对这个项目的认识变化了吗"。**

→ 这正是校验方报的 **C10（时间维度）** 的另一种表现。

### 问题三：**规划器的输出没有"上次 vs 这次"**

`Plan` 是一次性的返回值。**没有对比，就无法判断"规划是不是变好了"。**
SOTA 调研说得很直白：**"规划质量未评估——只断言结构性质，不声称计划最优"**。

→ **要补：同一目标，历史计划留档，可对比步数/拒绝率/降级率的趋势。**

## 5. 诚实边界

- **本文零实现。** 台账、快照、diff 全部**不存在**。
- **`O2 因果指针` 是最难的一条**：把"输出的一处差异"归因到"某条知识"，
  **可能被误归因**（差异其实来自别的改动）。**本文没有解决误归因**，只要求"给出指针"。
- **`O4` 需要时间**：`verified` 字段要等下一次同类输入才填得上。**没填之前，这条学习就不算完成。**
- **我自己的例子（§1.1）也只是一条因果链的自述**，不是我证明的因果——读者可核，但归因仍可能有误。
- **未覆盖**：多条学习互相影响时怎么归因；长期不命中的知识怎么清理。
