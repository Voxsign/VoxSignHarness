---

## 1. 核心命题：**缓存不是性能优化，是一个本地的小模型**

我此前的理解是错的。我把它当成"为了快而存的副本"。
**Peter 说的是：它是一个「模型」**——**输入 → 关联 → 输出**，只是不用神经网络。

| | 我此前的理解 | **正确理解** |
|---|---|---|
| 定位 | 远端数据的副本 | **一个本地可推理的关联结构** |
| 目的 | 省一次调用 | **让"懂你"不依赖任何调用** |
| 内容 | 缓存响应 | **词、别名、模式、判断** |
| 匹配 | 精确命中 | **有"关联度"**（近音、别名、相似） |
| 失效 | TTL | **版本 + 新鲜度 + 可审计** |

> **一句话**：**它是一个装着"你最近在乎什么"的小模型，常驻本机，随时可问。**

## 2. 三层状态（进程 → 本机 → 远端）

```
┌──────────────────────────────────────────────────────────┐
│ L0 · 进程内（内存）—— 微秒                                │
│   热词表 / 当前会话上下文 / 本轮已解析的别名                │
│   特性：最快、重启即失、无持久化责任                        │
├──────────────────────────────────────────────────────────┤
│ L1 · 本机持久（磁盘）—— 毫秒                              │
│   个人词典 / 别名路由副本 / 能力清单快照 / 学习到的规则      │
│   特性：跨重启、可审计、**带 `fetched_at` 新鲜度**          │
├──────────────────────────────────────────────────────────┤
│ L2 · 远端（网关）—— 秒级                                   │
│   /api/route /api/services /api/hosts /api/model/*        │
│   特性：权威但慢；**只在 L0/L1 答不出时才去**               │
└──────────────────────────────────────────────────────────┘
      **铁律：能本地答的，绝不外调。**
```

## 3. 缓存里装什么（**四类，按"该不该调模型"排序**）

### 3.1 热词表（**最重要**）

> Peter：「**最近我跟你说的特别多的几个词，你肯定是要有人记得住的——你不需要调别的东西。**」

**这是一个"热度"结构，不是词表**：

```
term        热度   最近出现   来源
voice-sign  0.92   刚刚       用户原话
harness     0.88   刚刚       用户原话
JEV         0.71   3 轮前     用户原话
漂移        0.64   5 轮前     用户原话
```

**用途**：ASR 纠错、意图消歧、指代消解——**全部不需要外调**。
**这正是"最近说的词，它应该记住"的机制。**

### 3.2 别名路由（**`/api/route` 的本地副本**）

实测 `/api/route` 靠服务注册表的 `aliases` 做匹配，**且 aliases 里含 ASR 变形词**
（`爱ops` / `研究obc` / `沃克body` / `格罗克`）。

**这份表必须落到本机**——因为它**抗语音识别错误**，而语音识别是**每次都要用**的。

### 3.3 能力清单快照（带新鲜度）

> Peter：「**定期检查模型中心的各种能力。**」

**不是每次拉，也不是拉了就不管**：
- **启动时拉一次**（L2）
- **之后按 TTL 定期刷新**（例如小时级）
- **每条带 `fetched_at`**，过期标 `stale` 而非静默使用
- **刷新失败 ⇒ fail-open + 标 `unknown`，绝不静默当"没有"**（`ASR-EXT-005` A3）

### 3.4 学习到的规则（从 `learn` 来）

`VHS-LEARN-USE-001` 的去向 ②（守卫规则）落在这里。
**注意**：去向 ①（判据）不进缓存——**判据归人，不归缓存**。

## 4. "关联度"怎么做（**这是"小模型"的关键**）

Peter 说「**跟有点关联度**」。**精确匹配不叫模型，有关联度才叫。**

| 关联方式 | 例子 | 成本 |
|---|---|---|
| **精确** | `harness` → `harness` | O(1) |
| **别名** | `爱ops` / `aops` / `aiops` → `aiops` | O(1) |
| **拼音/近音** | `哈尼斯` → `harness` | 低 |
| **编辑距离** | `voise sign` → `voice-sign` | 低 |
| **热度加权** | 热词优先命中 | O(1) |

**前五种全部本地可算，全部微秒级。** 这就是"小模型"的实质：
**它是一组可组合的相似度函数 + 一张热度表**，不是神经网络，但**做的是同一件事**：
**输入一个模糊的东西，输出一个最可能的关联。**

**当关联度不足**（多个候选分数接近 / 最高分低于阈值）→ **那才是升级到 L1/L2 的信号**。
这与 `VHS-FASTSLOW-001` 的三层路由**是同一个机制的两面**。

## 5. 刷新与失效（**防腐烂**）

校验方报的 **C10**（否定性声明单向腐烂）在缓存上**更容易发生**：

| 机制 | 做法 |
|---|---|
| **新鲜度** | 每条带 `fetched_at`；超过 TTL ⇒ 标 `stale`，**不得静默当新鲜** |
| **版本** | 远端能力清单带版本；版本变了 ⇒ 整表失效重建 |
| **来源** | 每条带 `source`（`VHS-PROJMODEL-001` F1） |
| **可清除** | 缓存可删可重建，**重建结果一致**（`EXT-08`） |
| **不得成为隐性依赖** | 缓存缺失 ⇒ **能降级**（回 L2），不是崩溃 |

## 6. 落地要求（给实现方）

| # | 要求 |
|---|---|
| **K1** | **三层显式**（进程 / 本机 / 远端），每层有明确职责与延迟量级 |
| **K2** | **能本地答的绝不外调**——热词、别名、能力清单都在本地 |
| **K3** | **关联度**：至少实现 别名 + 拼音/近音 + 编辑距离 + 热度加权四路 |
| **K4** | **每条带 `fetched_at` + `source`**；过期标 `stale` 不静默使用 |
| **K5** | **刷新失败 fail-open 标 `unknown`**，不得当"没有" |
| **K6** | **缓存可删可重建，重建一致**；缺失能降级不崩溃 |
| **K7** | **定期刷新能力清单**（启动一次 + TTL） |
| **K8** | **关联度不足 ⇒ 升级信号**（接 `VHS-FASTSLOW-001` 的三层路由） |
| **K9** | **热词表必须在 ASR 纠错路径上被真的用到**，否则等于没有 |

## 7. 诚实边界

- **本文零实现**，且**我不写代码**（分工：DSH 出设计，实现方落地）。
- **"关联度"的算法与阈值我未标定**：拼音方案、编辑距离阈值、热度衰减曲线**全是待定**。
- **热词表的"热度"怎么算**（次数？时间衰减？谁更新？）**未定义**。
- **我不知道 `/api/route` 的真实匹配算法**——我只探了 3 个 query。
  本地副本若与远端算法不一致，**会产生"本地答得出、远端答不出"的分歧**，本文未解决。
- **我没有验证过"本地关联"能否达到可用的准确率**。这可能只是一个听起来好的想法。
- **缓存与隐私**：热词表会记录用户说过的话，**本机存储的边界未定义**（谁能读、何时清）。
