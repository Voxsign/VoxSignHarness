# VHS-LEARN-USE-001 · 学习输出怎么用：从「学到」到「改好」

> **Peter 2026-10-03**：「用你的规划能力来指导自身改进，或者说**同时用学习那个能力来指导自身的改进**。
> **因为他学习输出的这种内容，你打算怎么用**？」

---

## 1. 先回答一句话

> **学习输出不是用来"存"的，是用来"变成下一圈的输入"的。**
> **如果 `learn` 的产出只进了知识库而没改变任何判据、守卫或模型，那就等于没学。**

这一条我在 `VHS-SELF-001` 的 **SR-3** 立过（「写回不等于学到，必须**下次命中且正确**」）。
本文回答它的下一问：**命中之后，怎么用它推动改进。**

---

## 2. 学习输出的三个去处（按"是否立刻改变系统"排序）

```
真实使用（用户纠正 / 任务失败 / 指代确认）
        ↓
   learn 通道（唯一写回入口，带证据）
        ↓
   可复用规则（不是日志摘要）
        ↓
   ┌────────────┬────────────┬────────────┐
   ▼            ▼            ▼
 ①判据缺口    ②守卫规则    ③项目事实
 （要人立桩） （自动生效） （更新模型）
   │            │            │
   ▼            ▼            ▼
 下一圈的红判据  护栏变厚    规划器看到的世界更新
```

### ① 变成「判据缺口」—— **这是推动改进的主路**

**学到的"这类错"必须变成一条红判据**，然后走既有的自举闭环：

```
learn 产出「这类输入我会判错」
   → DSH 立红判据（判据先于实现）
   → 实现方修
   → 全量门禁
   → 异源盲评
   → 人合并
   → 下一圈
```

**关键**：**learn 没有权限自己立判据**——按 `ASR-MODEL-02` L2，它只能写回**知识**。
**把知识变成判据，是人的动作**（DSH 出判据，Peter 决定要不要做）。

> **为什么必须经过人**：判据是"尺子"。**让被测量的系统自己造尺子，尺子必然越来越松。**
> 这正是本项目反复强调的「builder ≠ approver」。

### ② 变成「守卫规则」—— **不用等人，自动变厚**

有些学到的不是"缺口"，而是"**这类能自己判定**"：

| 学到 | 变成 |
|---|---|
| 「`不用了` 后面没有动作词，不该弹确认」 | 一条**守卫**（不占人力的自动规则） |
| 「同一个问题问过第二次，不要再问」 | `askedQuestions` 去重（已在 G8 落地） |
| 「用户确认过的指代，固化」 | 四元组缓存 |

**这类直接进护栏**——因为它们**不改变判据，只减少噪声**。

**边界**：若某条守卫会**改变安全侧行为**（如"否定可以不问"），
**必须走 ① 走判据**，不得作为守卫自动生效。

### ③ 变成「项目事实」—— **喂给规划器**

`VHS-PROJMODEL-001` 的项目模型里，有三节是**会被 learn 更新的**：

| 节 | learn 更新什么 |
|---|---|
| `dependencies` | 新发现的依赖 / 某个端点失效 |
| `boundaries` | **新发现的"我做不到什么"** ← 最重要 |
| `state` | 当前进展 / 已知问题 |

**然后规划器读更新后的模型** → 产出更准的计划。
**这是"学习"和"规划"的接合点**：

> **学到的东西改变模型，模型改变计划，计划改变行为。**
> **缺任何一环，学习都不会影响行为。**

## 3. 硬约束（防"学了但没用"）

| # | 约束 | 违反的后果 |
|---|---|---|
| **U1** | **每条 learn 产出必须指派去向**：①判据 / ②守卫 / ③模型，**不得"仅入库"** | 学了等于没学 |
| **U2** | 去向为 ① 的，**必须由人生成判据**，learn 不得自造判据 | 尺子越来越松 |
| **U3** | 去向为 ② 的，**若触及安全侧 → 强制改走 ①** | 悄悄放宽红线 |
| **U4** | 去向为 ③ 的，**必须有 `source` 与时间锚**；世界是时变的（`EXT-005` 实测：主机 10→8） | 模型静默腐化 |
| **U5** | **每条 learn 产出必须可回滚**（`ASR-MODEL-02` L4） | 不可逆污染 |
| **U6** | **不得自训练回路**：learn 自己的产出不得再触发 learn | 自我强化幻觉 |

## 4. 怎么验证「学习真的推动了改进」

这是 `VHS-COG` 里那条**试金石**的具体形式：

```
① 记下：learn 在某次使用中产出了什么
② 记下：它为哪条判据/守卫/模型项提供了依据
③ 验证：下一圈那条判据**是否从红转绿**
④ 验证：同类输入**下次是否判对**（SR-3）
```

**指标**：

| 指标 | 定义 | 健康的样子 |
|---|---|---|
| **转化率** | 变成 ①/②/③ 的 learn 产出 / 总产出 | **不应为 0**——为 0 = 白学 |
| **闭环率** | 走了 ① 且**下一圈真的变绿**的 / 走了 ① 的 | 高 |
| **重复犯错率** | 同类错误再次出现 / 总错误 | **下降**才是学到 |

> **`重复犯错率` 是唯一无法伪造的指标**：
> 说"我学到了"很容易，**同一个坑不掉第二次**才是真的。

## 5. 诚实边界

- **本文零实现**。`learn` 通道本身目前只有 **LEARN-01 的检测器**（红→绿，零模型），
  **写回路径未实现**，更谈不上"输出被用起来"。
- **U1 的"必须指派去向"没有强制机制**——它现在是**人的纪律**，不是代码约束。
  要变成代码约束，需要 `learn` 产出的数据结构里有 `destination` 字段并要求非空。
- **"重复犯错率"需要真实使用数据**。本项目当前的语料
  （35 条，其中 22 条 observed、`usage-events` 全为 constructed）**不足以计算它**。
- **我不知道 `learn` 用什么模型**（Peter 未定），所以"学习质量"无法评估。
- 本文的 ①②③ 划分是**我的设计**，未经实战检验。

---

## 6. 一句话

> **学到的必须变成判据、守卫或模型——三者之一。**
> **只入库不改行为的，不算学到。**
> **而把知识变成判据的那一步，必须由人做：尺子不能让被量的人自己造。**
