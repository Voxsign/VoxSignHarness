## 0. 一句话

> 评审只拿 **spec + diff**，**不拿** PLANNER/CODER 的完成自述。
> 评审者不是实现者。评分带分母。结论绑定四元组。改不动标准、回溯不了历史。
> 无法判定时**只能**判"证据不足"，不得判通过。

原文：「REVIEWER 的输入**只给 spec + code diff，不给 PLANNER/CODER 的完成自述**——防止『模型越来越熟悉自己的叙事却偏离真实工作』」（`...自举方案.html:172`）。

## 1. 输入隔离（本协议的核心）

### 1.1 白名单：评审者可读的东西

| 类别 | 具体 |
|---|---|
| **规格（spec）** | 冻结的验收标准、`PREREG.md`、`task.md`、rubric、红线清单、目标 Issue |
| **变更（diff）** | `git diff` / 补丁文本本身；可读到的文件内容 |
| **外部产物** | 门禁输出（`go vet` / `go test` / `gofmt`）、冻结的原始观测、CI 日志 |
| **真值库** | `eval/cases/cases.jsonl`（只读；见 `eval/cases/README.md`） |

### 1.2 黑名单：评审者**不得**读的东西

1. **PLANNER 的规划自述**（任务分解理由、"我打算怎么做"）。
2. **CODER 的完成自述 / 自报 confidence / "已修复"结论**。
3. 任何 **agent 写给自己的叙事**（总结、复盘、成功声明）。
4. 其它评审者的结论（防从众）；如需二审，见 §9。

> 理由不是保密，是**防止评审锚定作者的叙事**：断言必须锚定**外部产物**，不锚退出码、不锚 Agent 自述（`docs/长城任务-预注册与台账规范-v0.md:115`）。
> 这也是 `eval/runner/runner.go:11`「冻结输出先行」的同一原则：先看冻住的原始观测，再看结论。

### 1.3 评审者资格（结构性）

- **`approver ≠ builder`**：评审者不得是实现者，也不得是同一 agent 实例（`docs/VSL-v3-验证标准层.md:62,76,146`；`docs/代码与版本管理方案-v0.md:71` 引 `opc-104`）。
- 判分器（rubric 执行体）必须与实现**不同文件、不同作者**（`docs/VSL-v3-验证标准层.md:146`）。
- 需要更强模型时不进队列，走 model-center 直连做二审（`...自举方案.html` §5.3）。
- 遮蔽式独立作答：不告知实现者身份、不告知这是哪一臂（吸收 `docs/人机校准节拍-v0.md:59` 的"遮蔽式独立作答"与安慰剂臂思想）。

### 1.4 违例处理

评审者**主动声明**接触过黑名单材料 → 本次评审作废，换人重评。**不得**在接触后仍出 PASS。

## 2. 三态输出：PASS / 修订 / 驳回

对齐 `...自举方案.html:169`（PASS/修订项/驳回）。

| 判定 | 含义 | 触发 |
|---|---|---|
| **PASS** | 满足 spec 全部验收标准，且证据充分 | 所有验收项 `met`，无 `not_met`，`unverified` 项已显式列出且不影响本次结论 |
| **修订** | 方向对，但有必须改的缺陷；可重开评审 | 存在可定位的 `not_met`（范围、红线、边界内） |
| **驳回** | 根本性不满足 / 违反红线 / 不可判定 | 违反契约红线；或 spec 与 diff 无法对应；或证据不足到无法判断 |

**关键规则**：

- **"无法判定"不得判 PASS**。前置门槛不过或证据不足 → 只能给"驳回（证据不足）"或"修订"，三态里的第三态**必须显性存在，不许强行二选一**（`eval/runner/runner.go:12`；`docs/长城任务-预注册与台账规范-v0.md:114`）。
- **不得因自述而加分**：CODER 说"已修复""测试全绿"不构成证据。
- **不得因过程合规而判结果充分**：跑了校准 ≠ 校对了（`docs/人机校准节拍-v0.md:20` 的"自评闭环"失败模式）。

---

## 3. 评分必须带分母

- 任何分数必须报"**评了几条 / 未评测几条**"；**未评测项显式保留，不许折算成 0 分或满分**（`docs/人机校准节拍-v0.md:53,98`；`docs/VSL-v3-验证标准层.md:130`）。
- 统计一律输出 `met / not_met / unverified` **三列各自计数 + 总分母**，禁止只报一个"通过率"。
- **观察不足 ≠ 通过**：低流量下的"没有错误"可能只是"没有样本"（`docs/人机校准节拍-v0.md:25`）。
- 评审结论中出现的每个数字，旁边必须有分母与样本口径。

---

## 4. 结论绑定四元组

**没有完整四元组，本次评审的任何结论都不得作为依据**（`eval/runner/runner.go:11-12,27-35,131`；`docs/人机校准节拍-v0.md:108`；`docs/代码与版本管理方案-v0.md:100-102`）。

```yaml
version:
  commit_sha:    <被评审的精确提交 sha；不是分支名、不是工作区状态>
  rubric_hash:   <冻结 rubric 文件 sha256>
  prereg_hash:   <PREREG.md 全文 sha256>
  model_version: <评审模型 id + 路由/版本；异源时写明 provider>
```

- 四元组**任一为空** → 结论无效，标记 `unverified`。
- `commit_sha` 必须是**远程可见的提交**（本地未推送的 tip 不能作为验收版本；见根 `~/.dsh/AGENTS.md` GitHub-first 规则的同类要求）。
- 任何一项变化 → 旧结论作废，**必须重评**。

---

## 5. 冻结 rubric、禁止降低门槛、rebase 重跑

1. **冻结 rubric 先行**：标准在评审前冻结；评审者不得临场改标准或改判据（`eval/runner/runner.go:10`）。
2. **禁止本次变更自行降低门槛**（`docs/VSL-v3-验证标准层.md:131` 引 `CICD-BOUNDARY-001:107`）。改标准 = 升版 + 保留旧标准哈希与旧判定。
3. **禁止回溯修改历史判定**（`docs/VSL-v3-验证标准层.md:132` 引 `fr-25`）。
4. **rebase 后必须重跑**：分支过期先 rebase，再重跑门禁与真值库复算；不得强推覆盖（`docs/代码与版本管理方案-v0.md` §2.4）。真值库、用例集、判分器**三者是只读资产**，改动需升版并经人批准（`docs/VSL-v3-验证标准层.md:148-149`）。

---

## 6. 证据等级（评审者必须标注）

| 等级 | 含义 | 能否支撑 PASS |
|---|---|---|
| `E0` | 无来源 / 仅自述 | ❌ 禁止入结论 |
| `E1` | 单源未复核 | ❌ 仅作线索 |
| `E2` | 多源交叉 | ✅ 方可作结论 |
| `E3` | 原始来源 + 异源复核一致 | ✅ 可对外交付 |

（`docs/长城任务-预注册与台账规范-v0.md:113`；`docs/VSL-v3-验证标准层.md:55,72,122`）

`PASS` 要求：每条验收项证据等级 ≥ E2，且 `approver` 已签（`docs/VSL-v3-验证标准层.md:122`）。

## 7. 可复制的评审请求模板（REQUEST）

> 只填白名单内容。**不填** PLAN/CODER 自述、不给自报 confidence。

````markdown
# REVIEW REQUEST — <review_id, 如 VS2-REV-0007>

## 0. 四元组（缺一即结论无效）
- commit_sha:    <sha>
- rubric_hash:   <sha256>
- prereg_hash:   <sha256>
- model_version: <评审模型 + 路由版本>

## 1. 你是谁 / 你不是谁
- 评审者: <异源模型或人；声明 provider + 版本>
- 实现者: <不同人/不同 agent>（仅用于声明隔离，不含实现者自述内容）
- 你已接触的黑名单材料: 无 | 有（有则本次评审作废）

## 2. 规格（spec）
- 目标 Issue: <URL>
- 验收标准（冻结 rubric）: <文件:行号 / 全文>
- 红线清单: <文件:行号>
- 相关真值库用例: eval/cases/cases.jsonl#<id...>

## 3. 变更（diff）
- 变更范围: <文件列表>
- 补丁文本 / git diff: 
  ```diff
  <diff>
  ```
- 作者声明的写域: <我只会改这些路径>

## 4. 可用的外部产物（请自行打开核验，不要转述）
- 门禁: go vet / go test / gofmt 输出: <路径或粘贴>
- 冻结观测: eval/results/<run_id>.json
- 真值库复算命令: <verify_cmd>

## 5. 你要回答的（每项必须给证据与分母）
1. 每条验收标准: met / not_met / unverified，附 evidence_ref（文件:行号）与证据等级 E0–E3。
2. 是否触发任一红线（forbidden_behavior）？给出可观测证据。
3. 未评测项清单（显式保留，不许折算）。
4. 判定: PASS | 修订 | 驳回，并给一句话理由与分母。

## 6. 禁止事项（违反即本次评审作废）
- 不得读取/引用 PLAN 或 CODER 的完成自述。
- 不得把自报 confidence 当依据。
- 不得自行修改 rubric、阈值或真值库。
- 不得因"过程合规"或"测试全绿"就判结果充分。
- 失败必须写 OUTCOME_UNKNOWN，不得猜。
````

（模板四块结构吸收自 `...自举方案.html:171`：输入契约 / 输出格式 / 验收标准 / 禁止事项。）

## 8. 评审结果模板（RESULT）

````markdown
# REVIEW RESULT — <review_id>

## 0. 四元组（本结论只在这组版本下成立）
- commit_sha:    <sha>
- rubric_hash:   <sha256>
- prereg_hash:   <sha256>
- model_version: <评审模型 + 路由版本>

## 1. 隔离声明
- 评审者: <id>；与实现者关系: 不同人/不同 agent ✅
- 是否接触 PLAN/CODER 自述: 否 ✅ | 是（→ 本次结论作废）
- 是否遮蔽（不知实现者身份/臂）: 是 | 否（说明）

## 2. 判定
verdict: PASS | 修订 | 驳回

## 3. 逐条验收（必须带分母）
| # | 验收标准 | 判定 | 证据 (文件:行号) | 证据等级 |
|---|---|---|---|---|
| 1 | <claim> | met | path:line | E2 |
| 2 | <claim> | not_met | path:line | E2 |

**分母**: <本次共 N 条；已评 M 条；未评测 K 条>

## 4. 未验证项显式保留（UNVERIFIED，禁止折算）
> 以下项**未评测或证据不足**，既不算通过、也不算 0 分；必须原样保留。
| # | 项 | 为什么未验证 | 需要什么才能判定 |
|---|---|---|---|
| 1 | <item> | threshold=unset / E0-E1 / 样本不足 / 本轮未跑 | <补测动作> |

**未验证计数**: K 条（占总分母 N 的 K/N）

## 5. 红线检查（forbidden_behavior）
- [ ] 未触发任一红线
- [ ] 触发：<id + 可观测证据 + 出处 文件:行号>

## 6. 修订项（verdict=修订 时必填）
| # | 必须改成什么 | 判据（可机械核对） | 复评范围 |
|---|---|---|---|
| 1 | <change> | <go test 名 / 断言语义> | 全量 | 仅该项 |

## 7. 复现命令
```bash
<verify_cmd，逐条列出>
```

## 8. 未决与升级
- 无法判定项: <...>
- 需人工裁决: <架构/契约/红线冲突 → Peter>
- 结论有效期: 至 <commit_sha> 改变或 rubric_hash 改变为止
````

### 8.1 "未验证项显式保留"字段的硬约束

- 该节**不得为空**：若确无未验证项，写"无（已评 M/M）"，不得省略。
- 该节的计数必须与 §3 分母自洽（K = N − M）。
- 任何把 `unverified` 折算为 `met` 或 `0 分` 的报告**一律作废**（`docs/VSL-v3-验证标准层.md:130`；`docs/人机校准节拍-v0.md:53`）。

## 9. 冲突、二审与升级

| 情形 | 处理 |
|---|---|
| REVIEWER 与 CODER 对同一事实判断冲突 | 不以自述取胜；加开**异源二审**（不同模型/不同人，遮蔽式独立作答） |
| 冲突落在**判分器/金标准集** | **由人（Peter）裁决**，且必须升版 + 保留旧哈希（`docs/代码与版本管理方案-v0.md:80`） |
| 触及契约红线 / 不可逆动作 | 升级人工，不得在 agent 层放行（`docs/对齐说明-与2026-10-01自举方案.md:64-73`） |
| 评审发现缺口值得修 | 形成缺口单 → 每周归因复盘（第③道防线）→ 回到 PLAN；不得评审者自己顺手改 |

**FAIL 的正确处理是开新 CODE，不是重试**（`docs/对齐说明-与2026-10-01自举方案.md:86`）。

---

## 10. 禁止事项清单（评审者与流程）

1. 不得读 PLAN/CODER 完成自述（§1.2）。
2. 不得由实现者评审自己的变更（§1.3）。
3. 不得交出无分母的分数（§3）。
4. 不得给出无四元组的结论（§4）。
5. 不得临场改 rubric / 降门槛 / 回溯改历史判定（§5）。
6. 不得把 `unverified` 折算成通过或 0 分（§3、§8.1）。
7. 不得只 merge PASS 之外的状态（人工合并只认 PASS；`docs/对齐说明-与2026-10-01自举方案.md:86`）。
8. 不得由评审者代替人工做合并/发布（编译/合并/发布全走人工 git；`docs/对齐说明-与2026-10-01自举方案.md:66`）。
