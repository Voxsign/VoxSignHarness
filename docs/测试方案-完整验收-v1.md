## 4. 怎么证明「达到目标」（判定规则）

1. **三态**：
   - **PASS**：判据在对应口径下全绿 + 证据可复核（数据目录/日志/代码行号）。
   - **修订**：部分红，或依赖降级（degraded=True 才绿），或双配置结果不一致。
   - **驳回**：判据设计错（测的不是用户走的那层）/ 实现根本没接（死代码）。
2. **无法判定**：信息不足（无真实样本/无 key/无端点）——不许用「应该/大概」补位。
3. **判定依据只有**：代码真值 + 真跑证据。实现方的汇报理由不参与判定。
4. **双配置并列**：钉规则式（`accept.sh` 默认）与真装配级（`VHS_MODEL_CENTER=config/model-center.json`）必须同时呈现。

```
【判据】<编号> <一句话目标>

【修订方向】<判据口径 / 实现侧 / 基础设施侧 —— 只给方向，不越界替实现方定案>
【验证方式】<改完用哪条命令验，PASS 的标准是什么>
【状态】待实现方回应 → 回读复验 → 三态
```

> 对实现方的回应**不照单全收**：它说改好了不算，回读 + 真跑才算；有异议摆证据。
