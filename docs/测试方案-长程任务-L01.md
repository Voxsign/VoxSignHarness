## 0. 长程任务目标（用户口径）

> 「写一个比较复杂的任务让它能产出，然后不断地能产出，一次性搞定一长程任务。」

- **复杂度**：不是单点功能，是**完整服务**（架构 + 接口 + 数据闭环 + 红线 + 非功能）。

- **可持续产出**：实现 → 测试方验收 → 修订 → 再产出，直到第 11 章全绿。

## 5. 怎么测（测试方执行流）

```
1. 起最新版 harness（线 A：VHS_TOKEN+VHS_API_KEY+VHS_ASR_ENDPOINT，模型路径通）
2. 构造长程任务输入：text = 任务指令（引用 PDF 路径与目标）+ document = PDF 全文/章节结构
3. 经 /v1/tasks（或 /v1/voice）提交，观察 harness：
   · 规划：是否读文档（considered/document_read）、是否拆解长程步骤（分批）、是否越域
   · 执行：executor 是否真的产出（写代码/跑测试/产出物），还是 BOUNDARY_VIOLATION/回问
   · 终态：need_ask / done / canceled / error —— 是否到可交付终态
4. 若 harness 产出实现 → 按本文档第 2–4 章独立验收产出物（真跑）
5. 若 harness 卡住/产不出 → **记录为 harness 能力缺口**，按 §5 卡片报给实现方 deepseek 补 harness
6. 三态：harness 完成长程任务 = PASS；部分产出/缺口 = REVISE；完全产不出 = REVISE（报缺口）
```

## 7. ⭐ L-01 首次实测记录（2026-10-03，harness 长程任务能力）

**输入**：PDF 全文（8308 字符，201 段）作 document + 任务"按需求说明书实现可编译可运行的 Go 独立服务，满足第 11 章 6 条验收标准"。

| 层 | 实测结果 | 证据 |
|---|---|---|
| 规划·规则式 | 读文档（document_read=True, considered=18）→ **只给 2 步只读探查**（readonly-probe, degraded=True），不拆解实现步骤 | `/tmp/long_resp.json` |
| 规划·L2 真装配 | 读文档 → **模型拒绝编造计划**（refused=True, reason="无法判定目标所需能力，不编造计划"）→ 降级 2 步只读探查；耗时 60s（nginx 掐断） | `/tmp/long_l2_resp.json` |
| 执行·线 A | 意图 **UNKNOWN → need_ask 回问**（8+1 类意图无"实现服务"类），未执行 | 线 A `/v1/tasks` 实测 |

**三态结论**：**REVISE** —— harness 当前**产不出**「按 PDF 实现个性化 ASR 后台」的长程任务实现。

### 三个能力缺口（报实现方 deepseek 补 harness）
1. **意图缺口**：长程任务（"实现一个服务"）不在现有 8+1 意图（EDIT/DEBUG/QUERY/TEST/COMMIT/DEPLOY/NOTE/ASK/ORCHESTRATE）的清晰匹配内 → UNKNOWN 回问。需新增「长程任务/IMPLEMENT」意图或扩展 ORCHESTRATE 语义。
2. **规划缺口**：规则式对长程任务无拆解模板（只给只读探查）；L2 模型保守拒绝编造计划（模型能读懂文档但无"实现步骤"产出路径）。需长程规划模板（需求→模块→接口→验收 拆解）或允许模型产出实现计划（配合文档消费）。
3. **执行缺口**：域内无工具声明，一切域动作 BOUNDARY_VIOLATION；即使有计划也执行不了。需域/工具声明 + executor 接真实执行（写文件/跑 go build/test）。

**红线核查（本次实测顺带）**：全程 `execute:false`（Ask≠'' 绝不执行）✅；越域拒绝 ✅；模型不编造（refused）✅ —— 红线面是健全的，缺口在"能产出"这一面。
