## 4. 必须遵守的既有边界（1.0 明确不支持，我不许越线）

1. **不能自改发布**：编译/合并/发布全走人工 git。
2. **不能任意 shell**：高危命令默认拦截、交互命令拦截、超时钳制。
3. **不能自动改已发布契约**：只能新增 `@1.1/@2.0`，且要 supersede 归档。
4. **不能推断**：未知就是未知，必须回问。
5. **不能跨端点盲目重跑**：`OUTCOME_UNKNOWN` 先核对。
6. **不能发外部消息 / 动远端写**：V0 副作用仅限本地。

人工必须保留：契约签署、验收判定、合并与发布、激活翻转、付钱/对外承诺、Benefit 算账。

## 5. 因此，修订后的"闭环"长这样

```
① 取缺口       归因台账 / 缺口单（stage 字段）
② PLAN         OPC(PLANNER)：拆任务清单 + 依赖 + 每条的机械验收标准
③ CODE         OPC(CODER)：产出补丁文本 + 自测证据        ← 不改仓库
④ [人] 应用     人工把补丁贴回仓库                          ← 显式人工步骤，不伪装自动化
⑤ 门禁          CI：vet / test / gofmt / 可复现构建
⑥ REVIEW       OPC(REVIEWER)：只拿 spec + diff，输出 PASS/修订/驳回
⑦ [人] 合并     只 merge PASS；FAIL 开新 CODE（**不是重试**）
⑧ 评测          eval/cases.jsonl（人维护的真值库）+ LHT 族 → 六层读数
⑨ 回写          每周归因复盘，六格结论由人确认 → 回到 ①
```

与之前版本的差别：**④⑦ 两步是人的，不能自动化**。
