## 一、三处遗留问题修复（本机侧，代码改动）

对应《测试结果报告-云端服务器端功能-20261005.md》问题 1/2/3：

| # | 问题 | 修复 | 文件 |
|---|---|---|---|
| 1 | zhiji 包编译错误（`SelfItem` 缺 Status 字段，`go test ./...` 全量失败） | `SelfItem` 增加 `Status Status \`json:"status"\`` 字段；`UpsertSelf` 新建条目默认 `StatusActive`（superseded 替换逻辑不变：旧条目置 `StatusSuperseded`，新条目保持 active，`TestUpsertSelfVersioned` 锁定） | `zhiji/model.go`、`zhiji/store.go` |
| 2 | 本地模式 `/v1/devices/register\|heartbeat` nil panic（`s.devices` 仅云端创建，路由无条件注册） | `deviceToken` 中间件入口判 `s.devices == nil` → **501**「设备注册表仅云端模式可用」，绝不触碰 `s.devices`；public 路由 `handleDevicesLookup` 入口加同样 nil → 501 防护 | `server/devices.go` |
| 3 | 云端 `VHS_TOKEN` 为空时设备接口裸注册（两端凭证都空即放行） | `deviceToken` 中间件加硬保护：`s.cfg.Server.Token == ""` → **503**「服务端未配置 VHS_TOKEN（配置错误）」 | `server/devices.go` |

**防护顺序与状态码理由**（已写入代码注释）：

1. 先判 `s.devices == nil` → **501**。本地模式的问题是「该功能按设计未启用」，而非「配置错误」；若把 token 空检查放前面，本地模式（恰好也没配 token）会误报 503。此顺序同时满足两个验收场景：本地模式→501、云端漏配→503。
2. 再判 `Server.Token == ""` → **503**。此时必为云端模式但漏配：客户端无从提供有效凭证，不用 401（401 暗示「带正确 token 再来」，此处根本没有 token 可带）。
3. 最后正常比对：凭证不匹配 → **401**。

**连带修复**（包首次可编译运行后暴露的潜伏缺陷，均为首次运行即见）：

| 项 | 根因 | 修复 |
|---|---|---|
| `Registry.SetDefault` 自死锁 | 持写锁 `defer Unlock` 的同时调 `save()`（内部自取 `RLock`），RWMutex 不可重入 → 整包测试卡满 600s | 改为与 `Register()` 同款「先 Unlock 再 save」（`zhiji/registry.go`） |
| STM 条目检索不可见 | `TouchSTM` 未默认 Status，`Search`/写前验证/外化全部跳过 STM（写不进=检索不到） | 补 `if item.Status == "" { item.Status = StatusActive }`，与 `WriteMemory` 同款（`zhiji/store.go`） |
| 集成测试基线断言不可达 | 新 store 无 goal 条目，「决策注入应含目标基线」在设计上不可能成立 | 测试在 `BeforeDecision` 前经契约写入一条种子目标，断言保持不变（`zhiji/zhiji_test.go`） |

## 四、云端 VHS_TOKEN 闭环状态

| 侧 | 状态 |
|---|---|
| 本机修复侧（本仓库当前码） | ✅ **硬保护已就位**：云端模式 `Server.Token == ""` → register/heartbeat 一律 503（`TestDevicesCloudEmptyTokenHardBlock` 单测覆盖，注册表不被写入）；token 已设 → 401/200 鉴权边界单测+冒烟双实证 |
| 云端配置侧（voxsign.ai 生产） | ⏳ **待云端运维执行**：AIOps 平台经只读探测确认无「设环境变量/部署」类 API（configure 回退 SPA、write-grant 仅覆盖技能发布、唯一部署机制 cicd 是 git release-tag watcher 且需人工容器接管批准）。动作指引见《云端-VHS_TOKEN配置指引-20261005.md》（生成 `openssl rand -hex 32` → 写入 compose environment/.env → `docker compose up -d harness` → 验证 token_set=true + 无凭证 401） |

**两者差异 = 唯一剩余缺口**：云端跑的仍是旧码，即使运维现在配了 VHS_TOKEN，旧码在「token 已设」时本就有 401 比对能力（本地旧二进制对照已实证），故运维配置后云端即闭环；新码的 503 硬保护将在下次云端发布时顺带生效。
