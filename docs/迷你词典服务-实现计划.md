# 迷你词典服务-实现计划

## 1. 概述

迷你词典服务是一个基于 Go 实现的轻量级后台 HTTP 服务，对外提供健康检查与内置词典查询能力。服务的核心目标是以最小依赖、最小部署成本，向调用方稳定输出一份内置词典的 JSON 数据，其中包含常用词条与人名词条。

服务默认部署在自有域名下，配合前端或语音（ASR）链路使用，用于对识别结果中的专有名词进行校准与查询。

## 2. 目标与范围

### 2.1 目标

- 提供可用的健康检查端点，便于探活与负载均衡接入。
- 提供内置词典查询端点，返回结构化 JSON。
- 词典数据内置在服务中，不依赖外部数据库，保证启动即用。
- 词条中包含人名词条，满足专有名词查询与校准需求。

### 2.2 不在范围内

- 用户体系与鉴权（初期可全开放，后续按需补充）。
- 词典的动态增删改查与持久化。
- 全文检索、分词、模糊匹配等高级查询能力。

## 3. 接口设计

### 3.1 GET /v1/health

健康检查端点，用于探活。

- 请求：无参数、无请求体。
- 响应体：纯文本 `ok`。
- 状态码：`200 OK`。

示例：

```
GET /v1/health
200 OK
ok
```

### 3.2 GET /v1/dict

词典查询端点，返回内置词典的完整 JSON。

- 请求：无必填参数；后续可扩展 `?q=` 做前缀过滤。
- 响应头：`Content-Type: application/json; charset=utf-8`。
- 状态码：`200 OK`。

响应结构示例：

```json
{
  "version": "1.0.0",
  "updated_at": "2025-01-01T00:00:00Z",
  "entries": [
    {
      "id": "person-mansour",
      "term": "Mansour",
      "type": "person",
      "aliases": [],
      "blacklist": ["曼苏"],
      "note": "人名，标准拼写为 Mansour；中文音译「曼苏」不作为标准词条收录"
    },
    {
      "id": "domain-peterzou",
      "term": "model.peterzou.com",
      "type": "domain",
      "aliases": ["彼得周点com"],
      "blacklist": [],
      "note": "语音输入中「彼得周点com」应归一化为 model.peterzou.com"
    }
  ]
}
```

### 3.3 响应字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | string | 词典数据版本号 |
| `updated_at` | string | 词典最后更新时间（RFC3339） |
| `entries` | array | 词条列表 |
| `entries[].id` | string | 词条唯一标识 |
| `entries[].term` | string | 标准词条文本 |
| `entries[].type` | string | 词条类型：`person` / `domain` / `common` 等 |
| `entries[].aliases` | array | 可归一化到该词条的别名（如语音误识别） |
| `entries[].blacklist` | array | 明确标记为错误、不应输出的写法 |
| `entries[].note` | string | 备注说明 |

## 4. 词典数据设计

### 4.1 数据来源

词典以内置资源形式随服务打包，推荐两种方式之一：

- 编译期嵌入：使用 `go:embed` 将 `dict.json` 嵌入二进制。
- 启动期加载：从固定路径读取 JSON，加载失败则启动失败并输出明确日志。

初期推荐编译期嵌入，避免运行时文件依赖。

### 4.2 人名词条要求

- 人名统一使用标准拉丁拼写作为 `term`，不使用中文音译作为主词条。
- 常见误识别写法放入 `aliases`（可归一化）或 `blacklist`（明确错误）。
- 同一人物只保留一个主词条，避免同义重复。

### 4.3 语料校准约定

结合既往语音（ASR）校准沉淀，约定如下：

| 类型 | 内容 | 处理方式 |
| --- | --- | --- |
| 确认 | 「彼得周点com」→ `model.peterzou.com` | 作为别名收录，归一化输出标准域名 |
| 标错 | 「曼苏」→ `Mansour` | 「曼苏」为错误写法，不作为标准词条 |
| 黑名单 | 「曼苏」 | 禁止出现在输出结果中 |
| 教词 | `Mansour` | 作为标准词条正式收录，供查询与校准使用 |

要点：

- 标准拼写 `Mansour` 必须准确，大小写首字母大写。
- 「曼苏」列入黑名单，任何归一化输出都不应回落到该写法。
- 域名类词条以 `model.peterzou.com` 为标准形式，语音转写变体统一归入 `aliases`。

## 5. 实现要点（Go）

### 5.1 技术选型

- 语言：Go（建议 1.21+）。
- HTTP：标准库 `net/http`，不引入框架，保持依赖最小。
- 数据：`encoding/json` + `go:embed`。

### 5.2 目录结构建议

```
mini-dict/
├── main.go
├── internal/
│   ├── handler/
│   │   ├── health.go
│   │   └── dict.go
│   └── dict/
│       ├── dict.go
│       └── data/dict.json
└── go.mod
```

### 5.3 路由

在 `http.ServeMux` 上注册两个精确路径：

- `GET /v1/health`
- `GET /v1/dict`

非 `GET` 方法返回 `405 Method Not Allowed`；未知路径返回 `404 Not Found`。

### 5.4 关键实现要求

- 词典在启动时解析一次并常驻内存，请求期间只做序列化，避免重复解析。
- `/v1/dict` 输出使用稳定字段顺序与固定缩进，便于人工核对与差分。
- 对 JSON 序列化失败等异常情况返回 `500`，并记录日志。
- 日志中不得输出黑名单词条的原始文本作为「推荐结果」。

| 状态码 | 场景 | 响应体 |
| --- | --- | --- |
| `200` | 正常返回 | `ok` 或词典 JSON |
| `404` | 路径不存在 | `{"error":"not found"}` |
| `405` | 方法不允许 | `{"error":"method not allowed"}` |
| `500` | 内部错误 | `{"error":"internal error"}` |

## 8. 测试计划

- `/v1/health`：返回 `200` 且响应体严格等于 `ok`。
- `/v1/dict`：返回 `200`，响应可被 `json.Unmarshal` 解析，`entries` 非空。
- 人名词条校验：存在 `term == "Mansour"` 的词条。
- 黑名单校验：`Mansour` 词条的 `blacklist` 包含「曼苏」，且任何输出中不出现「曼苏」作为标准词条。
- 域名词条校验：`model.peterzou.com` 词条存在，且其 `aliases` 包含「彼得周点com」。
- 方法与路径：`POST /v1/dict` 返回 `405`；`GET /v1/unknown` 返回 `404`。

## 9. 部署

- 构建单二进制，静态编译，无外部运行时依赖。
- 通过反向代理接入 `model.peterzou.com`，并配置 `/v1/health` 作为健康检查路径。
- 容器化时暴露端口与 `HTTP_ADDR` 保持一致。
