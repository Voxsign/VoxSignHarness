# VoxSign Harness 异常自愈架构（问题定位模型层）

> 状态：设计 v0.1（Peter 2026-10-02 语音拍板方向）
> 目标：harness 出错时不是"简单降级/静态建议"，而是由**模型中心的问题定位模型**判断异常、给出自愈动作，并把诊断学回写，实现"能自愈、不断发现问题"。

## 1. 设计动机（来自真机/测试桩实证）

- 现有链路：工具执行失败 → `classifyAttribution` 给静态建议（"检查环境/路径/权限后重试"）；模型调用失败 → 固定降级文案。
- 问题：① 静态建议不针对具体错误，用户/系统无法据此自愈；② 同类错误反复出现（如 gpt-6-luna 的 max_tokens/temperature 400）每次都要人工定位；③ 错误发生后没有学习回写，知识不积累。
- 用户要求：**在上面再加一层**，在"执行错误之前/之后"加异常判断；调模型中心**问题定位模型（异常模型，用户拟命名 JEV/GAB）**；不是 fake 工具，是模型驱动的自愈。

## 2. 架构：三环自愈

```
[执行层出错]  (receipt.OK=false / verify fail / 模型调用 err)
      │
      ▼
┌─────────────────────────────────────────────┐
│ ① 异常知识库命中检查（0 模型调用）              │
│    错误指纹(err 前缀+工具+意图) → 已有根因/修复？ │
│    命中 → 直接复用建议（不再调模型，省预算提速）   │
└─────────────────────────────────────────────┘
      │ 未命中
      ▼
┌─────────────────────────────────────────────┐
│ ② 问题定位模型（模型中心异常接口，JEV 模型）      │
│    输入：任务原文+意图+失败轨迹(工具/参数/错误)    │
│    输出(JSON)：分类/根因/置信/可恢复/建议/动作     │
└─────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────┐
│ ③ 自愈执行器                                   │
│    retry    → 按建议重试（限 2 轮，防死循环）    │
│    modify   → 修正参数/换工具/换模型后重试       │
│    fallback → 安全降级（如 QUERY 降级文案）      │
│    ask      → 转回问用户                         │
│    stop     → 终止并归因                        │
└─────────────────────────────────────────────┘
      │ 失败且可再诊断 → 回 ②（最多 2 轮）
      ▼
[学习回写] 异常+根因+成功修复 → 写入 exceptions.jsonl（知识库）
      │
      ▼
[归因回写] 归因携带诊断结论（替代静态建议）
```

## 3. 插入点（不改现有主链）

| 位置 | 触发条件 | 现状 → 改造后 |
|---|---|---|
| 工具执行回执 | 任一 receipt.OK=false | 静态"检查环境/路径/权限" → 诊断层结论 |
| 独立校验 | verify.Status=Fail | 同上 |
| 模型调用 | queryLLMAnswer err / 空内容 | 固定降级 → 先诊断（预算/网络/参数分类）再决定重试或降级 |

设计原则：诊断层**可选**——模型中心异常接口未配置时自动跳过，现有行为不变（薄降级），不影响已跑通链路。

## 4. 问题定位模型接口契约（供模型中心配置）

- **端点**：模型中心 OpenAI 兼容通道（复用现有 provider，零新传输代码）
  `POST https://model.peterzou.com/v1/chat/completions`
- **模型名**：`jev-diagnose`（或 Peter 在模型中心命名的模型 id，配置里指定即可）
- **请求**（OpenAI 标准，response_format=json_object）：
  - system：`你是 VoxSign 异常诊断模型。根据任务与执行轨迹判断异常分类与根因，输出 JSON。只输出 JSON。`
  - user：
    ```
    {
      "task": "<用户任务原文>",
      "intent": "<QUERY/EDIT/...>",
      "failure": [
        {"tool": "<tool>", "args": "<参数摘要>", "err": "<错误信息>", "stdout": "<输出片段>"}
      ]
    }
    ```
- **响应**（json_object，必含字段）：
  ```json
  {
    "category": "tool_missing|network|auth|budget|param|permission|transient|unknown",
    "root_cause": "一句话根因（中文）",
    "confidence": 0.0,
    "recoverable": true,
    "suggestion": "具体可执行建议",
    "action": "retry|modify|fallback|ask|stop",
    "retry_params": {}
  }
  ```
- 注：`action=retry` 且 `recoverable=false` 冲突时以 recoverable 为准（stop）。

## 5. harness 侧准备（我负责，接口就绪即生效）

1. `config/config.go`：新增 provider `diag`（Model 默认 `jev-diagnose`，Endpoint 模型中心，Params 同 gpt-6-luna 适配：use_max_completion_tokens=true、跳 temperature）；未配置 → 诊断层跳过。
2. `pipeline`：新增 `diagnose(ctx, intent, receipts) *Diagnosis`（知识库命中 → 模型 → 结构化解析）。
3. 自愈执行器：`applyDiagnosis(d) (retryReceipts, done, err)`——限 2 轮。
4. 异常知识库：`log/exceptions.jsonl`（错误指纹 hash → 根因/修复/次数）；queryLLMAnswer 降级前也先查库/诊断。
5. 归因：`classifyAttribution` 静态建议替换为诊断结论（无诊断时保持现状）。

## 6. 风险与边界

- 自愈动作上限 2 轮，防止模型建议导致死循环/越权；动作仅限"重试/修正参数/换工具/降级/回问"，不自动执行不可逆动作。
- 诊断模型输出 JSON 解析失败 → 跳过诊断层（保持现有降级），不把错误扩散。
- 异常接口未就绪（404/超时）→ 薄降级，链路照常。
