# VoxSign Harness 详细设计 v1（草案）——语音驱动开发（Voice-Driven Development）

- 日期：2026-10-02 · 场景：以写代码为核心 · 目标：供 Claude Code 评审后定稿
- 定位：这不是"语音版 IDE"，是**以开发为第一个真实场景的生产底座闭环**

---

## 0. 一句话
**用嘴说变更意图，Harness 完成 容错→意图→规划→风险分级→执行→独立校验→回执→沉淀，下次更懂你。**

## 1. 与传统开发方式的本质差异（为什么"跟以前不一样"）

| 维度 | 传统开发（键盘+IDE） | 语音驱动开发（VDD） |
|---|---|---|
| 输入 | 精确的键鼠/命令 | 模糊语音（ASR 错误、口语、省略） |
| 输出 | 代码文件 | 意图 JSON + 执行 + 回执（可审计） |
| 迭代 | 手写→运行→看错→改 | 对话式 REPL：说→做→回执→再说 |
| 验证 | 人看/人跑 | **独立校验器**（读实际状态，不读自报） |
| 沉淀 | 代码注释/文档（人维护） | 轨迹 JSONL + 归因六格 + 认知层（自动） |
| 记忆 | 人的脑子 | 三元组缓存 + project-map + decisions-log（机器可查） |
| 代码量 | 人写全部 | **人只描述意图，模型生成，人验收**（代码越来越少） |

**核心变化**：开发 = 意图描述 + 模型生成 + 契约执行 + 独立验证 + 自动沉淀。人的重心从"怎么写"移到"说什么 + 验收什么"。

## 2. 开发意图分类（V0 定 8 类，映射工具契约）

| 意图 | 触发示例 | 风险基线 | 契约 |
|---|---|---|---|
| EDIT 改代码 | "把报价模块错误提示改中文" | 可逆/影响中 | file+git+test |
| DEBUG 查bug | "修一下这个崩溃" | 可逆/影响高 | git+test+run |
| QUERY 查代码 | "这个函数在哪定义" | 只读 | file+git |
| TEST 跑测试 | "跑一下测试" | 只读 | test |
| COMMIT 提交 | "提交这批改动" | **不可逆** | git |
| DEPLOY 部署 | "发布到服务器" | **不可逆** | run+git |
| NOTE 记想法 | "记一下这个想法" | 只读 | file |
| ASK 问问题 | "这个库怎么用" | 只读 | ask |

## 3. 架构分层（认识/接口/执行/沉淀，单向依赖）

```
┌─ 输入容错层 ─────────────────────────────┐
│ ASR原文留底 → 清洗 → 词典纠错(美墅→Mansour) │  ← 已有（M1）
│ → 意图JSON{type,path,params,confidence}    │
└──────────────┬─────────────────────────────┘
┌─ 认知层（认识，文字/慢变，模型维护）─────────┐
│ project-map.jsonl：仓库结构/模块职责/关键文件 │
│ decisions-log.jsonl：历史决策+原因           │
│ prefs.jsonl：命名风格/注释语言/测试习惯       │
│ 注入方式：首条 user 前缀（已定）；每次循环后   │
│ 模型总结 delta 写入                          │
└──────────────┬─────────────────────────────┘
┌─ 接口层（契约，只增不改，版本化）────────────┐
│ tools/ 每个工具一个契约 JSON @1.0            │
│ 五工具：git / file / test / run / ask        │
│ 契约变更=新增版本，不修改已发布版本            │
└──────────────┬─────────────────────────────┘
┌─ 执行层（代码，快/确定，Go）────────────────┐
│ 意图→规划(模型)→风险分级器(<100行)→执行器     │
│ 独立校验器：读实际状态 diff 预期，不读自报     │
│ 回执：可检索/可撤销/可追溯                    │
└──────────────┬─────────────────────────────┘
┌─ 沉淀层 ──────────────────────────────────┐
│ 轨迹 JSONL append-only（原文/意图/执行/回执）│
│ 归因六格：输入/上下文/契约/模型判断/执行/外部  │
│ 每日摘要：抽样复核"今天自动执行的 N 条"        │
│ 三元组缓存：不再问(意图,路径,权限范围)         │
└────────────────────────────────────────────┘
```

## 4. 语音驱动开发端到端流程（示例）

**例 1：低风险 EDIT**
"把报价模块的错误提示改成中文"
→ 容错 → 意图{EDIT, path=quote/, confidence=0.9}
→ 认知层注入（项目结构：报价模块在 quote/）
→ 模型生成 diff（改错误提示文案）
→ 风险分级：可逆+影响面小 → **自动执行**
→ 独立校验：grep 确认文案已改 + go build 通过
→ 回执：{diff摘要, 测试OK, 撤销命令:git checkout, 标记待抽查}
→ 轨迹落盘 → 认知层总结 delta

**例 2：高风险 DEBUG（改核心逻辑）**
"帮我把登录崩溃修了"
→ 意图{DEBUG, path=auth/, confidence=0.7}
→ 模型读轨迹/代码诊断 → 给方案+预估影响面
→ 风险分级：可逆但**影响面高** → **强确认**（展示方案+diff 预览）
→ 你："改吧"
→ 执行 → 独立校验（跑 auth 测试）→ 回执
→ 失败 → 回执 FAILED + 自动回滚

**例 3：不可逆 DEPLOY（永远强确认，硬规则）**
"发布到服务器"
→ 意图{DEPLOY} → 风险分级：**不可逆 → 强制人工确认**
→ 展示将执行的命令+目标 → 你确认 → 执行 → 独立校验（curl 200）→ 回执

## 5. 确认策略引擎（开发场景双信号：可逆性 + 影响面）

| 可逆性 | 影响面 | 动作 | 备注 |
|---|---|---|---|
| 可逆 | 小（注释/格式/小函数） | 自动执行+标待抽查 | 异步确认不打断 |
| 可逆 | 中（业务逻辑/签名） | 展示 diff 摘要→确认 | 轻确认 |
| 可逆 | 高（核心模块/公共 API） | 强确认：diff 预览+影响分析 | 展示再执行 |
| **不可逆**（提交/部署/删/推送） | — | **永远人工确认（硬规则）** | 不可被"学习"掉 |

- 置信度低于阈值（词典未命中已知实体）→ 回问澄清，不瞎猜
- 三元组缓存：只对（意图,路径,权限范围）命中才"不再问"，换路径重新问
- 每日摘要：随机抽 3 条自动执行的，异步复核

## 6. 竞争力分析（为什么别人抄不走）

| 复利引擎 | 内容 | 为什么是护城河 |
|---|---|---|
| 上下文复利 | project-map + decisions-log + prefs 越来越懂你的项目 | 模型通用能力人人有，**你的上下文是私有资产** |
| 契约复利 | 工具契约 5→20 个，每个都是验证过的能力 | 工具面越用越顺手，新工具=注册新契约 |
| 归因复利 | 错误六格分类沉淀（ASR/模型/契约/执行） | 错误模式识别，越用越准 |
| 数据本地 | 轨迹/认知全在本地 JSONL，不上云 | 隐私+可控 |

**竞争力 = 不是"能调模型"（人人能调），是"调模型+你的上下文+你的验证闭环+你的沉淀"四者叠加。**

## 7. 与原来的 harness 对比

| 维度 | 原来（Python harness） | 现在（Go V0） |
|---|---|---|
| 性能 | 解释型，慢 | 单二进制 16ms 启动 |
| 模型 | 单模型硬编码 | 多通道路由（基础/Codex/Claude/Cursor） |
| 输入 | 假设标准文本 | ASR 容错（模糊语音） |
| 验证 | 人肉 | 独立校验器 |
| 沉淀 | 无 | 轨迹+归因+认知层 |
| 开发方式 | 手写 Python | 语音意图+契约+受控执行 |
