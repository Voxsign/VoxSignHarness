## 三、Harness 输入包（下一轮可直接投喂）

```text
任务文本：把这份《ASR个性化后台服务-需求规格v3》实现出来，生成可运行的 Go 后台服务，
          安装脚本（install.sh）+ 一键验收脚本（accept_asr.sh），提交到仓库。
document：docs/ASR个性化后台服务-需求规格v3.md（7 P0 端点 + 技术约束仅标准库 + 判据）
验收判据：sh scripts/accept_asr.sh 期望 RESULT: ALL_PASS（12 判据，真装配）
对齐门槛：校验对齐 双证 PASS ≥ 90% 且 0 FAIL（validate-align v3）
迭代协议：一轮 ≤ 20 分钟 —— 我跑验收/校验 → 你按改进编排修订（留痕）→ 重跑 → 达标为止
历史教训（防再犯）：
  ① 证据门必须查"端点存在性"（curl/grep HandleFunc），不只查关键字
  ② 修订类表述（修订/补齐）必须命中 implement 意图，禁止 0 轮 done
  ③ LLM 必须消费验收反馈文档（缺口清单逐条对产物）
```

## 五、案例价值
