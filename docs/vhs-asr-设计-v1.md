# vhs-asr · 设计 v1（独立部署的 ASR 个性化识别服务）

> **v0 → v1 的修正**：v0 把这件事写成"在本机新建一个项目"，方向错了。
> 用户 2026-10-03 澄清：**可以部署在另外一台服务器上做，不一定要在这台电脑上**。
> 本机保留现有的 voice-sign harness，不动。
>
> **这个修正让它回到了架构第一原则**：ASR 个性化识别就是一个**外部能力**，
> 所以它**本来就该在别的机器上**，本机只留调用方。
>
> 上位原则：`docs/架构第一原则-能力外置本机极简.md` · 工作法：`docs/技能-自举闭环工作法-v1.md`

## 1. 部署拓扑（v1 的核心修正）

```
┌──────────────────────────────────────┐        ┌──────────────────────────────────────┐
│  这台电脑（保持原样，不加东西）          │        │  另一台服务器（新部署）                 │
│                                      │        │                                      │
│  voice-sign harness                  │  接口  │  vhs-asr                             │
│   · 13 步主链 / 域门禁 / 执行 / 校验   │ ─────► │   · Go 单二进制，零第三方依赖          │
│   · 手机入口 / 回执                   │ + key  │   · 个性化状态在这里（词表/热词/历史）   │
│                                      │        │   · 快路微秒级；慢路再外接模型          │
└──────────────────────────────────────┘        └──────────────────────────────────────┘
```

**这台电脑上不新增任何东西**——不加依赖、不加服务、不囤资料。
harness 只是**多了一个可调的接口**。

### 为什么这样分才对

| 能力 | 放在哪 | 依据 |
|---|---|---|
| 域门禁、执行、独立校验、回执 | **本机**（这台电脑） | 管的是"这台机器上能不能做"，外置无意义 |
| **ASR 个性化识别** | **另一台服务器** | 通用能力 + 可独立演进 + 可被多端复用 → 外置才有复利 |
| 个性化状态（个人词表/热词/纠错历史） | **服务端** | v0 写的是"留本机"，**v1 修正为留服务端**：它是这个服务的私有资产 |
| 模型判断 | 更外层（模型中心 / Jev） | 通用能力 |

## 2. 交付形态（为了"能扔到另一台机器上跑"）

一个**单二进制 + 一份配置**，没有别的：

```
vhs-asr                 # 静态编译单二进制，linux/amd64 + darwin/arm64
vhs-asr.toml            # 只有三样：监听地址、个性化状态目录、外部接口 key
```

**硬要求**（每条都对应一条设计判据）：
1. **零第三方依赖** —— `go.mod` 只有 `module` + `go`（与 vhs 一致）
2. **静态单文件** —— `CGO_ENABLED=0 go build`，scp 过去就能跑
3. **不连外网也能启动**（慢路不可用时降级到快路，不崩）
4. **状态目录可指定** —— 个性化数据落在指定路径，方便备份/迁移
5. **一条命令起服务** —— 无安装步骤、无包管理器

## 3. 职责边界（最重要的表）

| 问题 | 答案 |
|---|---|
| 谁产生识别与纠错？ | **vhs-asr**（那台服务器） |
| 谁调用它？ | **voice-sign harness**（这台电脑），通过接口 + key |
| 谁拥有个性化状态？ | **vhs-asr**（服务端）；本机只缓存可重建的东西 |
| 谁做域门禁/执行/回执？ | **harness**（本机）。asr 服务**不碰**这些 |
| 谁判"纠对了"？ | harness 把用户反馈（接受/改回）回传 `Observe`；**异源盲评**独立判 |
| 本机新增什么？ | **只多一个接口地址 + 一把 key** |

## 4. 接口（跨机器，所以必须稳）

```
POST /v1/correct     { raw, context[], domain }        → { text, corrections[], candidates[], latency_us }
POST /v1/observe     { raw, corrected, accepted, src } → { ack }
GET  /v1/lexicon     ?domain=                          → 当前个性化状态（可审计）
GET  /v1/health                                        → { ok, fast_path, slow_path }
```

**设计要点**：
- `correct` 是**无状态纯函数**（好测、好并发、好回放、好跨机器）；
  个性化状态由 `observe` 更新、由 `lexicon` 可审计。**状态与计算分离。**
- 每次纠错必须带证据：`{start, end, from, to, kind, confidence, evidence}`。
- 跨机器调用要**可归因**：接口带 key 标识，服务端记录每次调用的用途。

## 5. 测试桩（"ASR 识别的 harness"）

**两个用途**（用户 2026-10-03 明确："两个都需要"）：

1. **自己和自己比**：同一批真实语料，跑**改动前**与**改动后**，用数字看提升
2. **异源盲评**：DeepSeek 只看「规格 + 产物」给 PASS/修订/驳回，**不参与产出**

### 5.1 语料：真实对话，不是编的

取自 Peter 与 DSH 的**真实交互**（本会话实测过的真句）。
首批 15 条已备（`real-01` ~ `real-15`），覆盖：填充词、触发词同音失真、
专名同音、否定保真、纯噪声、元指令、条件句、多动作、自举注册、M7 真机长句。
**每轮对话往里加**——这是"越用越准"能被度量的基础。

### 5.2 判据（四类，每类双向反例）

| # | 判据 | 双向 |
|---|---|---|
| **C1** | 不该纠的不能纠：`不要删除`→ 不得纠掉"不"；M7 长句→ 原样 | 也要测"该纠的纠了" |
| **C2** | 触发词同音容错：多字触发词被听错仍能还原（提交→出交） | 不得把无关句纠成命令 |
| **C3** | 噪声不脑补：纯噪声必回问 | 不得把正常短句误判为噪声 |
| **C4** | 可观测：每次纠错带区间/原因/置信度，raw 留底 | 纠错记录为空 = 红 |

### 5.3 性能判据（"快"必须可测）

- 延迟：50 字输入 **p99 < 1 ms**（快路，无外部调用）
- 吞吐：单核 **≥ 10k QPS**
- 内存：常驻 **< 50 MB**
- **断网可跑**：快路必须不依赖外部（这条同时验证架构第一原则）
