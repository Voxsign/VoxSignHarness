# 缓存（CACHE-001）：K9 闭合证据 + 已知边界

## 1. K9 闭合：热词**真的改变输出**（不是"接口接上了"）

`recog/` 组合层（`asr` ← `hotcache` 依赖方向决定它必须另立包，否则循环依赖）：
基线纠错（引擎 + 词典）之后，用缓存做**关联度改写**，改写留痕（From/To/Route/Score）。

三条验收（`go test -tags vhsrecog ./recog`，全绿）：
| 判据 | 断言 |
|---|---|
| K9-① 输出因热词而变 | `爱ops` → `aiops`（alias 路），且 Corrections 非空 |
| K9-② 空表不改变输出 | 同一输入 → 原样，且 0 条 Corrections |
| K9-③ 清空后回退 | `Clear()` 后同一输入 → 原样 |

**实现中踩到的真实坑（只有真跑才发现）**：单遍滑窗 + 编辑距离会**吃掉前缀**——
`把爱ops接上` 被 edit 路匹配成 `aiops`（窗口 `把爱ops` 与别名距离=1）。
修法：**两遍扫描** —— ① 滑窗只认**精确/别名/拼音**（不认编辑距离）；
② 仅当 ① 无命中，才对**拉丁词元**做编辑距离（`voice-signn` → `voice-sign`）。

## 2. K7 定期刷新（已落地）

`Cache.StartRefresh(ctx, interval)`：启动即刷一次，随后按 TTL 周期刷；失败由 `Refresh` 内部
fail-open（**保留本地数据 + 标 unknown**），循环不中断。判据：短周期下 fetch 次数 ≥2；
失败后本地别名仍可命中。

## 7. 为什么必须"真跑"——三个实例（都只有真跑才发现）

| # | 静态看起来 | 真跑暴露 | 修法 |
|---|---|---|---|
| 1 | "有 `defer Unlock` 就安全" | `fatal error: sync: unlock of unlocked mutex`（`Observe`/`PutAlias` 漏了 `Lock`） | 补 `Lock` |
| 2 | "滑窗 + 编辑距离单遍扫描即可" | 编辑距离**吃前缀**：`把爱ops接上` → `aiops` | 两遍扫描：滑窗只认精确/别名/拼音；编辑距离只用于整词元 |
| 3 | "库层判据全绿 = K9 完成" | **HTTP 服务路径根本没接 `recog`** | 服务侧组装 + HTTP 端到端判据 |

**结论**：判据写得再对，也要真跑才知道实现错在哪；**库层绿 ≠ 能力交付**。

## 9. 规律：**等价是假设，不是事实**

| # | "看起来等价"的地方 | 真跑暴露的问题 |
|---|---|---|
| 1 | 有 `defer Unlock` ⇒ 安全 | `unlock of unlocked mutex`（漏 `Lock`） |
| 2 | 滑窗 + 编辑距离单遍 ⇒ 够用 | **吃前缀**（`把爱ops接上` → `aiops`） |
| 3 | 库层判据全绿 ⇒ K9 完成 | **HTTP 路径根本没接 `recog`** |
| 4 | httptest 组装同构 ⇒ main.go 可行 | 启动日志/真进程路径**未验证**（本轮补齐） |
| 5 | `cmd` 有现成网关地址访问器 ⇒ 直接用 | **编译期证伪**（`cfg.GatewayBase` 不存在） |

> **凡是"看起来等价"的地方，都要真跑一次。等价是假设，不是事实。**
> 判据写得再对，也要真跑才知道实现错在哪；**库层绿 ≠ 能力交付；同构 ≠ 同一份代码。**
