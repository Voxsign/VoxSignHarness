## 0. 一句话
**用嘴说变更意图，Harness 完成 容错→意图→规划→风险分级→执行→独立校验→回执→沉淀，下次更懂你。**

## 1. 与传统开发方式的本质差异

| 维度 | 传统开发（键盘+IDE） | 语音驱动开发（VDD） |
|---|---|---|
| 输入 | 精确的键鼠/命令 | 模糊语音（ASR 错误、口语、省略） |
| 输出 | 代码文件 | 意图 JSON + 执行 + 回执（可审计） |
| 迭代 | 手写→运行→看错→改 | 对话式 REPL：说→做→回执→再说 |
| 验证 | 人看/人跑 | **独立校验器**（读实际状态，不读自报） |
| 沉淀 | 注释/文档（人维护） | 轨迹 JSONL + 归因六格 + 认知层（自动） |
| 记忆 | 人的脑子 | 三元组缓存 + project-map + decisions-log |
| 代码量 | 人写全部 | **人描述意图，模型生成，人验收** |

**核心变化**：开发 = 意图描述 + 模型生成 + 契约执行 + 独立验证 + 自动沉淀。

## 2. 开发意图分类（8 类，映射契约）

| 意图 | 触发示例 | 风险基线 | 契约 |
|---|---|---|---|
| EDIT 改代码 | "把报价模块错误提示改中文" | 可逆/影响中 | file+git+test+verify |
| DEBUG 查bug | "修一下这个崩溃" | 可逆/影响高 | git+test+run+verify |
| QUERY 查代码 | "这个函数在哪定义" | 只读 | search+file+git |
| TEST 跑测试 | "跑一下测试" | 只读 | test |
| COMMIT 提交 | "提交这批改动" | **不可逆** | git |
| DEPLOY 部署 | "发布到服务器" | **不可逆** | run+git+verify |
| NOTE 记想法 | "记一下这个想法" | 只读 | file |
| ASK 问问题 | "这个库怎么用" | 只读 | ask |

```
└──────────────┬─────────────────────────────┘

│  （只注入当前 path/模块相关切片）            │
└──────────────┬─────────────────────────────┘
┌─ 接口层（契约，只增不改，版本化）────────────┐

│ 回执：可检索/可撤销/可追溯                    │
└──────────────┬─────────────────────────────┘
┌─ 沉淀层 ──────────────────────────────────┐

│ 每日摘要：抽样复核自动执行条目                 │
│ 三元组缓存：不再问(意图,路径,权限范围)         │
└────────────────────────────────────────────┘
```

## 4. 确认策略引擎 v2（三信号，任一高风险即升级）

**【v2核心修订】Claude 反对意见已吸收：影响面不能靠模型自评（模型不知道代码被谁依赖），安全边界必须至少有静态/机械信号参与判定。**

| 信号 | 来源 | 性质 |
|---|---|---|
| ① 可逆性 | 意图类型映射（硬事实） | 硬规则，不可被学习掉 |
| ② 影响面（**静态可算**） | 文件被引用次数 / 历史改动热度 / 测试是否覆盖 | **机械信号，不靠模型自评** |
| ③ 置信度 | 词典纠错命中率 / 意图解析确定性 | 软信号，只用于回问 |

决策矩阵：
| ①可逆 | ②影响面 | ③置信度 | 动作 |
|---|---|---|---|
| 可逆 | 小 | 高 | 自动执行 + 标待抽查（异步确认） |
| 可逆 | 小 | 低 | 自动执行 + 待抽查 + 回执高亮 |
| 可逆 | 中 | 任意 | 展示 diff 摘要 → 轻确认 |
| 可逆 | 高 | 任意 | 强确认：diff 预览 + 影响分析 |
| **不可逆** | — | — | **永远人工确认（硬规则）** |

**确认疲劳防护**（v2 新增）：
- 强确认有频率上限（连续 >3 次强确认同一路径时，自动降为"汇总待复核"）
- 每日摘要随机抽 3 条复核，替代高频实时打断
- 三元组缓存：只对（意图,路径,权限范围）命中才"不再问"

## 5. 认知层设计（v2 修订：独立低频 + 相关性注入）

- **不**在主循环里让模型"执行+自我归档"双任务（会退化+注入膨胀）
- 更新：独立的低频异步任务（每日或每 N 次会话批量 reindex），模型只做纯归档
- 注入：相关性检索（仅注入与当前 path/模块相关的切片），不全量塞上下文
- 内容：project-map（结构/职责/关键文件）、decisions-log（历史决策+原因）、prefs（命名/注释/测试习惯）

## 6. 独立校验器（契约化，v2 定稿）

- `verify` 契约独立于 `run`：执行后**读文件系统实际状态**（grep/diff/test 输出）对比预期
- 不读执行器自报 status（Codex + Claude 共识）
- 校验失败 → 回执标 FAILED → 自动回滚（git 层）
- 校验动作本身有版本化 + 审计（写轨迹）

## 7. 自举的充分条件（v2 定稿，Claude 核心意见）

**不是"独立校验器"，是"契约注册机制本身可被语音调用"。**

- 1.0 必须走通：`"加一个工具，把 markdown 转成 pdf"` → 意图{REGISTER_TOOL} → 模型生成契约 JSON → 风险分级 → 人确认 → 注册 → 下次可用
- 这条链路通了，2.0 才不需要人手写 Go——**新能力 = 语音注册新契约**
- 在此之前 2.0 不存在，只有 1.0 的 bug 修复

## 8. 竞争力来源（为什么抄不走）

| 复利引擎 | 内容 | 护城河 |
|---|---|---|
| 上下文复利 | project-map/decisions-log/prefs 越来越懂你的项目 | 你的上下文是私有资产 |
| 契约复利 | 工具契约 5→20 个，每个验证过 | 工具面越用越顺手 |
| 归因复利 | 错误六格分类沉淀 | 错误模式越用越准 |
| 数据本地 | 轨迹/认知全本地 JSONL | 隐私+可控 |

## 9. 已识别的坑与对策（v2 汇总）

| 坑 | 对策 |
|---|---|
| 影响面模型自评不可靠（Claude 架构性反对） | 静态信号（引用面/热度/测试覆盖）强制参与 |
| ASR 对代码实体纠错是无底洞（函数名/路径不可穷举） | 词典只管人名/项目词；代码实体靠意图+模型+回问，不穷举 |

## 11. 双端架构（v2 补充：手机=控制器，电脑=执行器）

**用户使用模式**：手机是唯一交互界面（ASR 语音输入 + 回执阅读 + 确认对话）；电脑/服务器是远程执行端（Go harness + 模型中心 + 工具 + 校验 + 沉淀），用户不直接碰电脑。

```
手机（控制器/认识面）          电脑/服务器（执行面）
┌──────────────────┐          ┌─────────────────────┐
│ 豆包 App：ASR 语音  │ 意图协议  │ Go harness：         │
│ → 意图 → 回执 → 确认 │ ───────▶ │ 认知/契约/执行/校验/沉淀 │
│ （标准化=基础设施）  │ ◀─────── │ （个性化=自建服务）    │
└──────────────────┘  回执推送  └─────────────────────┘
```

**设计推论**：
1. **按分配原则分层**：ASR/语音聊天/消息推送=标准化→用基础设施（豆包）；认知/契约/执行/校验/沉淀=个性化→自建（harness）。
2. **回执必须手机可读**（核心新增约束）：每条回执 ≤ 手机一屏（动作+文件+结果+撤销方式，4 行内）；diff 不刷屏，只给"改了 N 文件+关键行"摘要，详情可语音追问；确认=聊天式（一条消息+两按钮，或直接语音"改吧"）；每日摘要=一条消息。
3. **确认策略引擎的交互落到手机**：强确认=一条推送+两个按钮；低风险自动=回执进"待抽查"列表；三元组缓存命中=不再推送。
4. **harness 需要手机可连的 API 面**：本地 HTTP/WS 端点（或经模型中心网关），M2 预留接口，V1 落地 server。
5. **未来开发模式**：任何地方对手机说"把 X 改了"→ 电脑干活 → 手机收摘要 → 语音追问/确认。竞争力=你移动、电脑干活，沉淀全在本地底座（手机端人人有，抄不走的是你的执行底座+上下文）。

## 12. 边界哲学：意图识别 = 画边界（v2 补充，核心理念实施）

**核心理念**：开发的核心产出不是代码，是"边界变得清楚"。你提到"布置任务来回五次'是这样吗'"——那五次的本质就是把边界逐层画清楚。Harness 要把这五次做成**低成本自动化**，让模型主动画边界，而不是靠人反复澄清。

### 边界五轴（每个任务都必须画）
| 轴 | 内容 | 防什么 |
|---|---|---|
| ① 范围边界 | 覆盖哪些文件/模块（scope） | 防止范围蔓延 |
| ② 排除边界 | 明确**不碰**什么（non_goals） | 防止模型顺手改别的 |
| ③ 权限边界 | 可读/可写/可执行（=风险分级） | 防止越权/破坏 |
| ④ 验收边界 | 做到什么算完成（acceptance） | 防止"假装完成" |
| ⑤ 上下文边界 | 依赖哪些历史决策/契约版本 | 防止脱离你的意图 |

### 落地实施（写进意图 JSON 与回执）
- **意图 JSON 扩展**：`{type, path, params, confidence, scope, non_goals, acceptance}`——模型生成任务书时**先画边界再动手**
- **回执扩展"边界确认段"**：改了 N 文件 / 没碰 X / 验收项 Y 通过或未过——你一眼看到边界是否守住了
- **出界拦截**：模型碰了 non_goals 或超出 scope → 独立校验器拦截，回执标 BOUNDARY_VIOLATION
- **"来回五次"自动化**（每次成本=一句话或两按钮）：
  1. 边界不清 → 低置信回问（澄清范围）
  2. 模型画范围草案 → diff 预览轻确认
  3. 执行 → 回执
  4. 验收 → 测试结果 + 边界确认段
  5. 边界固化 → 三元组缓存"不再问" + 契约留痕
- **OPC 不乱的根本机制**：边界五轴全进任务书+轨迹；任何一步出界自动拦截。人少=边界机制更关键，因为没人盯。

### 竞争力再定义
通用模型会"乱"（范围蔓延/顺手改别处/越权）——**你的 harness 用边界五轴约束模型，这就是"指挥"，也是"不乱"的来源**。画边界=理念，五轴+校验=实施，两者都进了设计，才有价值。

## 13. 域（Space）边界单元（v2 定稿，三模型评审吸收）

**定义**：域 = 边界的**具名配置单元**（space manifest）。它不是隔离机制，是**策略入口 + 稳定主键**（space id）——真正拦截靠执行前统一校验。权限判断由代码做（manifest 可执行），模型只建议域选择。

### 三模型共识（全部吸收：Codex gpt-6-astra / Cursor gpt-5.2 / Claude claude-sonnet-5）
1. **有效权限 = 平台 ∩ 域 ∩ 工具声明 ∩ 本次授权的交集**；风险分级不能突破权限上限
2. **默认拒绝**：未匹配/跨域/目标不符 → 拒绝，绝不退回更宽权限；切域不继承授权，每次工具调用重新校验
3. **域内逃逸规则**：单次操作按（操作类型+资源类型）独立评估风险；宽松域不能掩盖高风险操作（如 git push --force 永远是高风险）
4. **域数量 3-7 个**：global/sandbox/external 全局单例；project 参数化（scope 作调用参数，不按项目开域）；0-3 个核心项目域
5. **漂移检测**：manifest 与实际路径/目录结构定期校验，漂移即失效（防"文档退化成谎言"）
6. **意图解析兜底**：模型只出候选域，代码用注册名/别名/工作位置消歧；首次/高风险**显式回显确认**；未知 → global 只读，绝不"猜最像的"
7. **缓存绑定**：三元组缓存 + 策略版本 + 有效期；策略变化即失效
8. **vault 拆分**：想法库（追加）与凭证库（高敏只读）分开，不共用语义
9. **acceptance/context 不参与授权**：是任务配置，不是权限

### 定稿域表（五类模板，权限以显式策略为准）
| 域 | 权限 | 说明 |
|---|---|---|
| global | 只读兜底 | 默认域，无写 |
| project（参数化） | 可读写+契约+认知切片 | "在 voicesign-harness 里改 X"，scope 为参数 |
| sandbox（单例） | 临时+过期+自动清理 | 禁止长期 sandbox |
| vault-notes（单例） | 追加 | 想法库 |
| vault-creds（单例） | 高敏只读 | 凭证库，独立强门槛 |
| external（单例） | 永远强确认 | 读取/发布按动作区分，强确认绑定具体目标 |

### 实施顺序（先证明无法绕过，再优化体验）
M2：space registry（版本化+漂移检测）→ 执行前 space_check（统一拦截点，默认拒绝）→ 越界测试与审计 → 意图解析接 space 入口 → "一句话选域"体验最后。

### 回应"伪需求"质疑（Claude 最大反对）
域 = 配置的具名复用，保留"域"命名因为：① 你指定的 space 概念；② 作为三元组缓存/契约注册/认知注入的**稳定主键**有独立价值；③ **不造域类型学**——五类只是模板，运行时真正起作用的是 space_check 交集，不是域的分类。

## 14. 指代消解（Reference）× 域 + 多模态 IO（v2 补充）

### 14.1 指代——从模糊到精确的核心机制
**问题**：自然语言天然充满指代（"季总"、"那个文件"、"它"、"上次那个"），ASR 又加重模糊（同音误识）。要让"自然语言→可执行代码"，必须先消解指代：**模糊表述 → 具体实体**。

**分层消解（对应你说的"代码/逻辑/语言"三种实现）**：
| 层 | 机制 | 例子 | 确定性 |
|---|---|---|---|
| 代码层 | 实体词典（已确认别名表） | 季总→冀总(Amber)、美墅→Mansour | 100% |
| 逻辑层 | 上下文解析规则（作用域内最近实体） | "它"→上一条回执里的文件 | 规则确定 |
| 语言层 | 模型推断（认知层/轨迹） | "上次报价那个客户的项目" | 候选+置信度，低置信回问 |

**与域结合（你判断的高可能性点）**：
- **域 = 指代消解的作用域**："那个文件"在 voicesign-harness 域 = 该域最近操作的文件；"那个客户"在 vault-notes/项目域 = 该域认知切片里的客户实体
- 域认知切片 = 指代的实体来源（project-map 的模块 / decisions 的决策 / 词典的别名）
- 缓存升级为**四元组** {意图, 域, 权限, 指代}：指代已消解 + 域内命中 = 不再问

**模糊→精确的闭环**：
ASR 文本 → 词典消解（代码）→ 上下文消解（逻辑）→ 模型推断（语言）→ 置信度低 → 回问 → 确认后**固化进词典** → 下次代码层直接命中。
每次成功消解 = 少问一次 + 词典变厚（上下文复利）。

### 14.2 多模态 IO（文字+图像，吸收 WorkBuddy 优点）
- **输入**：语音 / 文字 / **截图**（意图支持 IMAGE："截个图看看" / "这个报错"）
- **输出**：回执文字 + **图形摘要**（改动文件树、diff 可视化、测试结果图、执行截图）
- 与双端架构结合：手机截图 → 意图 → 电脑执行 → 带图回执推回手机
- 原则：文字负责精确，图像负责结构——两者结合效率最高

### 14.3 意义
1. **指代 = 画实体边界，域 = 画空间边界**——合起来才是完整语义边界（你的边界哲学闭环）
2. 每次消解成功都是上下文复利（词典/决策变厚）；竞争力来自你的个人上下文，别人抄不走
3. 指代不清 → 回问，绝不瞎执行（守住"代码必须可执行"底线）

## 15. 交互语言（VoxSign Language，VSL）——新时代的模型描述语言

**核心理念（你的定调）**：本质上干的是一件事——用**自然语言 + 规范**（代指规范、域定义、决策标准），让三件事达成共识：①决策依据和标准 ②代指对象 ③活动空间。目的=让系统真的理解你。这不是功能设计，是**一种新语言的设计**：用自然语言描述软件工程（意图/边界/验收），由模型理解并执行。

### 语言三要素
| 要素 | 内容 | 对应共识 |
|---|---|---|
| 词汇 | 域(space)、实体(词典)、契约(tool)、意图(8类) | 说得出名字 |
| 语法 | "在[域]里[动作][对象]"；对象可代指 | 一句话定位 |
| 共识机制 | 低置信回问 / 高风险强确认 / 确认后固化 | 说了算数 |

### 四种共识（语言的目标）
1. **决策标准共识**：验收条件 + 确认策略（什么算完成、什么时候问）
2. **代指对象共识**：指代消解 + 确认后固化词典（"季总"=冀总 Amber）
3. **活动空间共识**：域 manifest（能碰哪、能干什么）
4. **执行语义共识**：契约（工具做什么、副作用是什么）

### 交互方式（未来主形态）
- **语音为主（≈90%）**：口语短句、容忍模糊、可回问——语言按"说出来"设计
- **图像为辅（≈10%）**：截图 = 指代消解的**第四路信号源**（"这个报错"=截图里的报错）
- 文字居中：回执/确认用文字精确表达

### Claude 评审吸收（research-inputs/14）
1. **跨域指代规则**：时间"最近"与空间"域"冲突 → **显式消歧回问**（"是 sandbox 的还是 project 的？"）；域不是唯一实体来源，合法跨域引用需在域 manifest 显式声明（如 vault 密钥→project 只读引用）
2. **层间置信度显式化**：规则层低置信必须转交模型层，**不许静默吃掉**（静默误判比回问更危险）；词典固化带版本 + 失效机制（语境漂移即失活）
3. **图形输出 = 可选呈现层**：不进 M1/M2 主闭环（纯语音终端用不上，渲染管线成本陡增）；**输入截图进主闭环**（第四路信号）
4. **M2 顺序修正**：指代消解提前（风险分级和 verify 都依赖"指的是哪个实体"）

### 意义
**VSL 是"人容易说"与"机器精确执行"之间差距最小化的语言**——差距靠规范层（域/指代/验收）缩小，靠回问补齐。这就是"新时代的模型描述语言"：代码越来越少，规范越来越厚，共识越来越快。
