# VoiceSign Harness「脱离豆包独立运行」诊断报告（2026-10-04 实测）

> 回答的问题：iOS + Harness + ASR 不依赖豆包、不依赖人工，现在能不能直接跑？差什么？
> 方法：真实独立起服务（`scripts/m7-serve.sh`）+ 真实提交任务（`scripts/standalone-verify.sh`），全部实测。

## 1. 一句话结论

**能跑，且今天已经实测跑通。** Harness 是独立 Go 二进制（`vhs serve`），不依赖豆包运行时；
意图分类是**纯规则引擎**（不调用任何模型），所以"识别→分类→执行→SSE→回执"这条主干
**完全不需要豆包、不需要人工、不需要模型配额**。唯一的外部依赖是**模型中心配额**
（QUERY 回答 / ORCHESTRATE 汇总用），今天预算超支 429，只降级回答质量，不瘫痪。

## 3. 依赖清单（谁依赖什么）

| 能力 | 依赖 | 脱离豆包 | 脱离人工 | 脱离模型配额 |
|---|---|---|---|---|
| 端侧 ASR（语音→文本） | Apple SFSpeechRecognizer | ✅ | ✅ | ✅ |
| 意图分类 | 纯规则（input/taskintent.go） | ✅ | ✅ | ✅ |
| 域门禁/安全闸 | 本地规则 + 自动注册 | ✅ | ✅ | ✅ |
| 执行/回执/SSE | 本地 | ✅ | ✅ | ✅ |
| 打断/取消/确认 | 本地 | ✅ | ✅ | ✅ |
| QUERY 自然语言回答 | 模型中心 gpt-6-luna | ✅ | ✅ | ❌ 429 → 降级文案 |
| ORCHESTRATE 汇总 | 模型中心 | ✅ | ✅ | ❌ 429 → 确定性拼接 |

**关键**：分类器 `NewTaskClassifier(conf, nil)` 不依赖模型——分类、门禁、执行主干是
"断网断模型也能跑"的确定性代码。这保证了 iOS 真机装上后**至少能完成识别→提交→执行**。

## 4. 今天实测发现的唯一卡点（需人工）

```
HTTP 429: daily_budget_exceeded — spent $366.6052 of $30 (2026-10-03)
```

- 模型中心（model.peterzou.com）**今日预算 $30 已超支 $366**（第三方记账）。
- 影响：QUERY 回答 = 降级文案（带检索结果）；ORCHESTRATE 汇总 = 源文档拼接。
- 不崩溃、不影响规则链路；**恢复方式 = 人工充值/提高预算**（非代码缺陷）。
- 代码侧已有完整降级路径 + 测试（pipeline_test.go:636/683），无需改动。

## 5. 要"马上真机跑通"还差什么（按紧要度）

1. **模型预算**（人工）：充值/提额 → QUERY/汇总恢复真回答。**不充也能跑**，只是回答降级。
2. **iOS 服务地址**：Debug 默认 `http://192.168.8.129:8897`（M7 冒烟地址）。
   真机要和 Mac 同一 Wi-Fi；地址不对 → 设置页改（SettingsStore 已支持）或改默认值。
3. **ASR 后台纠正层**（asr/ 是 P1 桩，未实现）：手机端 Apple 识别**已可用**，无需等它；
   个性化纠正（热词/同音字）是增强项，T2 再接。
4. **音频留底上传**（T2）：当前只传文本；原始音频留底是 v2 需求书要求，增强项。

## 6. 一键自检方法

```bash
bash scripts/standalone-verify.sh   # 起服务 + 规则链路自检 + 模型链路诊断，30 秒出结论
```

- 规则链路全 PASS → iOS 端侧 ASR→提交→SSE 可独立跑通，无需豆包。
- 看到 429/预算 → 充值后重跑即恢复。

## 7. 结论

**没有"一下子跑不起来"的风险**——主干链路不依赖豆包、不依赖模型、不依赖人工；
今天唯一"人工补齐"项是模型中心配额（外部计费，非代码问题）。ASR 识别在手机端原生完成，
后台纠正层是增强项不阻塞安装使用。
