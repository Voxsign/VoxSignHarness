## 3. 从材料里提炼的 10 条设计原则

| # | 原则 | 出处 |
|---|---|---|
| P1 | **长任务的全对率会指数塌缩**（单步 0.95 → 100 步全对 0.6%），所以"全对/不全对"是最差的读数：它同时制造假的"涌现"和假的"无能" | `auto-009` |
| P2 | **先冻结输出，再换指标重算**；阈值必须预注册；结论允许是"证据不足"（三态：支持/推翻/证据不足） | `auto-009` |
| P3 | **必须有安慰剂臂**（等长但无信息的对照）——没有阴性对照，任何"提升"都可能是上下文长度或泄漏造成的 | `auto-010` |
| P4 | **换模型只是其中一臂**。正交五臂：更强模型 / 基线 / +验证器 / +定向修复 / 无验证器，同一批实例配对跑 | `auto-012` |
| P5 | **成本要五项分记**：模型 + 工具 + 人工 + 重试 + **错误后果**。最后一项对"语音误执行"尤其关键 | `auto-012` / `auto-010` |
| P6 | **预期必须事前书面落盘、append-only**；先落预期再接触实际，禁止倒序——否则事后归因没有防篡改锚点 | `one-person-calibration`、`growth-is-calibration` |
| P7 | **归因是多标签竞争假设，不是单选**：H0 需求误判 / H1 执行偏差 / H2 环境扰动 / H3 认知负荷 / H4 合理试错，每个标签要有可复现触发条件，并保留兜底类目 | `one-person-calibration` |
| P8 | **闭环完整性校验**：预测 / 验证 / 修正 / 再迭代缺任一环即失败；**一次失败没有变成下一条规则或预警，那就是死循环，不是校准** | `growth-is-calibration`、`fr-24` |
| P9 | **门禁必须机械可裁决、锚定外部产物**（落盘文件/日志/回执），不锚退出码、不锚 Agent 自述；三态门禁 met/unverified/not_met，**显性保留"未验证"** | `fr-25`、`opc-104`、`fr-08` |
| P10 | **反博弈清单**：装机成功、生成文档、空壳用例、合成题满分，一律不加分；改标准=升版+保留旧分与旧哈希，禁回溯改分 | `fr-25`、`auto-002` |

## 4. 对你直觉的一处重要修正

> 你说："给他一个特别难的任务，看他有什么结果。"

**这条对"看见水平"成立，对"判定进步"不成立。**

材料里的硬约束（均来自原文，未经独立验证）：41 条冻结题的**最小可检测效应量约 30.9 个百分点**——也就是说，样本这么小时，两套方案的真实差距要大到 30 个百分点才看得出来；要压到 14pp 需要 **N≥200**。结论很直接：

- **一条长城任务 = 展示（demo）**，可以打动人、可以暴露致命问题，**不能用来宣称"变好了"**。
- **要宣称"变好了"，需要"长城任务族"**（同一族、多变体、200–500 个实例）**+ 对照 + 预注册阈值**。

所以设计是**两层**：

```
长城任务族（判定层） ── 同族多变体，N 足够，配对跑多臂，预注册阈值
        └── 旗舰长城任务（展示层） ── 一条超长、真实、可讲故事的，用来"看见水平"
```

旗舰任务负责**让人看到**，任务族负责**让系统可判定**。两者同一套运行器、同一套读数。

## 5. 长城任务测试桩的架构（五件套）

```
① 任务源        长城任务族 + 旗舰任务；每条带 front-matter（id/版本/难度/预期步数/注入点）
② 预注册文件    PRE-REGISTRATION：事前写死 指标定义 / 阈值 / 样本量 / 判定规则 / 停止条件
③ 运行器        Runner：冻结输出落盘（原始轨迹），多臂 × 多实例，配对同实例，成本五项记账
④ 结算器        Scorer：冻结输出 → 事后算分（可换指标重算），六层读数 + 三态判定
⑤ 归因台账      Ledger：预期登记簿（append-only）+ 证据链（E0–E3）+ 竞争性归因（H0–H4）+ 反驳台账
```

### 5.1 六层读数（取代"全对率"）

| 层 | 指标 | 为什么需要 |
|---|---|---|
| R1 | 端到端完成（EM） | 传统读数，但**只能当背景** |
| R2 | 分步 rubric 分 | 长任务里最终对错掩盖过程对错 |
| R3 | 连续距离分（编辑距离 / token-F1） | 连续指标比二值敏感 2–3 倍 |
| R4 | **首次重试成功率** | 材料建议的主指标：自纠错会抵消链式错误，端到端率低估强模型 |
| R5 | **校准度**（Brier / ECE） | "可校准能力"的直接量化——知道自己有多不确定 |
| R6 | **成本向量**：模型/工具/人工/重试/**错误后果** | 每合格交付成本才是真指标 |

### 5.2 长城任务必须具备的四个注入点

（对应材料里反复指认的代际分水岭：长程状态管理 + 错误恢复）

1. **误差可累积**：步数长到小错误会放大（不然测不出状态管理）。
2. **每步有真实可验证反馈**：锚定外部产物，不锚自述。
3. **权限受限点**：中途出现"该拒绝""该问人"的岔路（测 jidoka：何时必须停下）。
4. **意图漂移/指代歧义点**：注入模糊指代与上下文超载（这正是本项目 refer 层的高危区）。

### 5.3 判定规则（三态）

```
支持提升  ：预注册阈值全部达标 + 安慰剂臂无显著变化 + 前置门槛通过
推翻      ：任一关键指标劣化超界，或安慰剂臂也"提升"
证据不足  ：样本量不够 / 前置门槛未过 / 结果不一致     ← 合法结论，不许强行二选一
```
