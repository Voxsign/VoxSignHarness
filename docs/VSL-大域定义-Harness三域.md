# VoxSign Harness 大域定义 —— record / discuss / control（VSL 定义实例 2）

- 版本：v1.0 · 2026-10-02 · 用 VSL（描述定义语言）定义 harness 主域
- 一句话（自然语言版）：**先记录碎片（原汁原味）→ 再讨论建模（认知变强）→ 最后控制执行（达成结果）**；执行完对比"是模型错还是执行错"，结论回喂建模。这是认知-行动闭环。

---

## 1. 大域结构（VSL manifest）

```
space: harness-core
type: root（大域，未来后台的骨架）
子域：
  ├─ record   记录域   （碎片 → 素材）
  ├─ discuss  讨论域   （想法 → 模型，建模域）
  └─ control  控制域   （意图 → 结果，执行域）
```

三个子域共享：词汇表（实体词典）、认知层（模型/决策/OGSM）、轨迹层（证据）。

## 2. 子域定义

### 2.1 record 记录域 `.space`
```
name: record
purpose: 碎片沉淀——把不成熟、零散的想法原汁原味留下，做长期数据素材
input : 语音想法碎片（ASR 原文留底，不加工）
output: idea-log（追加）+ raw-notes（原文）+ 时间/来源/标签
consensus: 记录不做共识——先记录、后整理；只追加，不改写
acceptance: 原文 100% 保留、可检索、可回放（原汁原味可验证）
perms: vault-notes 追加（无改写权）
一句话: "我说的每句话都先存下来，一个字不改。"
```

### 2.2 discuss 讨论域 `.space`（建模域）
```
name: discuss
purpose: 建模——把不成熟想法变成对世界认知的模式（OGSM/决策/项目映射/边界）
input : 想法 + 历史认知 + 外部评审（多模型/研究引擎）
output: 模型更新（认知切片、决策、边界澄清、归因结论）
consensus: 讨论结果 = 共识达成 → 固化进认知层（低置信回问、结论显式化）
acceptance: 认知可追溯（讨论 → 结论 → 固化，链路完整）
perms: 认知层写入（vault + project-map + decisions）
一句话: "把事聊明白，模型就长厚一层。"
```

### 2.3 control 控制域 `.space`（执行域）
```
name: control
purpose: 达成结果——执行意图、调用工具（现实能量）、解决问题
input : 意图JSON + 域 + 验收标准
output: 执行结果 + 回执 + 轨迹（append-only）
机制  : 执行前 space_check（默认拒绝+权限交集）；执行后**预算对比**：
        "是模型/预算没想明白（建模错）？还是执行没做到（执行错）？"
        归因结论 → 回写 discuss（更新模型）
consensus: 低置信回问 / 高风险强确认 / 不可逆永远人工
acceptance: 验收标准达成（.accept 定义）
一句话: "动手干，干完对账：是我想错了还是没干好。"
```

## 3. 闭环机制（三个子域的关系）

```
        ┌─────────────────────────────────────────┐
        ▼                                         │
   record（碎片原汁原味）                          │
        │ 素材                                     │
        ▼                                         │
   discuss（建模/认知变强）                        │
        │ 模型/决策/验收                           │
        ▼                                         │
   control（执行/达成结果）                        │
        │ 对比归因：模型错 vs 执行错               │
        └─────────────────────────────────────────┘
        （新碎片 → 新一轮）
```

- **record 保证素材**：长期持续、原汁原味——模型的食物
- **discuss 保证认知**：讨论越多，对事情灵魂/根本目的越清楚——模型的骨架
- **control 保证结果**：执行现实动作达成目的——模型的手脚
- **对比归因**：每次执行后对账，错在模型还是执行——模型的进化回路

## 4. 自然语言优先（VSL 修订约定）

**每个定义块必须能用一句话自然语言讲清**，结构化字段只是它的投影：

| 域 | 一句话（你说的话） |
|---|---|
| record | "我说的每句话都先存下来，一个字不改。" |
| discuss | "把事聊明白，模型就长厚一层。" |
| control | "动手干，干完对账：是我想错了还是没干好。" |

规则：先有这句话 → 机器字段（purpose/input/output/consensus/acceptance）自动对应；未来你说的话全是自然语言，VSL 是它的规范层（词汇+语法+共识）。

## 5. VSL 规范修订建议（v1.1）

1. **自然语言优先**：定义块 = 一句话人话在前，结构化字段在后
2. **新增机制"对比归因"**：control 域的验收含"预算 vs 执行"归因，结论回写 discuss
3. **record 域约定**：只追加不改写（原文与结构化并存，互为索引）
4. 三域与 voxsign JEV 四门映射：record=record 门、discuss=sort+discuss 门、control=execute 门

## 6. v2 增补：三域判断字段（判断语义层，见 VSL-v2）

每个域定义强制回答："如果这个定义错了——错在哪、代价是什么、机器怎么反问我"

| 域 | anti 反例/失败模式 | cost 出错代价 | ask 反问方式 |
|---|---|---|---|
| record | 把整理稿当原话存；矛盾记录瞎选 | 素材失真，误导后续所有判断 | "这是原话还是我的整理？两份记录矛盾，信哪个？" |
| discuss | 立场冲突时系统附和默认假设 | 模型固化错误方向 | "你的立场和我的假设冲突，你是要纠正我还是在探索？" |
| control | 代价超预期仍闷头执行 | 不可逆损失 | "中途发现代价超预期——继续还是停？" |

补充机制：
- **record**：源优先级 + 原话/解释强制区分 + 矛盾上报（不瞎选）
- **discuss**：冲突 → 反问规则（不附和、不记笔记式退化）
- **control**：中断准则（失败时不做，而非做错后道歉）+ 共识状态机（已确认/暂定/待问/已失效）
