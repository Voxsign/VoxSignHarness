# VSL v2 —— 判断语义层（灵魂层）

- 版本：v2.0 · 2026-10-02 · 整合 Codex(gpt-6-astra) / Cursor(gpt-5.2) / Claude(claude-sonnet-5) 三方评审
- 回答的问题：**"描述出灵魂"到底指什么——为什么字段罗列≠懂，机器怎样才算真的懂**

---

## 1. 核心认知（三模型共识）

**字段罗列描述"是什么"（本体），机器"懂"是指：遇到字段没覆盖的新情况，能按你的立场做出和你一致的选择。**

VSL v1.1 只有"人话+字段"——人话若不约束行为，就只是注释。缺的是**判断语义层**：
- 目的（为什么存在、值得维护什么）
- 取舍优先级（冲突时牺牲什么、听谁的）
- 反例与失败模式（错误判断具体长什么样）
- 矫正触发与出错代价（何时承认不知道、何时被纠正）

> Claude 一句话："字段罗列是枚举情况，意图代数给一条能推演到未枚举情况的原则。"

## 2. 定义块强制字段（每个定义都必须回答）

```
如果这个定义错了——具体错在哪？代价是什么？机器该怎么反问我？
```

| 强制字段 | 回答的问题 | 示例（域定义） |
|---|---|---|
| purpose 目的 | 为什么存在 | "让碎片变成长期素材" |
| priority 取舍 | 冲突时牺牲什么 | "原文准确性 > 整理整洁" |
| anti 反例/失败模式 | 错会长什么样 | "把解释当原话存" |
| cost 出错代价 | 错一次付出多少 | "素材失真，误导后续所有判断" |
| correct 矫正触发 | 怎么知道自己错 | "你说'不是这个意思'两次 → 降置信度" |
| ask 反问方式 | 机器怎么问你 | "这是原话还是我的整理？" |

## 3. 两种语言的范式（模型 vs 控制）

| | 描述模型（认知/世界模式） | 描述控制（执行/边界/验收） |
|---|---|---|
| 本质 | **可被推翻的理解** | **可被验证的承诺** |
| 结构 | 信念 + 更新规则 | 权限 + 可逆性 + 确认阈值 + 中断准则 |
| 回答 | "世界大概率是什么样" | "我有多大把握承担做错的后果" |
| 示例 | 默认假设: 深夜消息=紧急；置信度: 高(命中>90%)；出错代价: 误判不紧急>>误判紧急；矫正: 连续两次纠正→下调假设 | 动作: 发取消通知；可逆性: 不可逆；默认确认: 需要；失败时: 不做，而非做错后道歉 |

**连接规则**：二者通过**共识**连接——不能从"我理解你"直接跳到"你授权了"。

## 4. 双向交互（系统有角色、会提问）

### 系统角色（定义在语言里）
- **有权质疑什么**：矛盾、授权歧义（"表达想法 vs 授权执行"）
- **必须解释什么**：影响下一步行动的歧义
- **哪些决定只能由你作出**：不可逆动作、超出范围

### 共识状态机（每条定义/理解带状态）
```
已确认 → 暂定（带置信度）→ 待问 → 已失效（语境漂移即失活）
```
推测永不冒充授权。

### 提问协议（最快达成共识）
不问字段问卷，问**边界案例和代价**：
1. "你是在表达想法，还是授权执行？——这决定我是否改文件"
2. "如果我理解错了，你希望我往保守还是大胆的方向错？"
3. "这件事做错了，后悔的成本是什么？"
4. 每次只问最关键的分歧，给出暂定理解与后果；用反例验证，别问"你同意吗"

## 5. 三域升级：从"容器"到"判断力"（反例吸收）

record / discuss / control 之前只是**系统内部管道**（存/聊/做），没规定判断。升级：

| 域 | 缺的判断 | 补上 |
|---|---|---|
| record | 矛盾信息信哪个源 | 源优先级 + 原话/解释强制区分 + 矛盾上报 |
| discuss | 立场冲突附和还是反问 | 冲突→反问规则 + 结论必须显式 + 可质疑 |
| control | 中断准则 | 代价超预期→继续还是停 + 失败时不做 |

（Model 意义 / Align 共识 / Commit 承诺 = 三域之上的能力闭环，record/discuss/control 是其存储/对话/执行通道。）

## 6. 一句话（v2 的灵魂版定义）

> **模型 = 可被推翻的信念 + 更新规则；控制 = 可被验证的承诺 + 中断准则；共识 = 让理解获得行动正当依据的过程。**
