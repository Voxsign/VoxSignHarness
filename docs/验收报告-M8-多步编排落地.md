## 1. 背景与验收口径

用户 2026-10-03 实测长任务：

> 「把全部沟通记录和设计文档整理成《VoiceSign Harness 全景开发文档》并保存提交」

该任务在旧 pipeline 下被压成**单条 NOTE append 进 notes.md**，且 **COMMIT 未触发**——即一整段原文被塞进笔记文件，没有真正去读源文档、没有生成目标文档、没有产生真实提交。

本次修复目标与验收口径：

- **长任务必须在 harness 内部走通真实闭环**：读文档 → LLM 汇总 → 写目标文件 → 定向 git add 单文件 + commit。
- **回执必须是真实多步动作链**，证据（evidence）含真实文件与真实 commit hash，例如 `receipt:file×6 + receipt:git`。
- **不得是占位回执**（"OK（自动执行）"空壳），**不得是整段原文 append 进 notes.md**。

## 2. 改了什么（设计取舍：方案 B 组织者式路由，非模型工具循环）

取舍说明：不做"让模型自己循环调工具"的 ReAct 式路由，而是由 harness 内一个确定性的**编排引擎**接管——意图命中后，按固定管线（读→汇总→写→提交）执行，回执可预测、可白名单、可幂等。

| 文件 | 改动 |
|---|---|
| `input/taskintent.go` | 新增 `detectOrchestrate` 复合意图识别：在单类触发**之前**判定。三连信号 =（整理/汇总/汇编）∩（文档/记录）∩（保存/提交/生成），并从《…》书名号中抽取目标文档名。命中后基线不可逆 → 走一次人工确认闸；普通 NOTE 不被误判（有单测覆盖） |
| `contract/contract.go` | 新增 `IntentOrchestrate = "ORCHESTRATE"` |
| `space/space.go` | `needsWrite` 纳入 ORCHESTRATE（编排写动作触发写域登记） |
| `pipeline/pipeline.go` | 编排引擎主体：`execOrchestrate`、`llmSummarize`、`ensureProjectSpace`、`commitTargetPath`（详见下） |
| `pipeline/orchestrate_test.go` | 新增：真实临时 git 仓端到端、`..` 穿越白名单拒绝、NOTE 不误判、幂等跳过 |
| `input/taskintent_orchestrate_test.go` | 新增：复合意图识别单测 |

`pipeline/pipeline.go` 内四个子能力：

- **`execOrchestrate`（编排引擎）**：读 5 份源文档 → LLM 汇总 → 写目标文档（写前带 `.bak` 备份）→ 定向 `git add <单文件>` + commit。**绝不 `git add -A`**，只提交本次生成的那一份文档。
- **`llmSummarize`**：`max_completion_tokens=8000`；system 提示"直接输出正文勿长篇推理"；出错/空结果均打日志；走 noJSON 纯文本、不带 temperature。
- **`ensureProjectSpace`**：惰性自动注册 project 域（`scope = 服务器 cwd 的 git rev-parse --show-toplevel`，落盘 `spaces/`），免去全新环境手工注册。
- **`commitTargetPath`**：幂等——`git diff --cached` 无变化则跳过提交，回执注明"内容无变化，跳过提交（已是最新）"。
