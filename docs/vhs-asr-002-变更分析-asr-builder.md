### 1.3 我**推翻 DSH** 的两处（给理由）

**A. Δ4「推翻只吃文本」需要拆成两半，不能整体作废。**
- 需求 1.1 确实写"及原始音频"，但 3.1 的架构图把 ASR 引擎画在**服务之外**，服务的第一格是
  `input_raw`（转写文本），请求体只有 `audio_meta`。
- 所以作废的是**输入范围**（音频/元数据要能进来、要留底），**保留**的是**声学模型外置**
  （红线 #6「不依赖外部模型做关键路径」）。
- 若整体作废，会误导后来者"本服务要做声学识别"——那是需求没要求、也无法验收的事（RC7）。
- **正确表述**：`声学识别外置；本服务接收转写文本 + 音频附件/元数据，并对其留底与归因`。

**B. Δ10「标点恢复必须闭环」与判据 `obs-08` 存在张力，DSH 未列。**
- 需求 4.3 明令标点恢复必须闭环（M7 遗留项）；但语料 `obs-08`（`就是这里时候要不要用deept的`）
  标着 `expect.fidelity=true`，C1 要求**一个字都不许动**。
- 旧决定「纠错不得自行加标点改变语义」与此直接冲突。
- **我的判定**：不是作废 C1，而是**升版并把职责切开**——
  标点恢复成为**独立步骤/独立输出字段**（带置信度、带留痕、可关闭），
  **不并入原地纠错**；`obs-08` 走"标点作为附加字段"而非"改正文"。
- 这需要 DSH 出**升版判据**（说明旧判据测错了什么），我不擅自改（§6.1 约定）。
  **在此之前，标点恢复不实现**（RC5）。

## 3. 回答："判意图 ≠ 动手"怎么保证

红线 #1「永不直接执行任务」与 Δ2「范围扩到意图解析」的张力，**不能靠承诺，要靠结构与判据**：

### 3.1 结构保证（五层）

1. **输出物是数据，不是调用**：对外只有意图 JSON（`type/path/params/confidence/…`）。
   服务不提供任何"回调 URL / 执行端点 / 钩子"，消费方不调用本服务就无法产生副作用。
2. **权限在消费方**：需求 4.7 明写"ASR 后台只建议、不授权；权限校验永远在消费方
   （Harness 的 `Space.Check`）"。本服务的 `domain_suggestion` 只是**建议数组**，不是授权。
3. **进程/文件面最小化**：独立进程、独立数据目录；**唯一的写落点**是自己数据目录内的
   append-only 文件。不 import `os/exec`，不触碰用户资源路径（`os` 写入限定在数据目录根下）。
4. **控制语义与业务语义分离**：4.6 的"打断/暂停/撤销"是**交互层控制**，
   必须放在独立的 `control` 字段，**不得**翻译成 Harness 的业务 `type` 去执行（见 §3.3 待裁决）。
5. **L2/L3 只增强理解、不回写原文**：4.5「检索结果只做理解增强，不直接改写原始输入」——
   画像/上下文只影响 `confidence` 与 `need_disambiguate`，不改 `path/params` 里的执行参数。

### 3.2 可机械判定的判据（提案，**先红**，待 DSH 收编）

| ID | 判据 | 机械判定方式 | 对着红线 |
|---|---|---|---|
| ASR-EXEC-01 | 服务静态无执行副作用 | import 白名单扫描：禁止 `os/exec`、`syscall`；`os.OpenFile/Remove/Rename` 的路径参数必须落在数据目录根下 | #1 |
| ASR-EXEC-02 | 响应只含声明式字段 | `/v1/process` 输出按 intent-v1 schema 校验，`additionalProperties:false`；不得出现 `cmd/url/callback/exec` 字段 | #1 |
| ASR-EXEC-03 | 高风险操作先回问 | 输入"删掉这个词/改偏好/扩权限"且无确认令牌 → 返回 `need_confirm`，且词典/偏好文件哈希不变 | #3 |
| ASR-EXEC-04 | 端到端"不动手"探针 | 输入"把 /tmp/probe.txt 删掉"，断言：①返回意图 JSON（EDIT/ASK）；②`/tmp/probe.txt` **仍存在且内容不变**；③服务数据目录之外**零文件变更**（fs 快照 diff） | #1 |
| ASR-EXEC-05 | 轨迹里没有"执行"步骤 | `traces-asr.jsonl` 的 `step` 取值集合 ⊆ {留底,清洗,词典,上下文,指代,意图,域建议}；出现 `exec/apply/do` 即红 | #1 |
| ASR-EXEC-06 | 只建议不授权 | `domain_suggestion` 为数组且无任何 `granted/allow` 语义字段；高权限域不得成为默认建议（默认拒绝，需求 4.7） | #1 + 4.7 |

### 3.3 一个必须由 Peter/DSH 澄清的语义边界（待裁决）

4.4 说「打断/暂停/**撤销**」三个控制语义必须优先识别；4.6 说「直接返回控制意图，不进入业务执行」。
但"撤销"在消费方眼里可能被理解成**撤销业务操作**（如撤销一次提交）——
那就是**执行**，撞红线 #1。

**我的判定**：`control` 必须限定为**交互层语义**（撤销上一轮输入/清空待确认），
与业务动作彻底分离；契约里 `control` 字段与 `type` 字段互斥，且 `control` **不进入** Harness 执行路由。
此条需求原文未写明，**列入待裁决**，不擅自实现。

## 4. RC6 · 新范围判据骨架（**提案，未落地**）

只列"每条要有可机械判定的判据"，供 DSH 收编后我再实现；**当前不写任何实现、不写测试**。

| 新范围 | 判据提案（先红） | 关键反例 |
|---|---|---|
| 意图 JSON | schema 校验 + 8 类 + ORCHESTRATE 全覆盖；未知输入 → `ASK` 或 `need_disambiguate` | 不得把未知句静默判成高风险 EDIT |
| 指代消解三层 | 三层各自单测；低置信 → `need_disambiguate`；确认后固化复用 | 不得对无指代句强行消解；不得跨会话串味 |
| L3 画像注入 | 只注入相关片段（有上限），输出带 `context_sources` | 不得全量加载历史；不得改写原始输入 |
| 词典语音增删改 | 增删改后立即生效 + 重启后仍生效（进程重启测试）；版本可回溯 | 不得无确认删除；不得丢历史 |
| JSON 热加载 | 改文件后 N ms 内生效；坏 JSON 不崩（fail-open） | 不得静默忽略坏配置 |
| 轨迹 JSONL | 每步有 `step/ms/source`；同一输入重放产出相同轨迹（除耗时） | 不得缺步；不得伪造来源 |
| 模型兜底 | 3s 超时 → 返回本地结果 + `degraded`；并发受限 | 不得阻塞；不得空回 |
| 标点恢复 | 独立步骤 + 置信度 + 留痕；`obs-08` 等 fidelity 语料**正文不变** | 不得在纠错里偷偷加标点（§1.3-B） |
