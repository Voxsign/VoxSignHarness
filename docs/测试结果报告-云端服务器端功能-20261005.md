## 三、发现的问题（按严重度）

1. **【中·生产风险】云端 VHS_TOKEN 未设置，设备注册接口无鉴权放行**
   - `GET /v1/health` 返回 `token_set=false`；`POST /v1/devices/register` 不带任何凭证即返回 200 并注册成功（发设备 token）。
   - 建议：云端部署环境设置 `VHS_TOKEN`，使 `/v1/devices/register|heartbeat` 走 Bearer 校验（本地 main 的 deviceToken 中间件已实现该逻辑）。

2. **【中·代码缺陷】本地（非 cloud）模式 `/v1/devices/register|heartbeat` 触发 nil panic**
   - 复现：`VHS_ADDR=127.0.0.1:18899 vhs serve`（无 VHS_TOKEN）后 POST register → `http: panic serving … nil pointer dereference`（devices.go:135）。
   - 根因：`server.New()` 仅云端模式初始化 `s.devices`（server.go:182 注释「云端模式创建，本地模式 nil」），但路由无条件注册（server.go:237-238），本地模式访问即崩。
   - 建议：本地模式对 `/v1/devices/*` 返回 501/400 或在本地模式也初始化 registry。云端模式不受影响（测试已通过）。

3. **【低·代码质量】`go test ./...` 全量失败：zhiji 包编译错误**
   - `zhiji/store.go` 使用 `SelfItem.Status` / `StatusActive` / `StatusSuperseded`，但 `zhiji/model.go` 的 `SelfItem` 结构体未定义 `Status` 字段及常量（store.go:123/126/143/160）。
   - 影响：`go build ./zhiji/...` 失败；`go test ./server/...` 及主程序 `vhs` 构建不受影响（zhiji 未接入主循环）。
   - 建议：`SelfItem` 增加 `Status string` 字段并定义 `StatusActive`/`StatusSuperseded` 常量后即可通过编译。
