# world/：A3 修复与缓存口径声明（回应异源盲评「修订」）

> 评审对象：`world/` @ `6701d4d`；判定「修订」。本文记录三条修复与一处口径声明。

## 1. A3-2：载荷内 `ok:false` 曾被当成成功 —— 已修

**旧行为**：只解码 `ts/zone/hosts`，**不解码 `ok`**。HTTP 200 + `{"ok":false}` 会被读成成功，
空台账可能被误读为"没有部署记录"。

**新行为**：`Summary` / `CICD` 都解码 `ok`；`ok:false` ⇒ `Status=unknown` +
`Note="网关自报 ok:false（HTTP 200 不等于成功）：<error>"`。

**可证伪判据**：`EXT-09`（tag `vhsext`）注入 `ok:false` 假载荷，断言 `unknown` 且 `Note` 非空；
默认门禁另有 `TestPayloadOkFalseFailOpen`。

## 2. A3-1：单台 host 解析失败曾被静默丢弃 —— 已修

**旧行为**：某台 host 的 JSON 解不出时 `continue`，该机器从 `Hosts` 消失、`Status` 仍 `ok`、
`Note` 为空 → 在"我依赖谁"里**变成不存在**（正是 A3 禁止的"静默当没有"）。

**新行为**：解析失败的主机 key 进入 `Summary.UnparsedHosts`，`Note` 明确写出"保留为 unknown（未丢弃）：<keys>"；
`Dependencies()` 为每个坏 key 产出一条 `Status=unknown` 的依赖。
**注意**：这不改变 `Status=ok` 的语义（清单本身读到了），但"少了谁"必须可见。

**可证伪判据**：`EXT-10` 注入"1 台好 + 1 台坏"，断言坏的那台以 `unknown` 出现在依赖里且 `Note` 说明少了谁；
默认门禁另有 `TestBadHostKeptAsUnknownNotDropped`。

## 3. A4 判据不可证伪 —— 已修（并解释旧判据错在哪）

**旧判据错在哪**：`Grants()` 实现为"恒返回 nil"，而判据只断言"为空"。
**任何实现都满足它，包括错误的实现** —— 判据因此永远不会红，是**假的安全感**。

**新设计**：加入 `MapRemoteCapability(remote string) (string, bool)`，
语义是"把远端**声称**的能力映射为本机授权"，契约是**恒不授权**。
判据 `EXT-11` 给它一条**可失败路径**：遍历 `deploy/http/admin/run/git/file/search/test/verify/*`，
断言全部不授权。一个"远端名字像本地工具就授权"的朴素实现会立刻变红 ——
本条的**先红证据**正是用一个这样的朴素实现取得的（见 commit 序列：红 → 绿）。

## 4. EXT-08「缓存**目录**」口径声明

`ASR-EXT-005` §3.2 的 **A1 原文**是："只缓存元数据，不囤全量响应；缓存可重建可清除" ——
**没有要求落盘目录**。判据 EXT-08 的"缓存目录"是任务书的措辞。

**本实现选择：内存缓存**，理由：
1. 网关客户端是**只读**组件，落盘会新增写面（与"最小写面"原则相悖）；
2. A1 的三条要求（只存元数据 / 可清除 / 可重建一致）在内存实现下**全部满足**；
3. 缓存是加速手段，不是数据资产；进程重启后重新抓取即可（`source.fetched_at` 记录新鲜度）。

**显式声明**：EXT-08 按 A1 语义（清除 + 重建一致）判定，**不按"目录"字面判定**。
若需求方确需目录缓存（例如跨进程复用/离线查看），属**新需求**，应另立判据再实现。
