# 人机校准节拍 v0

- 日期：2026-10-03
- 解决的问题：自动循环会**自欺**——自己产出、自己判分、自己宣布变好
- 定位：`长城任务测试桩-思路-v1.md` 的**外部锚点层**；`代码与版本管理方案-v0.md` 的**人工闸门**

---

## 0. 一句话

> 机器可以自己转，但**不能自己证明自己转对了**。
> 所以每隔一段，必须由**人**往环里注入三种外部锚点：**真实素材 / 人工评分 / 更高标准的校验元素**。

---

## 1. 为什么必须这样（不是谨慎，是材料里的硬教训）

| 失败模式 | 出处 | 表现 |
|---|---|---|
| **自评闭环** | `one-person-calibration` | 「我执行了校准所以方向正确」→ 把**过程合规**误认为**结果充分**，成为不可反驳的独白 |
| **单一内部信号触发结论** | 同上，失效条件④ | 仅凭内部数据（如某日 DAU 下跌）就归因，属协调熵失控而非理性探索 |
| **无对照、无预注册** | `fr-08` | n=1、无对照 ⇒ 结论不可外推；"修复成功"的假象反复出现 |
| **可观测性幻觉** | `ai-agent-coordination-reliability` | trace 视觉连贯 ≠ 语义正确；「可观测性仅放大了问题可见性，却未赋予判断力」 |
| **分数复制传播** | `fr-25` | 9 个工作区 rubric/observations 逐字节相同 = 「分数随仓库繁殖」，证据失效 |
| **低流量假绿** | `CICD-BOUNDARY-001:389` | 「没有错误」可能只是**没有样本**；观察不足不能写成统计验证通过 |
| **自动化悖论** | `fr-08` | 生成速度快过审查能力 → 人工被跳过 → 18 个任务全标 done 而 `reviews/` 是空的 |

**结论**：自产自证是这条链上最脆弱的一环。必须有**不由 agent 生产**的外部输入。

## 2. 三种外部锚点（全部由 Peter 提供，agent 不得自产）

### A. 真实素材锚
**是什么**：真实的对话、需求、任务——例如你与豆包几十个来回的内容。
**用途**：让系统在**真实复杂度**上暴露问题，而不是在我编的用例上自我感觉良好。
**形态**：一段原始素材 + 一句"我要的结果长什么样"。
**注意**：原始素材可能含隐私 → 只入**脱敏后的**任务定义；原始件不入 Git，只留哈希引用。

### B. 人工评分锚
**是什么**：人来打分，**不是 agent 自评**。
**打什么分**（沿用你文档里的五把尺 `VS-HARNESS-001:24-30` + 首要指标 `:38`）：

| 维度 | 问什么 |
|---|---|
| 复用证据 | 这个产出下次能直接再用吗？ |
| 净节省 | 比我自己做，省了多少？ |
| 迁移能力 | 换个项目还能用吗？ |
| 可验证性 | 我能不靠它自述就核验吗？ |
| 维护负担 | 我要为它长期背多少债？ |
| **人工注意力** | **这一轮，我花了多少分钟？**（`VS:38` 的首要指标） |

**评分必须带分母**：评了几条、哪些没评测——**未评测项显式保留，不许折算成 0 分或满分**（`fr-25`）。

### C. 更高标准的校验元素
**是什么**：更严的判据、更权威的参照、更强的评审——**强度要高于 agent 自己能生成的标准**。
**用法举例**：
- 把某个缺口的判定标准从"动作对了"提到"**副作用为零**"；
- 引入异源评审（不同模型 / 不同人）做**遮蔽式独立作答**（`auto-002` P3）；
- 引入**安慰剂臂**作为阴性对照（`auto-010`）。

**关键**：C 必须由**外部**给出。agent 自己提高标准 = 自定难度，等于没提高。

## 3. 节拍：什么时候必须插人工校验点

| 触发 | 条件 | 人做什么 |
|---|---|---|
| **C1 版本里程碑** | 任何准备打 tag 的版本 | 看结算摘要 + 打分；未过不发布 |
| **C2 "支持"判定** | 测试判定为"支持"（系统确实做不到），准备让开发 Agent 去修 | **确认这个缺口值得修**、优先级、以及判定标准是否被误设 |
| **C3 连续无提升** | 连续 N 轮（建议 N=3）读数无改善 | **强制停机**，人工归因；不许继续自动转（防空转烧钱） |
| **C4 高风险动作** | 涉及不可逆 / 外部动作 / 资金 | 逐次确认，不可被学习掉 |
| **C5 定期强制** | 即使一切"看起来正常"，每 7 轮也必须看一次 | 对抗"看似正常"——`fr-08` 的 18 个 done 就是在这种状态下发生的 |

**C3 和 C5 是防自欺的主闸**：一个防"越转越差没人管"，一个防"看起来没事其实没人看"。

## 4. 阶梯式校验强度（每一级都要上一级先过）

```
L0 机械门禁        CI：vet / test / gofmt / 可复现构建        ← 全自动，阻断
L1 自动评测        LHT 族 + 六层读数 + 三态判定               ← 全自动，非阻断
L2 人工评分        Peter 按 §2B 打分（带分母）                ← 人
L3 异源外部评审    不同模型/不同人 遮蔽式独立复核              ← 外部
```

**升级条件**：L0 绿 → 才允许 L1 出读数；L1 判定不是"证据不足" → 才进 L2；
**凡是要对外发布或写入 main 的，必须过 L2**；重大版本过 L3。

---

## 5. 防自欺四条铁律（违反即判定无效）

1. **自产不能自证**：agent 产出的东西（测试、标准、结论）不得作为它自己合格的证据。
2. **预期先写、事后不改**：人给的预期必须**事前书面 + append-only**，这是唯一的防篡改锚点。
3. **分数必带分母**：任何分数必须报"评了几条 / 未评测几条"，未评测显式保留。
4. **单一内部信号不得触发结论**：结论至少要**一个外部锚点**参与。

## 6. 记录：每次人工校验点留下什么

```yaml
checkpoint_id: HC-0003

version: { commit_sha, rubric_hash, prereg_hash, model_version }   # 四元组
anchor:
  material: { ref: <脱敏素材哈希>, provided_by: Peter }
  human_score: { 复用证据: 3, 净节省: 4, 迁移: 2, 可验证性: 5, 维护: 3, 人工分钟: 25, 分母: "7/42 条已评" }
  elevated_criteria: [ "副作用=0（原为：动作正确）" ]
verdict: 继续 | 提升标准 | 停机人工归因 | 放弃该方向
actions: [ rule | checklist | alert ]      # 闭环守卫：没有动作 = 死循环
```

## 7. 与自动循环的接口

```
自动循环：①取缺口 → ②开发 → ③推送 → ④CI门禁 → ⑤拉取 → ⑥测试 → ⑦判定 → ⑧回写
                                          ↑                              ↓
                                     人机校准节拍 ◄──── C1/C2/C3/C4/C5 触发
```

**人工校验点不是"打断自动循环"，而是循环的一个正式状态**。
没有它，循环会退化成 `fr-08` 那种"能自己跑 ≠ 可靠"。
