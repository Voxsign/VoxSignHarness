# 版本台账

> **规矩**（Peter 2026-10-03）：「以后每次给一个大的版本或一个标签，这样版本不至于搞乱。
> 接下来测过什么、用过什么东西，把版本管理做起来。」

## 命名

```
v<主>.<次>.<修订>-test.<序号>    可测版本（交异源测试方，冻结 sha + Release）
v<主>.<次>.<修订>                正式版本（测试通过后，由 Peter 决定）
```

**一条铁律**：**只有"已验证且冻结"的 commit 才打 tag。**
**在动的东西不许打 tag** —— 否则测试方测的是一个漂移对象。

## 每个版本必须带（缺一不可）

```
① 冻结 sha + git tag
② GitHub Release（含内容、验证、已知缺口）
③ 一条 Issue 回写（被测范围、怎么开始、验收标准、回写目标）
④ **已知缺口清单** —— 让测试方别把已知的当新发现，也别漏掉未知的
⑤ **测过什么 / 用了什么** —— 见下
```
