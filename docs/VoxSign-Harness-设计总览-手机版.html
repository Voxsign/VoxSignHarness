PHILOSOPHY

设计哲学（定调）

不是造软件，是造"我的生产底座"。10 倍效率来自底座复利。
原则内容
认识与执行分离边界 = 契约。分得越清楚越好，背后是哲学。
软件是生长问题认知层（文字慢变）→ 接口层（契约版本化）→ 执行层（代码快确定）+ 生长回路。
标准化 vs 个性化显性化/标准化 → 用基础设施（模型调用/ASR/权限）；个性化 → 自建服务（认知/词典/OGSM）。
先稳住再变模型中心 / 翻译 / 备份先拆稳，一步稳住再动下一步。
模型优先思维先有模型 → 执行 → 对比归因（模型错 vs 执行错）→ 更新模型。
LANGUAGE · VSL

交互语言 VSL（v1 + v2）

本质：自然语言 + 规范（代指 / 域 / 决策标准）→ 让系统真的懂你。这是"新时代的模型描述语言"。

三要素

要素内容
词汇域 space · 实体 entity · 契约 contract · 意图 intent（8 类）
语法"在[域]里 [动作] [对象]"；对象可代指（它 / 那个）
共识机制低置信回问 · 高风险强确认 · 确认后固化

四种共识（语言的目标）

决策标准代指对象活动空间执行语义

v1.1 自然语言优先

每个定义块 = 一句话人话在前（"先记录碎片，一个字不改"），结构化字段在后自动对应。

v2 判断语义层（灵魂层）——三模型评审定稿

核心认知：字段罗列描述"是什么"；机器"懂"= 遇到没列举的新情况，能按你的立场做出和你一致的选择。灵魂 = 判断力，不是文案。

强制字段回答的问题
目的 purpose为什么存在、值得维护什么
取舍 priority冲突时牺牲什么、听谁的
反例 anti错误判断具体长什么样
出错代价 cost错一次付出多少
矫正触发 correct怎么知道自己错了
反问方式 ask机器怎么问你
两种语言范式：描述模型 = 可被推翻的信念 + 更新规则（"世界大概率是什么样"）；描述控制 = 可被验证的承诺 + 中断准则（"我有多大把握承担做错后果"）。二者通过共识连接——不能从"我理解你"跳到"你授权了"。

双向交互（系统有角色）

角色 = 有权质疑什么 · 必须解释什么 · 哪些决定只能你作。共识状态机：已确认 / 暂定（带置信度）/ 待问 / 已失效。
提问协议：不问字段问卷，问边界案例和代价——"你是在表达想法还是授权执行？""理解错了希望我往保守还是大胆错？""做错了后悔成本多少？"

交互形态

语音为主（≈90%，口语短句、可回问）+ 截图为辅（≈10%，截图 = 指代消解第四路信号）+ 文字精确回执。

SPACE · HARNESS-CORE

大域：record / discuss / control

一句话：先记录碎片（原汁原味）→ 再讨论建模（认知变强）→ 最后控制执行（达成结果）；干完对账，结论回喂建模。
RECORD · 记录域
碎片 → 素材
"我说的每句话都先存下来，一个字不改。"
  • 只追加不改写：原文 100% 保留、可检索可回放
  • ASR 原文留底，先记录、后整理
  • 判断层：反例=把整理稿当原话；矛盾记录不瞎选，上报问源
DISCUSS · 讨论域（建模域）
想法 → 模型
"把事聊明白，模型就长厚一层。"
  • 建模 = 对世界认知的模式（OGSM/决策/项目映射），不是调用模型
  • 讨论越多，对事情灵魂/根本目的越清楚
  • 判断层：立场冲突不附和、必反问；结论显式、可质疑、可追溯
CONTROL · 控制域（执行域）
意图 → 结果
"动手干，干完对账：是我想错了还是没干好。"
  • 执行前 space_check（默认拒绝 + 权限交集）
  • 执行后对比归因：模型/预算没想明白 vs 执行没做到 → 回写讨论
  • 判断层：代价超预期→继续还是停；失败时不做，而非做错后道歉
record → discuss → control → 对账归因 → 回喂建模 → 新碎片触发新一轮

record 保证素材（模型的食物）· discuss 保证认知（模型的骨架）· control 保证结果（模型的手脚）· 对账归因是进化回路。

ARCHITECTURE

架构要点

域 Space（三模型评审定稿）

机制内容
有效权限平台 ∩ 域 ∩ 工具声明 ∩ 本次授权的交集；风险分级不能突破上限
默认拒绝未匹配 / 跨域 / 目标不符 → 拒绝，绝不退回更宽权限
逃逸规则宽松域不能掩盖单次高风险操作（push --force 永远是高风险）
数量控制3–7 个域；project 参数化（scope 作参数），不按项目开域
漂移检测manifest 与实际路径定期校验，漂移即失效
意图兜底模型只出候选域，代码消歧；首次/高风险显式回显；未知→global 只读，绝不"猜最像的"

指代消解（模糊 → 精确）

层级机制与例子
代码层实体词典（100%）：季总→冀总(Amber)、美墅→Mansour
逻辑层上下文规则："它"→上一条回执的文件；域 = 指代作用域
语言层模型推断："上次报价那个客户的项目"；低置信回问
闭环确认后固化词典 → 下次代码层直接命中（每次成功=少问一次+词典变厚）

确认策略（三信号）

可逆性（硬事实）× 影响面（静态评估）× 置信度。不可逆永远人工确认（硬规则，不可被学习掉）。

组合行为
可逆+小+高自动执行 + 标待抽查
可逆+中展示 diff 摘要 → 轻确认
可逆+高强确认（diff 预览 + 影响分析）
不可逆永远人工（无论置信度）

契约与自举

verify 契约 = 独立校验器（读实际状态，不读自报）；search 契约；四元组缓存 {意图,域,权限,指代}（最后做）；REGISTER_TOOL = 自举充分条件（语音注册新契约）。

双端架构

手机 = 唯一交互面（ASR 语音输入 + 回执 + 确认）；电脑 = 远程执行引擎（Go harness + 模型 + 工具 + 校验 + 沉淀）。回执一屏 4 行看懂：动作 / 文件 / 结果 / 撤销；diff 不刷屏，详情语音追问。
