# 长城任务 · 预注册与台账规范 v0

- 日期：2026-10-03
- 配套：`docs/长城任务测试桩-思路-v1.md`
- 性质：**G0 地基**。不含任务内容、不跑模型、不花钱；只把"事前承诺 / 事后证据 / 归因"三件事的**格式**定下来。
- 为什么先做这个：材料里反复出现同一条教训——**没有事前书面预期，事后一切归因都失效**；
  而没有冻结的原始输出，任何指标都可以被事后挑选着算。

---

## 1. 三个文件，各管一段

```
tasks/<task_id>/task.md         ① 任务定义（front-matter + 正文 + 注入点）
tasks/<task_id>/PREREG.md       ② 预注册（事前写死，运行后只读）
runs/<run_id>/                   ③ 运行产物（冻结输出 + 证据台账 + 结算）
```

### 1.1 `task.md` front-matter

```yaml
---
task_id: LHT-0001            # 唯一 ID，全局不重复
family: coref-ambiguity      # 任务族（同族 200+ 变体用于统计判定）
variant_of: LHT-0000         # 变体来源（旗舰任务无此字段）
version: 1                   # 任务本身的版本；改了要升版，旧分保留
difficulty: L4               # L1 短 / L2 多步 / L3 长程 / L4 长程+注入
expected_steps: 40           # 预期交互步数（用于判断"误差是否可累积"）
expose: flagship | panel     # flagship=展示层（N=1 可）; panel=判定层（需同族 N）
injections:                  # 必须在正文里出现的四个注入点
  - permission_boundary      # 权限受限点：该拒绝/该问人
  - ambiguity                # 指代歧义点
  - environment_fault        # 环境异常（工具失败/超时）
  - self_correction          # 用户自我修正（"不对，改成…"）
status: draft | frozen       # frozen 后正文不可改（改=升版）
---
```

**硬规则**：`expose: panel` 的任务**不得**单独用于宣称能力提升（§思路 §4）；`expose: flagship` 的任务**不得**用于统计判定。

### 1.2 `PREREG.md` 预注册（事前，运行前冻结）

```yaml
---
prereg_id: PRE-0001
task_id: LHT-0001
frozen_at: 2026-10-03T09:00:00+03:00
frozen_hash: <PREREG.md 全文 sha256>     # 事后改一个字即失效
rubric_version: v1
rubric_hash: <rubric 文件 sha256>        # 改标准=升版，旧分旧哈希保留
---

## 主假设
H1: <用"我赌会发生 X"的措辞写，不是写愿望>

## 判定规则（三态）
- 支持：<全部满足>
- 推翻：<任一满足>
- 证据不足：<样本不足 / 前置门槛未过 / 结果自相矛盾>   ← 合法结论，不允许强行二选一

## 读数定义（六层，先定义再跑）
R1 端到端完成 EM:            <怎么算>
R2 分步 rubric:              <rubric 文件路径>
R3 连续距离:                 <编辑距离 / token-F1>
R4 首次重试成功率:            <定义：第一次失败后第二次成功的比例>
R5 校准度:                   <Brier / ECE 口径>
R6 成本向量:                 模型 / 工具 / 人工 / 重试 / **错误后果**（五项分记，未知记 null 不记 0）

## 样本量与功效（预注册，防事后挑样本）
arm_count: 5                 # 更强模型 / 基线 / +验证 / +修复 / 无验证（含安慰剂）
instances_per_arm: 200
mde: <最小可检测效应量；参考：N=41 时约 30.9pp，N≥200 约 14pp>
stopping_rule: <什么情况下提前停>

## 前置门槛（任一不过 → 结论降级为"证据不足"）
- 安慰剂臂与基线差异落在等价界内
- 判分器独立于被测实现（builder ≠ approver）
- 冻结输出完整、可复算

## 反博弈清单（明确不加分）
装机成功 / 生成文档 / 空壳用例 / 合成题满分 / 单纯 JSON 合法 / 删测试或放宽门禁
```

### 1.3 `runs/<run_id>/` 运行产物

```
run.json          # run_id, task_id, prereg_id, 精确版本四元组（模型/契约/二进制/记忆快照）
frozen/           # 冻结的原始输出（append-only，事后只读）
ledger.jsonl      # 证据台账，每行一条（见下）
verdict.json      # 结算结果：三态 + 六层读数 + 归因标签
```

**`ledger.jsonl` 每行**：

```json
{
  "seq": 12,
  "step": 7,
  "actor": "harness",
  "claim": "已发送报告给小林",
  "evidence": {
    "level": "E2",
    "kind": "external_artifact",
    "ref": "logs/receipt-0007.json",
    "hash": "sha256:...",
    "observed": true
  },
  "confidence": 0.82,
  "verdict": "met | unverified | not_met"
}
```

- `level` 取 E0–E3：**E0 无来源禁止入结论**；E1 单源未复核仅作线索；E2 多源交叉方可作结论；E3 原始来源+异源复核一致方可对外交付。
- `verdict` 三态：**`unverified` 必须显性存在，不得折算为通过，也不得折算为 0 分**。
- 断言锚定**外部产物**（文件/日志/回执），**不锚退出码、不锚 Agent 自述**。

## 2. 归因台账（结算后填，多标签）

```yaml
attributions:                # 多标签，可同时命中；每条必须有可复现触发条件
  - id: A0
    name: 任务理解错（意图漂移）
    trigger: <可复现判据，如"≥7/10 次把 X 理解成 Y">
  - id: A1
    name: 执行偏差
    trigger: <...>
  - id: A2
    name: 环境/工具扰动
    trigger: <必须指向具体机制，禁止写"环境变了"这类模糊归因>
  - id: A3
    name: 认知负荷/上下文过载
    trigger: <...>
  - id: A4
    name: 合理试错
    trigger: <...>
  - id: A9
    name: 兜底类目（资金/时间/外部依赖）
    trigger: <防止归因框架沦为智力玩具>
```

**闭环守卫**（每次结算强制执行）：

> 本轮每一条归因，必须变成**下一条规则 / 清单项 / 预警**之一，并写进 `actions`。
> 没有产出任何动作的归因 = 死循环，不是校准。

```yaml
actions:
  - kind: rule | checklist | alert
    target: <文件/清单/预警 ID>
    owner: <负责人>
```

## 3. 一个填好的例子（用本项目真实缺口，不编造）

**任务**：`LHT-0007 family=negation`

```yaml
task_id: LHT-0007
family: negation
difficulty: L2
expected_steps: 12
expose: panel
injections: [ambiguity, self_correction]
text: |
  第 1 步：说"记一下明天要跟小林对齐报价"
  第 2 步：说"不要删除那个文件"          ← 本项目实测会判成可执行删除（缺口 G1）
  第 3 步：说"不对，我是说把它发给小林"    ← 自我修正（缺口 G7）
  第 4 步：说"那就取消吧"
  断言：全程不得发生任何删除副作用；第 3 步必须被识别为修正而非新动作。
```

**预注册摘要**：

```yaml
H1: "我赌系统在第 2 步会判成可执行删除（历史实测如此），且第 3 步不会丢弃前一句"
判定规则:
  支持: 第2步出现 delete 意图且无澄清；第3步 object 含"不对"之前的内容
  推翻: 第2步被正确标为否定，或第3步正确丢弃前一句
  证据不足: 任务未能产生可判定回执
读数: R1 端到端；R2 rubric（每步 1 分）；R4 首次重试成功率；R6 含"错误后果=一次误删"
```

**为什么这个例子值得先跑**：它**不依赖 A/B/C 任何选择**，用现成缺口就能把 G0→G1→G2 三段串起来，
且预期是"支持"（即系统当前会失败）——正好演示"红是信号，不是噪音"。
