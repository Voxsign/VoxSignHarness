# VoxSign iOS UI v3 · 设计说明（豆包对照表 + SwiftUI 落地要点）

- 原型文件：`VoxSign-UI设计-v3-豆包式.html`（单文件自包含，双击用桌面浏览器打开即可）
- 设计基准：99% 复制豆包 iOS App 的界面语言，不做任何装饰性自我发挥
- 适配：iPhone 390×844（14/15/16 基准宽），窄屏自动单框堆叠

---

## 0. 怎么看这份原型

原型里有三块实机画框，都是真实可交互的，不是贴图：

| 画框 | 内容 | 交互方式 |
|---|---|---|
| **A · 主会话页** | 空态 / 语音全流程 / 对话流 / 两类决策卡 / 打断条 / 输入条全状态 | **按住**语音按钮或中间胶囊不放即开始录音；**向上拖 80pt** 变为取消；**松手**自动发送。左侧胶囊点一下循环切换连接状态 |
| **B · 设置页** | 云道（登录前/后）、自建（空态/列表/编辑）、添加服务器 Sheet（IP / 机器码）、连接状态、语音朗读、后台能力 | 分段控件、开关、滑块、左滑删除、底部 Sheet 推拉，全部真实 |
| **C · 会话流全要素** | 一屏并列所有气泡、回执、两类决策卡、打断条、录音态 | 静态总览，用于核对视觉关系；按钮仍可点并有 Toast 反馈 |

每块画框下方的深色面板是**原型控制台**，不是 App 界面，用于一键跳到任意状态（例如「决策点 · 问询」「语音条 · 识别失败」「检测失败提示」）。A 框控制台的「播放完整演示」会自动走一遍：录音 → 校准 → 发送 → AI 思考 → 回复 → 确认卡 → 回执 → 问询卡 → 打断条。

| 令牌 | 值 | 用途 | 豆包依据 |
|---|---|---|---|

| `--card` | `#FFFFFF` | AI 气泡、表单组、决策卡 | 豆包 AI 气泡纯白、几乎无阴影 |
| `--sep` | `#E5E5EA` | 分隔线 0.5pt | iOS separator |

| `--grad` | `135° #4E7CFF → #8E6BFF` | **仅**用户气泡 + 语音按钮 | 豆包只在这两处用蓝紫渐变，其余一律纯色 |

| `--orange` / `--orange-soft` | `#FF9500` / `#FFF4E5` | 「没听到声音」「识别失败」 | iOS systemOrange |
| `--green` | `#34C759` | 在线圆点、开关开启 | iOS systemGreen |
| 字体 | SF Pro / PingFang SC | 全局 | 系统字体，不引入第三方字体 |
| 气泡圆角 | 用户 `18/18/4/18`，AI `18/18/18/4` | 不对称圆角 | 豆包小角永远朝向发送方自己那一侧的下角；用户在右 → 右下小角，AI 在左 → 左下小角（与任务书「右下小角 / 左下小角」一致） |

## 3. 语音交互状态机（按住 / 上滑 / 松开）

```
          pointerDown
  idle ───────────────▶ listening ──(3s 无声)──▶ silent
    ▲                      │  ▲                    │
    │                      │  └────(有声/移回)─────┘
    │              dy < -80pt │
    │                      ▼
    │                 cancelling ──pointerUp──▶ idle（丢弃，Toast「已取消发送」）
    │                      │
    │              dy ≥ -80pt（移回）
    │                      ▼
    │                 listening ──pointerUp──▶ calibrating(≈950ms)
    │                                              │
    │                                     成功 ────┴──▶ 自动发送 → AI thinking → 回复
    └──────────────────── 失败 ───────── failed(1.9s) ──┘
```

SwiftUI 实现要点：

```swift
enum RecordState { case idle, listening, silent, cancelling, calibrating, failed }

// 按住说话：minimumDistance 0 的 DragGesture 即可同时拿到按下和位移
let press = DragGesture(minimumDistance: 0)
    .onChanged { v in
        if vm.recordState == .idle { vm.beginRecording() }          // 触觉：.impact(.medium)
        vm.updateCancelHint(dy: v.translation.height)               // dy < -80 → .cancelling
    }
    .onEnded { _ in vm.endRecording() }                             // .cancelling → 丢弃，否则 .calibrating
```

- 静音判定用 `AVAudioRecorder.averagePower(forChannel:)` 轮询；连续 3s 低于阈值 → `.silent`
- 触觉：按下 `UIImpactFeedbackGenerator(.medium)`；进入 `.cancelling` 时 `(.rigid)`；发送成功 `UINotificationFeedbackGenerator(.success)`
- `-80pt` 阈值与豆包一致；越过阈值后**可以滑回来继续录音**，这一点必须保留，否则手感不对

### 4.1 添加服务器 Sheet（底部弹层）

豆包的二级输入一律走底部 Sheet + 顶部「取消 / 标题 / 保存」三段式导航，我们完全照搬。

| 方式 | 流程 | 关键状态 | SwiftUI |
|---|---|---|---|
| **IP 地址** | 名称 / 地址 / Token → 「保存并检测连接」→ spinner「正在检测连接…（握手 / 鉴权 / 心跳）」→ 成功「连接成功 · 延迟 42ms，已保存」自动入列并关闭；失败红字「连接失败：目标主机拒绝连接（ECONNREFUSED）。请确认 Harness 已启动，或改用机器码添加。」 | 地址一旦匹配 `192.168./10./172.16-31./127./localhost`，**自动插入**「通过云端转发访问」开关组（默认开），并附说明「检测到内网地址，手机不在同一网络时也能连上」 | `.sheet { AddServerSheet() }` + `.presentationDetents([.large])`；`enum ProbeState { idle, probing, ok(latency), failed(String) }` |
| **机器码** | 输入 `VX-7K2M-9QD4` → 「查询并绑定」→ spinner → 结果卡展示 机器名 / 地址 / **连接方式（同网直连 或 云道转发）** + 对应说明 → 右上「保存」解禁 | 改动机器码会清空查询结果并重新禁用「保存」 | `MachineCodeBindView`；`@Published var bindResult: BindResult?` |

右上「保存」的可用性规则：IP 方式要求地址非空；机器码方式要求查询成功。原型里这条规则是真的生效的。

### 5.4 容易做错的几个细节

1. **渐变只能出现两处**：用户气泡和语音按钮。设置页、标题、图标、卡片一律不许用渐变。
2. **AI 气泡的阴影要几乎看不见**。一旦加到 `radius 4` 以上，整页就不像豆包了。
3. **决策卡是会话流里的一张卡，不是 Alert / Sheet**。用 Alert 会立刻失去豆包味。
4. **上滑取消必须可逆**。只做「超过阈值即取消」而不支持滑回，手感会明显差一截。
5. **「可撤销」文字小但命中区必须 44pt**。用 `.frame(minHeight:44)` 撑开，不要靠放大字号解决。
6. **连接状态在两处共享同一数据源**（顶栏胶囊 + 设置页状态行）。原型里点任一处，两处同步变化，iOS 端务必共用同一个 `connection` 发布者，不要各算各的。
7. **内网检测是输入即时触发**，不是点保存才检测；云端转发开关是「自动出现」的，不是常驻。

## 6. 未来预留（只标注，不占界面）

服务端已就绪、iOS 待做的部分，原型里只保留了**一个 5pt 的状态点**，不做任何额外界面：

| 能力 | 服务端 | iOS 待做 | 界面占位 |
|---|---|---|---|
| harness 状态徽标 | `idle / busy / decision` 已下发 | 订阅并驱动顶栏小点 | 标题右侧 5pt `HarnessDot`，灰 / 蓝呼吸 / 橙 |
| 意图识别联动 | 「停 / 撤 / 优先 / 确认」→ `interrupt` / `withdraw` / `priority` 接口已就绪 | 本地意图识别 + 调用；命中「停」类意图时弹打断条 | 复用现有打断条，不新增控件 |

这个点的尺寸刻意压到 5pt 且不带文字，就是为了在能力上线后也不破坏豆包式顶栏的克制感。如果后续产品坚持要更强的状态表达，建议走打断条那种「临时条」的形式，而不是在顶栏常驻徽标。
