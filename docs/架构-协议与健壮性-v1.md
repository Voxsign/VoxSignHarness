## 1. 背景与目标

VoxSign 双线（本地自建线 / 云端云道线）已全链路跑通。随着真实使用场景深入，暴露三类架构命题：

1. **通信机制**：任务提交/结果/状态/心跳用什么协议与连接，如何标准化。
2. **快速打断**：长任务堵死时「说停就停」；说错时能「撤回」；急事能「插队」——本质是控制面必须不排队、立即生效。
3. **健壮性**：一切外部调用（平台 ASR、模型服务、远端进程）必须有超时/熔断/重试/隔离兜底，任何单点卡死都不能拖死主进程。

**设计总纲**：

- 控制面（心跳 / 打断 / 撤回 / 确认）与数据面（任务 / 音频 / 结果）分离——控制命令不排队、立即生效。
- 心跳、打断、撤回、健壮性共享同一套「控制层」能力：短超时、独立执行路径、状态联动、可审计。
- 协议按场景分层决策：低频管理类保持 HTTP+JSON；实时语音走 WebSocket 双工；结果推送保持 SSE。
- 外部调用四件套：超时分层、熔断、重试退避、批量隔离；回调模式也必须带计时器兜底。

## 2. 系统拓扑（云道 / 自建双模式）

```
                 ┌──────────────────────────┐
                 │      iOS App（VoxSign）    │
                 │  录音 48kHz→ASR · 本地TTS  │
                 │  Google OAuth 登录 · JWT   │
                 └────────┬─────────┬────────┘
             自建(直连)   │         │  云道(默认)
                          ▼         ▼
              ┌──────────────────────────────────┐
              │   Harness（vhs · Go）             │
              │  机器码 XXXX-XXXX-XXXX · 自适应心跳 │
              │  任务队列(priority) · SSE结果流    │
              │  控制面: interrupt/withdraw/confirm│
              └──────┬───────────────┬───────────┘
                     │               │
         ┌───────────▼───┐   ┌───────▼───────────┐
         │ 平台外部服务    │   │ 云端目录(云道)      │
         │ ASR/模型/远端   │   │ 设备注册表·租户落盘  │
         └───────────────┘   │ lookup 返回 state   │
                             └─────────────────────┘
```

- **云道**：零配置，Google 登录即用；Harness 机器码注册云端目录，云道只做目录 + 应急转发，不常驻中转。
- **自建**：默认空列表；添加服务器（IP 地址 / 机器码）；内网 IP 自动出现「通过云端转发」开关；保存前必检连通性。

## 3. 分层架构：控制面 vs 数据面（核心原则）

| 面 | 承载 | 特征 | 要求 |
|---|---|---|---|
| **控制面** | 心跳、interrupt、withdraw、cancel、confirm | 低频、语义小、时效强 | 不排队、立即生效、短超时、独立执行路径、永不阻塞 |
| **数据面** | 任务提交、ASR 音频、SSE 结果流、产物 | 高频/大体积/可排队 | 可排队、可重试、断线重连、流式 |

**铁律**：

1. 控制面命令不被任何任务执行阻塞——独立 handler 直接作用于任务表 / 设备表。
2. 控制面自身永不超时挂死：短 deadline + 独立 worker。
3. interrupt 只影响发出时刻的活动任务；新任务不受历史 interrupt 影响（时序护栏）。
4. 打断 / 撤回 / 熔断全部记日志，可回溯「谁在何时打断了什么、卡了多久」。

## 4. 协议矩阵（现状 → 目标）

| 场景 | 现状 | 评估 | 目标 | 优先级 |
|---|---|---|---|---|
| 任务提交/确认 | HTTP POST + JSON | 合理 | 保持；`/v1/tasks` 增加 `priority` 字段；补统一错误码契约 | — |
| 结果推送 | SSE 流（`GET /v1/tasks/{id}/events`，seq 重连） | 已达标 | 保持；TLS 后自动 HTTP/2 | — |
| 在线/心跳 | iOS 30s 轮询 /v1/status + Harness 2min POST 心跳 | 冗余分散 | 统一为自适应 4 态心跳（见 §5） | P1 |
| 语音上行识别 | 整段录音 multipart 上传 → 一次返回 | 最大延迟瓶颈 | WebSocket 双工：音频分片边说边传 + 中间结果流式回（需先确认平台流式 ASR 支持） | P0 |
| 语音输出 | iOS 本地 TTS | 可接受 | 保持；多音色/远程 TTS 另议 | — |
| 认证/租户 | Google OAuth + JWT Bearer | 标准 | 保持；JWT 短时续期 | — |
| 传输层 | 本机明文 HTTP/1.1；正式域名 HTTPS | — | 生产全 HTTPS（HTTP/2 自动）；本机测试保留明文 | P1 |

**传输层决策**：Go net/http 与 iOS URLSession 在 TLS 下自动协商 HTTP/2 多路复用，SSE 与上传均受益，无需改代码。

## 5. 自适应心跳协议

### 5.1 状态机（Harness 自判，4 态）

```
       任务提交                 出现确认项
 idle ──────────► busy ──────────────► decision ★
 ▲  ▲             │  ▲                 │
 │  │任务完成      │  │用户拍板/超时      │
 │  │             ▼  │                 ▼
 │  └──────────── idle ◄────────────────┘
 │  长时间无交互
 └──────────────► standby
      新任务 ◄──────────
```

| 状态 | 心跳周期 | 适用场景 |
|---|---|---|
| decision 待决策 | **5 秒** ★ | 有 confirm 等你拍板，随时响应 |
| busy 忙碌 | 15–30 秒 | 任务执行中，你在等结果 |
| idle 空闲 | 2 分钟 | 常规待机 |
| standby 待命 | 5 分钟 | 持续干活、无需交互，最省 |

**事件驱动 + 周期双轨**：状态切换瞬间立即补发一次心跳（不等下一周期）——切到 decision 那一刻云端马上知道。

### 5.2 心跳负载（轻量 JSON，服务端只更新 last_seen + state）

```json
{"machine_code":"EG7Z-ULPP-ZYR5","state":"busy","pending":2,"uptime_s":86400,"v":"0.2.1"}
```

5 秒心跳一天约 17KB/台机，负担可忽略；多机规模化后再收紧。

### 5.3 服务端勾兑

- online 判定**窗口化**：`now − last_seen < 3×当前周期` 才算在线——慢心跳不误判离线。
- 记录 state；`lookup` 返回 state → iOS 显示「忙 / 闲 / 待决策」徽标。
- 卡住任务报 busy；超时熔断强制中断后切 idle/failed——iOS 实时可见「被掐断」。

## 6. 打断 / 插队 / 撤回协议

### 6.1 意图语义（iOS 录音结束先判意图，再走任务流）

| 意图 | 口语 | 动作 | 协议 |
|---|---|---|---|
| 打断 | 停停停 / 别干了 / 闭嘴 | 立刻终止执行中任务，丢弃输出 | `POST /v1/interrupt`（可带 task_id，缺省=当前活动任务；`force=true` 连排队任务一起清） |
| 撤回 | 我说错了 / 撤回 / 删掉刚才的 | 按阶段分层处理 | `POST /v1/withdraw {task_id, scope}` |
| 插队 | 这个优先 / 赶紧弄 / 先做这个 | 新任务插队首 | `POST /v1/tasks {priority:0-255, 默认50}`，同优先级按时间 |
| 确认 | 可以 / 不行 / 换一个 | 决策点继续或改向 | `POST /v1/confirm`（已有） |

### 6.2 撤回分层状态机（说错了的三种情况）

```
说错了 ──► withdraw
  ├─ 未开始(pending)  → 从队列移除（零成本）
  ├─ 执行中(running)  → 终止 + 丢弃输出（取消传播链掐断远端）
  └─ 已完成(done)     → 标记 revoked + 清理副作用（删除生成文件/笔记/外部调用记录）
撤回完成 ──► 立即说新指令（同一会话无缝继续，不需等待）
```

- 迟到/重复 withdraw 幂等；撤回后会话不进入锁定态。
- 打断与撤回均记录日志（task_id、scope、发起方、时间）。

### 6.3 与实时语音的统一

Phase 2 WebSocket 流式识别后，「用户开口说话」本身即可作为打断信号——说话声一出现即触发 interrupt，天然解决「堵死了插不进话」。

## 7. 健壮性设计（外部调用四件套 + 回调计时器）

现状审计（2026-10-05）：仅 cloud.go 两处 http.Client Timeout（10s/15s）+ server.go 两处 WithTimeout（20s/5s）——**零散，无系统性防护**。以下为补齐设计。

### 7.1 超时分层（每层都有 deadline）

| 层 | 默认值 | 说明 |
|---|---|---|
| 传输层 | 5s（快）/ 30s（中）/ 120s（长）可配 | HTTP client 分级 timeout |
| 会话层 | 继承任务 context | deadline 向外部传播，interrupt → 自动掐断远端 |
| 步骤层 | 每 pipeline 步骤独立（如 60s） | 单步卡死不拖全局 |
| 任务层 | 总 deadline 硬上限（如 10min） | 超时强制中断 → stTimeouted/failed |

### 7.2 熔断 + 重试

- 外部服务连续失败 5 次 → 熔断 30s 快速失败；半开探活恢复，不反复打爆死服务。
- 幂等调用指数退避重试（1s→2s→4s，上限 3 次）+ 抖动。
- 非幂等调用只熔断不重试。

### 7.3 隔离（Bulkhead）

- 外部调用 goroutine 化：每个外部通道独立 worker 池 + 有界队列。
- 单点外部卡死**绝不阻塞主循环**；控制面永远不被数据面阻塞。
- 池满快速失败（返回 503 熔断语义），不排队堆积。

### 7.4 取消传播链

interrupt/cancel → context cancel → HTTP 请求取消 → 远端（平台/ASR）收到取消。打断不只本地标记，真掐断远端连接释放资源。

### 7.5 回调模式计时器（异步调用也必须兜底）

- 异步调用**发起即注册计时器**（等待窗口 30s/60s 可配）；回调未到 deadline → 降级（本地兜底）/ 幂等重试 / 报错三选一。
- 迟到回调用幂等键去重，标记过期忽略——不留无限等待。

### 7.6 状态联动与审计

- 卡住任务心跳报 busy；熔断中断后切 idle/failed → iOS 徽标可见。
- 每次外部调用记日志：调用方、目标、耗时、超时/熔断/重试事件。

## 8. 认证与租户

- Google OAuth（Web + iOS 双 client ID，PKCE）+ JWT Bearer（10h 有效，短时续期）。
- 云端模式：登录即落盘租户文件（`tenants/{sub}/tenant.json`：sub/email/tier/trial_until）；`VHS_GOOGLE_CLIENT_IDS` 逗号分隔受信列表，acceptsAud 任一命中即通过。
- 机器码即自建凭证：`/v1/devices/lookup` 免鉴权（机器码本身是凭证），register/heartbeat 需设备 token。
- 凭据分级：Google Client Secret 只进 env，不入代码/git。

## 9. 错误码与契约

统一错误码（Phase 1 落地）：

| 码 | 含义 |
|---|---|
| 400 INVALID_REQUEST | 请求体/参数非法 |
| 401 UNAUTHORIZED | 缺 token / token 非法 |
| 403 FORBIDDEN | 权限不足（非本租户资源） |
| 404 NOT_FOUND | task_id / 机器码 / 设备不存在 |
| 409 CONFLICT | 状态冲突（如 confirm 时不在等待确认态） |
| 429 RATE_LIMITED | 限流 |
| 503 SERVICE_BUSY | 外部通道熔断 / 池满 / 平台不可用 |
| 504 DEADLINE_EXCEEDED | 任务/步骤超时 |

契约文档与端点清单同步维护（`docs/` + `server` 注释）。

## 10. 演进路线

| Phase | 内容 | 状态 |
|---|---|---|
| 0 | 现状：HTTP/1.1 + JSON + SSE + 轮询 + 固定心跳，全链路跑通 | 完成 |
| 1 | **架构升级**：控制面命令集（interrupt/withdraw/priority）；自适应心跳 4 态；健壮性四件套 + 回调计时器；统一错误码/契约；生产 HTTPS | **实施中** |
| 2 | **实时语音**：WebSocket 双工（音频分片上行 + 中间结果流式回 + 控制帧）；语音延迟秒级→百毫秒级；开口即打断 | 待立项（先确认平台流式 ASR 支持：DashScope qwen） |
| 3 | **规模化**：gRPC/QUIC 评估（多机低延迟）、连接池/多路复用、多租户隔离通道 | 等规模信号再启动 |

**验收标准（Phase 1）**：
- 心跳：状态切换立即上报；云端窗口化判在线；iOS 徽标显示 state。
- 打断：长任务堵死时 interrupt 秒级生效；撤回三阶段语义正确、幂等。
- 健壮性：注入外部 1 小时阻塞 → 30s/120s 超时掐断、主循环不挂、控制面可用。
- 契约：错误码全端点一致，文档同步。

## 11. ADR 决策记录

| # | 决策 | 理由 | 否决的选项 |
|---|---|---|---|
| ADR-01 | 低频管理类保持 HTTP+JSON | 请求-响应式、低频，换协议徒增复杂度无收益 | 全量 gRPC / 全量 WebSocket |
| ADR-02 | 结果推送保持 SSE | 已达标：单向下行、断线重连、HTTP 友好 | WebSocket（上行不需要） |
| ADR-03 | 实时语音走 WebSocket 双工 | 双向、低延迟、边说边传 | 继续整段上传（延迟瓶颈）/ gRPC 流（生态成本） |
| ADR-04 | 控制面独立于数据面 | 打断/心跳不排队、立即生效，主进程不被数据面拖死 | 控制走任务队列（会被堵） |
| ADR-05 | 心跳 4 态自适应 + 状态切换立即补发 | 忙快闲慢省资源，决策态 5s 保证响应 | 固定 2min（用户不可感知在线/待决策）/ 纯事件驱动（掉线检测失效） |
| ADR-06 | online 判定窗口化（3×周期） | 慢心跳不误判离线 | 固定 last_seen 阈值（慢心跳必误判） |
| ADR-07 | 撤回三分层（pending/running/done） | 说错场景按阶段差异处理，避免一刀切 | 只 cancel（已完成产物无法撤回） |
| ADR-08 | 外部调用四件套 + 回调计时器 | 任何单点卡死不拖死主进程；异步也有兜底 | 裸 http.Client（现状，风险不可控） |
| ADR-09 | 机器码即自建凭证（lookup 免鉴权） | 自建模式无会话 JWT，机器码本身就是凭证 | 要求 JWT（自建无法登录） |
| ADR-10 | 云道只做目录+应急转发，不常驻中转 | 避免云端成为带宽/计算瓶颈 | 云道常驻代理（资源消耗大） |

## 12. 实施顺序（Phase 1）

1. **P1-a 服务端健壮性基础**：统一外部调用 client（分级 timeout）、熔断+退避重试、bulkhead worker 池、任务步骤级超时、任务总 deadline。
2. **P1-b 控制面命令集**：`/v1/interrupt`、`/v1/withdraw`、`/v1/tasks priority`。
3. **P1-c 自适应心跳**：Harness 状态机 + 事件驱动补发；服务端窗口化在线判定 + lookup 返回 state。
4. **P1-d iOS 联动**：意图识别（停/撤/优先/确认）、状态徽标、withdraw/interrupt 按钮。
5. **P1-e 契约与文档**：统一错误码、端点清单同步、本文档验收闭环。

每步：`./run test` → 真机/curl 验证 → commit push。
