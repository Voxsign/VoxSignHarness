## 一、Claude Code 新方案（原文核心，未改动）

### 1. 最大风险 & 第一周验证
最大风险不是技术，是**范围自我欺骗**——用"底座/生长/契约"叠层术语，把一个"语音敲命令"的小工具包装成需要持续维护的平台。方法论自洽 ≠ 需求已验证。
**第一周不该写更多模型层代码，该做一件事**：用现有 demo 真实跑满 20 个你自己会做的任务，记下哪几个语音确实比打字/鼠标快、哪几个因"确认摩擦"让你想切回键盘。若 20 个里有 15 个中途放弃语音，方向就是错的，架构再漂亮也没用。

### 2. 确认策略引擎（规则简单到能背下来）
- 分级只用两个信号：**操作是否可逆**（删除/发送/写外部系统 = 不可逆）、**意图识别置信度**（词典纠错后是否命中已知实体）
- 优先级：**不可逆 > 低置信度 > 其余**。不可逆操作永远强确认——硬规则，不能被"学习"掉
- 可逆 + 高置信：自动执行 + 写回执，不问
- 可逆 + 低置信：自动执行但标记"待抽查"，下次打开轨迹时高亮——**异步确认，不打断当下**
- "不再问"按 **(意图类型, 目标路径/实体, 权限范围) 三元组缓存**——换文件夹/项目就重新问（防"永久真相"陷阱，V0 必须做）
- 抽样复核用**每日摘要**："今天自动执行 N 条，随机抽 3 条请确认"，不做实时打断

### 3. 三 OPC 防自我强化：优先级排序（不要三个角色同时上）
1. **硬闸门先于角色**——"回执≠验证"第一优先：执行后必须有独立于执行路径的校验动作（读文件系统实际状态并 diff 预期，**不读执行器自报的 status**）
2. **REVIEWER 独立读原始证据**（原始轨迹+现场状态），有否决权、可要求重执行
3. **单工对比实验**：V0 验收时做——3 个真实任务键盘鼠标单人计时 vs 三 OPC 流程计时；若三 OPC 更慢，说明流程是付费仪式感，先砍流程不砍目标

### 4. 自举临界点（不靠能力清单，靠频率）
连续两周、每周用 1.0 处理真实任务 ≥10 个，且"记一条→下次不再问"命中率 ≥50% 时，才有资格谈"用 1.0 迭代 1.0 代码本身"。**在此之前 2.0 不存在，只有 1.0 的 bug 修复**。过早谈 2.0 = "为了高效先造了个永久维护项目"。

### 5. V0 新方案（两周）
**范围收紧为一句话**：`语音 → 意图 → 风险分级 → 执行 → 本地回执 → 轨迹可查`。
- 砍：生长回路状态机、"三层认知/契约/工具"的显性工程实现——**作为设计哲学留着，但 V0 代码里不出现对应抽象类/状态机，用最笨的 if-else + 一个 JSONL 文件实现**
- 保留：ASR+词典纠错、意图解析→JSON、执行器、回执+JSONL 轨迹（均已有）
- 新增：**风险分级器**（<100 行，即第 2 点规则）、**独立校验器**（执行后读实际状态对比预期，不读执行器自报）、**每日摘要**（抽样复核用）
- 该砍：get_time 等无风险小工具、三 OPC 团队的角色命名层、任何"学习用户偏好"的自适应模型（V0 用固定规则，不做学习，避免归因复杂化）
- **验收指标换成可感知**：连续 5 天每天 ≥4 个真实任务语音完成，且**没有一次**因"不信任结果"手动重查执行器已自称完成的操作；外加单工对比：3 个任务里至少 2 个语音更快或等快，否则 V0 不算通过
- 两周内做不完全部时，**先砍每日摘要**——校验器和分级器不能砍，它们是防"回执代替验证"陷阱的唯一硬闸门

## 二、MainAgent 推进建议（整合四轮评审后的执行顺序）

1. **采纳本稿为 V0 定稿**：范围=一句话闭环；哲学留作设计文档，代码不建抽象
2. **第一步（本周，不写新代码）**：在现有 M1 demo 上跑 20 个真实任务，做"语音 vs 键盘"方向验证；结果决定 V0 是否继续（≥15 个放弃语音 → 停止重设计方向）
3. **V0 开发顺序（M2 放行）**：风险分级器 → 独立校验器 → 三元组缓存 → 每日摘要（可后补）→ 单工对比实验（验收门槛）
4. **三 OPC 团队**：暂不建角色层；等 1.0 频率达标（每周 ≥10 真实任务 + 命中率 ≥50%）再启动，且从"硬闸门 + REVIEWER 独立"做起
5. **2.0 自举**：与 4 同门槛，临界点由频率数据决定，不靠清单
