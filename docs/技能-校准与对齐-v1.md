# 技能：校准与对齐（v1）

> **Peter 2026-10-03**
> 「这实际上在真正的开始去执行这种普通的开发和测试之前，
> **最新做的是要校准** —— 尤其是对**大的意图架构**、他的这个**框架**，
> 以及**数据怎么流转的大逻辑**进行校准。
> **如果这些不校准，其实我们现在做了很多东西，其实意义不大。**
> 所以我们要把**校准先于测试、先于改**。所以我觉得校准**甚至可以在一边干的过程一边校准**。
> 所以把这个能力现在记下来作为**一个核心的能力**。
> 而且未来这也作为你做 harness 的一个很重要的问题 —— **harness 有个技能就要校准**。
> **校准与对齐**，好，我增加了这个技能，要把这个很重要弄进去。」

---

## 0. 一句话

> **在动手之前和之中，反复确认「我以为的那个东西」和「实际的那个东西」是同一个。**
>
> **校准不是测试的前置步骤 —— 它是测试和改的**前提**。**
> **校准没做，后面做的一切都可能是在错的参考系里做对的功。**

## 1. 校准什么：三个对象（Peter 指名的）

| # | 对象 | 要确认的问题 | 今天真实的反例 |
|---|---|---|---|
| **C-1** | **大意图架构** | 「我要交付的，是不是你以为你要的」 | 我推了 40 个污染提交上 main —— **我推的不是我以为的那个** |
| **C-2** | **框架** | 「这个框架的实际形状，是不是我以为的形状」 | 我以为 `~/vhs-live` 是主仓库；实际机器上有 **≥4 个副本 + 2 个常驻进程** |
| **C-3** | **数据怎么流转的大逻辑** | 「数据从哪来、到哪去、谁改它」 | `git config` 不带 `--local` 会**上溯父仓库** ⇒ 测试写了主仓库，覆盖了用户的 git 身份 |

**⇒ 三个对象都不是"细节" —— 都是**结构性**的。所以校准必须发生在**结构性动作之前**。**

## 2. 为什么校准必须先于测试（今天的实证）

**今天一天内的账：**

```
错误次数：我 6 次（4 个机制误判 + 1 个候选红 + 1 次推错 tip）· 实现方 1 次
被否的候选：7 个（对 `core.bare` 一个现象）
未归因项：  2 个（core.bare 写入者 · 钩子里的 gate 为何失败）
真正闭环的机制：1 个
```

**而这 6 次错误，形状只有两个：**

```
① **我读的东西不是我以为的那个**（读数错）
     · `d["refused"]` 读顶层 ⇒ None ⇒ 差点报"接口没返回"
     · grep 到 `git init` 就断定"测试在 cwd 操作" ⇒ 没读它上面的 `cmd.Dir`
     · 在错误的 worktree 上跑 gate ⇒ 整棵代码树都不是我以为的那棵
② **我改的东西改变了我要观测的东西**（观察者效应）
     · 测试写主仓库 .git/config ⇒ 用户 git 身份被覆盖
     · gate 跑测试 ⇒ 改了它要验证的环境
     · push 触发 gate ⇒ HEAD 被推走 ⇒ 我推错了东西
```

**⇒ 两条都是校准失败。而它们的代价是**五轮 CI 没人知道为什么红**。**

## 3. 校准怎么做：今天实证过的手段（按证据强度排）

### ★★★ 同一把尺子：payload 逐字节重放

```
**不是"同一个意思的输入"，是"同一串字节"。**
落法：payload 存成 `testdata/replay/<卡片号>.json` **进仓库**
今天的实证：测试卡片说 considered=18，我实测 considered=2
           ⇒ **我们测的不是同一个输入** ⇒ 三层"无变化"只能算"在我的输入下无变化"
```

### ★★★ 同一条命令内前后对比

```
**最强形式的证据** —— 它不需要你知道机制，就能证明"这件事发生了"。
今天的实证：
  git push（同一条命令内）：推前 bare=false → 推后 bare=true
  ⇒ ① 现象 ✅（最硬）· 而 ② 路径 ⚠️ · ③ 反证 ❌ ⇒ **仍只能叫"候选解释"**
```

### ★★ 在「别的参考系」里验证

```
**"本地绿"不是证据，除非本地与被验证环境同构。**
今天的实证（两次都立刻见效）：
  · `GIT_CONFIG_GLOBAL=/dev/null`（抹掉全局身份，模拟 CI runner）
    ⇒ 抓到 `fatal: empty ident name`
  · **浅克隆 `--depth 1`**（模拟"真值基线不可达"）
    ⇒ 抓到 SM-4 的 FAIL 路径
⇒ 而 CI（**唯一异源验证者**）三分钟内抓出了本地五轮看不到的东西。
```

### ★★ 机制闭环三条（缺一不可）

```
① **现象**可复现（有命令、有前后对比）
② **路径**可指名（具体哪一行/哪个变量导致现象）
③ **反证**成立（把那条路径改掉 ⇒ **现象消失**）

⇒ 缺一条，只能说"候选解释"，**不许说机制、不许立判据、不许写进文档当事实**。
今天的实证：我给过 4 个"机制"，**4 个都不满足三条** ⇒ 全部撤回。
```

### ★★ 回读远端，不信本地

```
**推之前**：被推的 sha 必须来自 `git rev-parse <显式ref>`，**不用 `HEAD`**
          （被污染的工作树里，HEAD 会在"读取"与"使用"之间变化）
**推之后**：必须断言 `远端 tip == 我显式指定的那个 sha`
今天的实证：这条纪律**在事故发生时就生效了** —— 我推了 40 个污染提交，**同一条命令内就发现并恢复**。
```

## 4. 校准的产物：**参考系声明**

**每次动手前，用一句话写清：**

```
【参考系声明】
  我在哪      : <绝对路径 / worktree / clone>
  它是哪个仓库 : <remote url + 我读到的 sha>
  谁可能在改它 : <已知的其它 writer：进程 / agent / 测试 / hook>
  我的判据依赖 : <这个参考系里必须有什么>（如"全局 git 身份"、"某个 commit 可达"）
  不成立时     : <SKIP 并显式报告 / 换参考系 / 停止>
```

**今天的实证**：SM-4 判据依赖"真值基线 commit 可达" —— **它没声明这个依赖**，
于是本地永远绿、CI 永远红，**而它自己不说原因**。⇒ 红了五轮。

**⇒ 这就是校准技能的**核心产物**：把隐含的参考系依赖**写成文字**。**

## 5. 校准与「大石头」（`tasks/VHS-CALIB-001`）的关系

```
CA-1 参考系分离        = 校准的**基础设施**（跑校验不得改变被校验对象）
CA-2 参考系一致性      = 校准的**声明**（校验须说清它跑在哪个参考系）
CA-3 归因可分          = 校准的**前提**（能区分"产品坏了"和"校验把它弄坏了"）
CA-4 单跑 vs 全量一致   = 校准的**自检**
CA-5 判据不得静默失效   = 校准的**底线**
CA-6 绿须附证据        = 校准的**留痕**
CA-7 阻断等级匹配       = 校准的**权重**

⇒ **「校准」技能 = 这七条的**可执行形态**；CA-1..CA-7 = 它的判据。**
```

**⚠️ 而 `VHS-CALIB-001` 的七条 **一条都还没落地**（如实）。**

## 6. 反面清单（明令禁止 —— 全部是今天真实犯过的）

```
❌ **"本地绿"就报绿** —— 除非本地与被验证环境同构
❌ **用一个片段推断整体** —— 读一个 grep 结果就下结论（今天 3 次）
❌ **只凭"现象成立"就宣布机制** —— 缺②路径和③反证（今天 4 次）
❌ **在未归因的东西上继续堆候选** —— 今天是第 7 个才停
❌ **相信本地 HEAD** —— 它会在"读取"与"使用"之间变
❌ **假设"只有一个仓库/一个进程/一个 writer"** —— 机器上有 ≥4 个副本
❌ **把"我观察到了"说成"我知道为什么"**
❌ **把 SKIP 当通过**（`docs/LHT-0002` 已有原则）
```
