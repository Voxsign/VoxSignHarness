### 1.1 A3：fail-open / unknown —— 两处真实缺陷

**先说做对的部分（可核）**：

| 场景 | 代码 | 行为 |
|---|---|---|
| HTTP 非 200 / 网络错 | `gateway_impl.go:54-56`、`49-51` | 返回 error → 上层转 `unknown` + `Note` |
| JSON 解析失败 | `gateway_impl.go:86-88`、`128-130` | `Status=unknown`，`Note="解析失败（不是「没有」）…"` |
| summary 失败时的依赖列表 | `gateway_impl.go:137-146` | **返回 1 条 `unknown` 依赖，不是空列表** ✅ |
| `WhoHandles` 未命中 | `gateway_impl.go:281-287` | 返回 `unknown`，措辞「未匹配到（这不代表该对象没有）」 ✅ |
| 注册表缺失/坏格式 | `gateway_impl.go:214-226` | 返回 error、**不改变已有缓存** ✅ |
| 默认门禁覆盖 | `world/aiops_test.go:44-71`（**不带 tag，随 `go test ./...` 常跑**） | 500 / 垃圾 JSON / 404 三种都断言 `unknown` + `Note` 非空 ✅ **可证伪** |

**缺陷 A3-1：单台机器解析失败被静默丢弃 —— 正是 A3 禁的「静默当没有」**

```go
// world/gateway_impl.go:96-101
for _, k := range keys {
    var h Host
    if err := json.Unmarshal(raw.Hosts[k], &h); err != nil {
        continue // 单台机器解析失败不拖垮整份清单（元数据降级）
    }
```
- 某台 host 的 JSON 解不出来 → 该 host **从 `Summary.Hosts` 里消失**，
  `Summary.Status` 仍是 `ok`，`Summary.Note` **仍然为空**。
- 下游 `Dependencies()`（`gateway_impl.go:147-157`）按 `Hosts` 逐条生成依赖 →
  **那台机器在「我依赖谁」里变成不存在**。
- 这正是指令 §3.2 **A3**「读失败必须 fail-open 且标 `unknown`，**不得静默当「没有」**」的字面违反。
- 修法：解析失败时保留一条该 key 的 `unknown` 记录（或把 `Summary.Status` 降级并在 `Note` 里列出失败 key）。

**缺陷 A3-2：HTTP 200 + 载荷内 `ok:false` 被当成成功**

指令 §1.2 / §1.3 明确 `ok` 是**两份载荷的字段**（`{"ok": true, "ts": …, "zone": "inner", "hosts": {…}}`）。
但实现**根本没有解码 `ok`**：

```go
// world/gateway_impl.go:81-89  —— raw 结构里没有 ok
var raw struct {
    TS    string                     `json:"ts"`
    Zone  string                     `json:"zone"`
    Hosts map[string]json.RawMessage `json:"hosts"`
}
...
out := Summary{Status: StatusOK, Source: src, Zone: raw.Zone, TS: raw.TS}
```
```go
// world/gateway_impl.go:123-131  —— 同样没有 ok
var raw struct {
    Status     string   `json:"status"`
    CurrentTag string   `json:"current_tag"`
    Ledger     []Ledger `json:"ledger"`
}
...
return CICD{Status: StatusOK, Source: src, CurrentTag: raw.CurrentTag, Ledger: raw.Ledger}
```

后果分两档：

| 路径 | 后果 | 严重度 |
|---|---|---|
| `Summary` | 200+`ok:false` → `Status=ok`、`Hosts` 空。**侥幸**：`Dependencies()` 有 `len(sum.Hosts) == 0` 兜底（`gateway_impl.go:137`），会转 `unknown` | 中 |
| `CICD` | 200+`ok:false` → `Status=ok`、`CurrentTag=""`、`Ledger=nil`。**没有任何兜底** | **高** |

`CICD` 挂到 `state`（指令 §3.1 表格：「`state`（我在哪）← `cicd.current_tag` / `ledger`」）→
**一份取不到数据的台账会以 `ok` + 空值进入「我在哪」，读起来就是「没有部署记录」**。
这就是 A3 说的「静默当没有」。

另有两点，作为**观察**记录（不单独判缺陷）：
- **失败结果被缓存**：`gateway_impl.go:71-73` 把 `unknown` 结果也写进 `g.cache.summary` →
  一次瞬时网络抖动会被固化到 `ClearCache()` 为止（A3 未要求重试，故不判违规，但应显式写进设计说明）。
- **`maxBody = 4<<20` 截断**（`gateway_impl.go:30,57`）：超限会截断成非法 JSON → 走 `unknown` 路径 ✅ 安全方向正确。

### 1.2 A4：读 200 ≠ 写权限 —— 语义通过，但**判据不可证伪**

**语义上确实是只读的（可核）**：
- `Grants()` 恒空：`gateway_impl.go:174` `func (g *Gateway) Grants(context.Context) []string { return nil }`
- 依赖的 `Kind` 只取 `host` / `gateway` / `service`：`gateway_impl.go:154,159,260,275`；
  类型注释 `aiops.go:86` 明确「**永不**是 capability/grant」
- `Boundaries()` 恒含 `no-deploy` 与 `gateway-read-only`：`gateway_impl.go:166-171`
- 全包**只有 GET**：`gateway_impl.go:45` `http.NewRequestWithContext(ctx, http.MethodGet, …)`，无写方法

**但守护 A4 的那条判据是空转的（这条比缺陷本身更值得处理）**：

```go
// world/ext_criteria_test.go:135-137
if grants := g.Grants(ctx); len(grants) != 0 {
    t.Errorf("[EXT-07] 读到 200 却产生了权限授予: %v", grants)
}
```
`Grants()` 的**桩与实现是同一行**（下面的命令输出是实际粘贴，不是重述）：

```bash
$ git show cf45bf7:world/aiops.go | grep -n "Grants"
157:// Grants 返回"本机因网关读到的内容而获得的能力" —— 恒为空（A4：读不产生权限）。
158:func (g *Gateway) Grants(ctx context.Context) []string { return nil }
$ git show 6701d4d:world/gateway_impl.go | grep -n "Grants"
173:// Grants 恒为空：网关读到的任何内容都不产生本机能力（A4）。
174:func (g *Gateway) Grants(context.Context) []string { return nil }
```
除参数名（`ctx context.Context` → `context.Context`）外，**函数体逐字相同——都是 `return nil`**。
**桩和实现逐字相同。** 所以：
1. 这条断言在 `cf45bf7` **从未红过**（不满足本项目「判据先红」的要求）；
2. 今天它**也不可能失败**——没有任何输入能让恒空函数返回非空；
3. 「读 200 不得被解释成写权限」这条 **A4 硬要求，实际上没有任何判据在守它**。

> §1.1 里我表扬了「判据先红做得好」，那是针对 EXT-05/06/08 ——
> 它们在 `cf45bf7` 是**真桩返回零值、断言真失败**（`git show cf45bf7:world/aiops.go:146-168` 的 8 个方法全返回零值）。
> **EXT-07 的 `Grants` 那一半是例外。**

**补强建议**：A4 应该由「**输入侧**」守，而不是「输出侧」。
例如：注入一份 `hosts[*]` 里包含 `"can_deploy": true` / `"role":"root"` 之类**暗示权限**的载荷，
断言生成出的 `Dependency` 里**不出现任何 capability/grant 语义**、且 `Grants()` 仍为空。
只有让"读到的东西"变化，才能证明"读到的内容不影响授权"。

**补充观察（不作为缺陷）**：`world/` 目前**没有被任何生产路径引用**——
全仓只有 `eval/projmodel/gen/main.go:28` import 它。所以 A4 今天不可能被真实违反，
**不是因为守住了，而是因为这条路径还没接进产品**。这一点请在判定时一并计入（见 §6 U5）。

### 1.3 缓存：元数据-only ✅ / 「缓存目录」⚠️

- 可重建且一致：`world/ext_criteria_test.go:155-180` 断言
  「第二次不打网络（hits 不变）」→ `ClearCache` → 「重新打网络」→ `DeepEqual(first, rebuilt)` ✅ **可证伪**

**不符点**：指令 **EXT-08** 的字面要求是
> 「**缓存目录**可删可重建；删掉后重新抓取结果一致（A1）」

而实现里**没有任何缓存目录**——缓存是纯内存的，`ClearCache()` 是 API 而非文件系统操作。
- 与 §3.2 **A1**（「只缓存元数据…缓存**可重建可清除**」，未提目录）不冲突；
- 与 **EXT-08**（明写「缓存目录」）冲突。
- **指令自身内部就不一致**（§3.2 说缓冲、§3.3 说目录），所以这**不能全算实现的账**；
  但结果是：**EXT-08 被按较松的那一版实现了**，且没有任何文档记录这次口径替换。

**判定**：算「修订」项。请规格方明确 EXT-08 到底要不要落盘缓存；若不要，把 §3.3 的「目录」改成「缓存」。
