# 意图层：模型兜底的边界 + 「找谁」归类落地（C1–C5）

## 1. ⚠️ 登记：模型兜底**不能修高置信误判**（隐性缺口，显式化）

兜底只在**本地低置信**（`confidence < 0.70`）时触发。但白名单分类器的危险恰恰相反：

> **它会在高置信下判错** —— 例如「如果测试通过就提交」当年就是"高置信地执行了"。
> 这种情况**永远不会进入兜底分支**，因此**兜底补不了它**。

**这不是本层能解决的**，登记在此以免变成隐性缺口。已知的候选机制（未实现、未评估）：
- 高危动作强制降置信（irreversible → 强制 `need_disambiguate`）；
- 二次确认 / 因果校验；
- 与 RV-3 域门禁联动。

**责任边界**：本层只保证"低置信会去问模型、失败会降级"；**不保证"高置信一定对"**。

## 2. 找谁归类（VHS-CLASSIFY-001 裁决落地）

| 情形 | owner 前缀 | 说明 |
|---|---|---|
| 不可逆 / 生产影响（部署、发布、删除） | **`人：` 在前**，`网关：` 在后 | 授权是前置；能力是后置 |
| 对外产生输出（推远端、上架、邮件、上传） | `网关：` | U2 |
| 判断类（判断/评估） | `网关：`（请求类型=模型） | U3：模型中心已并入网关，不单列 |
| 只读 / 本地 | 无缺口 | 自己做 |

**同一目标可同时有两类缺口**（C2），且**授权在前**。实测：

```
"帮我部署到生产服务器" →
  ["人：deploy 属不可逆/生产影响动作，须人工授权（授权是前置）",
   "网关：且当前无 deploy 能力（请求类型=工具；域别名不是工具契约）"]
"把这个仓库推到 GitHub 远端分支" →
  ["网关：且当前无 push 能力（请求类型=工具；域别名不是工具契约）"]
"判断一下这份格式有没有歧义" →
  ["网关：且当前无 model-judgment 能力（请求类型=模型；域别名不是工具契约）"]
```

**为什么两个都写**：只报"缺能力"→ 用户以为加工具就行（忽略授权才是本质）；
只报"缺授权"→ 用户以为能力已有。两者并写并排序，既不误导也不隐瞒（C4：不可逆必须有人工指向）。

**与判据的关系**：测试方 `SW-1/SW-2` 只要求"期望 owner 存在"、不排斥额外 owner，
因此 C2 的双条目与其断言相容（已实测 `vhsplan` 全绿）；若其后续收紧为互斥，**由测试方升版**。
