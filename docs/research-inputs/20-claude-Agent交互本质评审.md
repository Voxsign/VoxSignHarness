1) **多角色/多 Agent 组织方式**(三种最强范式)
- **单会话内角色切换**(Grok 式):同一上下文窗口内挂载不同"人格/技能包",用户用 @或下拉切换,底层记忆/上下文不丢失——代价是角色边界易模糊,用户常搞不清"现在谁在说话"。
- **并行 Agent 面板**(Claude Code subagent、Devin 式):主 Agent 做编排,子 Agent 后台跑,结果以"卡片/通知"形式汇总回主线,用户只跟主 Agent 对话——本质是把多 Agent 协作折叠成单一交互入口,可追溯但不打断主流程。
- **显式状态机/工作台视图**(如 Operator、多步 workflow 工具):把角色切换做成可视化阶段条(规划→执行→校验),用户始终看得到"当前在哪个阶段、谁负责"。三者共同点:**折叠复杂度,但保留可展开的追溯路径**。

2) **五个本质原则**
- 意图澄清(ambiguity → clarify before acting)
- 状态可见(用户任何时候都知道 Agent 在干什么、到哪一步)
- 可打断/可撤销(执行中可随时叫停,且动作可逆)
- 确认关键节点(风险操作前显式 checkpoint)
- 信任校准(让用户对 Agent 能力边界有准确预期,不多不少)
根基是**状态可见**——没有可见性,打断、确认、信任都无从谈起;用户必须先"看见"才能"决策"。

3) **VoxSign Go 式单人语音控电脑——最优交互架构**
核心矛盾:语音是线性、流式、不可一目了然的,而控制电脑是高风险、需要刹车点的。最优解是**"流式播报 + 离散刹车点"分层**:
- 底层按你的 harness 分段(意图→域→风险评估→确认→执行→verify→回执→撤销→归因)天然就是一串可打断的状态机,每段都该有一句话语音播报+对应文字浮层。
- 多角色折叠:让"风险评估/确认"这类判断性角色收进一个固定提示词模板(四行回执本身就是折叠产物),执行类角色(各域 agent)保持后台跑、仅在 verify 失败或高风险时才"弹出"打断用户。
- 可打断流式:语音侧用"确认词可随时打断当前播报"(barge-in),而非等播报完才能喊停——这是语音 UX 的生命线。
- 一屏刹车点:把"风险→确认"这一步做成**唯一的强制可视化节点**(哪怕手机锁屏也要有一个清晰的 Yes/No/撤销三选项),其余步骤都可以静默流过。四行回执就是这个刹车点的"收据",撤销权限应至少保留到下一次高风险操作前。

4) **"感觉极爽"的设计**
三者同时成立才爽,缺一个就是"快但慌"或"稳但慢":
- **速度**:默认静默执行低风险步骤,不为每步都打断(减少无谓确认);
- **掌控感**:高风险点有且只有一个清晰、低认知负荷的刹车(不是十个选项,是是/否/改);
- **不犯错**:verify 环节对用户不可见但对系统强制——用户感受到的是"它从不出错",背后是 Agent 自己在拦截。
本质是**把确认成本压缩到风险真正存在的那一刻**,其余时间用户感觉是被"预判"而非被"询问"。
