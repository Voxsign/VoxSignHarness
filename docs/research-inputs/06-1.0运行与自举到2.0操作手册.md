# VoxSign Harness 1.0 运行说明 + 自举到 2.0 操作手册

- 版本：1.0-stable 使用手册（dogfooding 版）｜日期：2026-10-01
- 适用前提：M0–M3 全过、两周窄闭环验收通过（30 样例 ≥27、幂等、人工操作时间降 30%）、自然生长若干轮后的稳定态。
- 本文不是设计方案，是照着敲就能跑的操作手册。所有命令假设二进制名 `voxsign`、配置在 `~/.voicesign/harness.json`、轨迹在 `~/.voicesign/trajectory-YYYYMMDD.jsonl`。

---

## A. 1.0 完成态能力清单

每条能力 = 触发条件 / 调用方式 / 产物 / 证据落点（轨迹条目 kind）。

| # | 能力 | 触发条件 | 调用方式 | 产物 | 证据落点 |
|---|------|----------|----------|------|----------|
| C1 | 记一条闭环 notes.add@1.0 | 说「记一条/记一下/存一下…」+ 内容 | `voxsign run "记一条，美墅报价待复核预算"` 或 REPL 直接说 | note_id、SQLite 记录、幂等回执 | `input_raw`→`input_correct`→`intent`→`actions`→`receipts`→`final` |
| C2 | 列事项 notes.list@1.0 | 说「列一下/最近记了什么/这个项目的事项」 | `voxsign run "列一下当前项目最近记的"` | 列表（note_id+text+ts） | 同上，receipts 为数组 |
| C3 | 词典双向复用 | ASR 原文含已确认变体（美墅/Mansour） | 自动（无需调用）；回写用 `voxsign dict add --term Mansour --variant 美墅 --project p1` | `memory/dictionary.json` 新条目 | `input_correct.corrections[]`、回写轮 `receipts` |
| C4 | 回执幂等 | 同一 idempotency_key 重复提交 | harness 自动；重复时返回原回执不新写 | `duplicate:true` 回执 | `receipts` 中 `idempotency_key` 命中即查旧记录 |
| C5 | 归因六格 | 任意一次 run 失败/回问/人工纠正后 | `voxsign attrib <request_id>` | 归因 JSON（六格之一）+ 缺口登记 | 新写 `attribution` 条目 + `gap` 条目 |
| C6 | 契约只增不改 | 新增工具时 | 新文件 `contracts/tools/<name>@<ver>.json`，旧文件一字节不动 | 新 schema；旧 prompt 前缀不变 | `actions` 条中 `tool_contract_hash` 与历史一致 |
| C7 | 轨迹重放 | 调试一次 run | `voxsign replay <request_id>` | 打印该 request_id 全链路 JSONL | 按 request_id 过滤当日轨迹文件 |
| C8 | 模型路由 | 每次 run 自动 | 显式覆盖：`VHS_ROUTE=complex VHS_PROVIDER=strong voxsign run "..."` | 实际端点/模型写进回执 | `model` 条含 provider/model/prompt_hash/usage/latency_ms |
| C9 | 生长回路状态机 | Use 中发现缺能力 | `voxsign gaps list` / `voxsign gaps show <gap_id>` | 缺口单：原始请求/期望/为何不足/临时成本 | `gap` 条目 + 状态机字段 `stage: Use→Gap→…` |
| C10 | 时间直通 get_time | 说「几点/今天几号」 | `voxsign run "现在几点"` | 本地时间字符串，零 LLM | `intent{intent:TIME,conf:0.95}`，无 `model` 条 |

## B. 能力 × 阶段矩阵（2.0 开发六阶段怎么调用 1.0）

六阶段：想法 → 契约 → 编码 → 测试 → 回归 → 部署。四能力：记一条闭环 / 归因六格 / 契约只增不改 / 轨迹重放。

| 阶段 | 记一条闭环 | 归因六格 | 契约只增不改 | 轨迹重放 |
|------|-----------|----------|--------------|----------|
| ①想法 | `voxsign run "记一条：想做 budget_check，因为每月手工核对 15 分钟"` → note_id 落账 | 用 `voxsign attrib` 把现有失败样例归到「契约不足」格，避免又归成「模型错」 | — | `voxsign replay <旧失败 request_id>` 把真实痛点原话翻出来当需求依据 |
| ②契约 | 把契约要点记一条：`"budget_check@1.0 入参 project_id/月，出参 已用/剩余/预算"` | Triage 阶段归因：缺口属于「契约缺」还是「上下文缺」——决定写契约还是写词典 | 新文件 `contracts/tools/budget_check@1.0.json`；`notes.add@1.0.json` 不动 | replay 出 receipts 结构，照着定 budget_check 的回执 schema |
| ③编码 | 编码中遇问题随手 `voxsign run "记一条：budget_check 需读 ogsm.yaml 预算行"` | 编码报错 → `voxsign attrib <req>` 归到「执行」或「外部」格（如 ogsm.yaml 字段名变了=外部变化） | 实现只动 `internal/tools/budget_check.go` + 注册；旧工具代码零改动 | 跑 `VHS_PROVIDER=mock voxsign run "..."` 录一条 mock 轨迹做基准 |
| ④测试 | 测试用例记一条进 `eval/cases.jsonl`：输入+预期回执 | 每条失败用例当场 attrib，六格选一格，不许写「模型不好」 | 测试只断言新契约字段，不断言旧契约被改 | 用 `voxsign replay` 旧 30 条验收样例，确认它们仍走旧路径 |
| ⑤回归 | 回归发现某条旧样例回问变了 → `voxsign run "记一条回归异常：req-xxx 行为漂移"` | 漂移必归因：是契约加字段破了兼容？还是 prompt 前缀变了？ | `prompt_hash` 与 M3 基线对比——不一致就是动了旧契约 | `voxsign replay` 漂移样例，逐条目对比旧轨迹找差异行 |
| ⑥部署 | 部署决定记一条：激活范围（哪个项目先 Pilot） | Benefit 阶段归因：新工具到底省没省人工注意力分钟数 | Register 先 `active:false`；Pilot 后才翻 `active:true`；旧版本归档不删 | 部署后 replay 首轮真实 run，确认全链路落盘完整 |

## C. 典型工作流逐步推演：新增 `budget_check@1.0`

走一遍生长回路 Use→Gap→Triage→Draft→Verify→Register→Pilot→Learn→Benefit。

**① Use（真实使用中撞墙）**
- 人工原话：「帮我核对一下这个月预算还剩多少。」
- harness：input 五级跑完 → intent=INFO、conf 0.4 → 路由 complex→strong 模型 → 模型 ActionPlan 找不到可用工具（能力目录里没有 budget_check）→ receipts 返回 `error:no_such_tool`。
- 轨迹：`intent`（INFO）→`actions`（空 plan）→`receipts`（`{ok:false,reason:"no_such_tool"}`）→`final`（"我还没有预算核对能力"）。
- 回执样例：
```json
{"request_id":"req-1042","tool":null,"ok":false,"reason":"no_such_tool","registered_tools":["notes.add@1.0","notes.list@1.0","get_time"]}
```

**② Gap（harness 自动登记缺口）**
- 人工动作：什么都不用做。
- harness：`final` 判定为「能力缺口」→ 自动写 `gap` 条目，含原始请求、期望结果、现有能力为何不足（notes.add 只写不算）、临时处理成本（你手工翻 ogsm.yaml 约 15 分钟）。
- 落盘：`gap{gap_id:g-7, request_id:req-1042, stage:Gap, raw:"帮我核对一下这个月预算还剩多少"}`。

**③ Triage（归因+价值筛选，人工一句话拍板）**
- 人工原话：「这个缺口归到契约不足，值得做——每月都要核。」
- harness：`voxsign attrib req-1042` → 六格选「契约不足」；`voxsign gaps show g-7` 看五把尺子（复用证据：每月用→过；净节省：15min→2min→过）。
- 轨迹：`attribution{gap_id:g-7, cell:"contract", verdict:"worth_new_tool"}`。

**④ Draft（契约草案，人工审一眼）**
- harness 侧：模型起草 `contracts/tools/budget_check@1.0.json`（入参 project_id/month，出参 budget_used/remaining/cap，失败语义：ogsm.yaml 缺预算字段→`error:budget_unknown` 不猜数）。
- 人工动作：读一遍草案，确认「预算未知时必须回问、禁止从'报价'推断」写进失败语义。改完保存。
- 轨迹：无（这是文件操作，不经过 run 管线；但草案变更由 git 记录）。

**⑤ Verify（实现+测试，全部人工在普通开发流程里做）**
- 人工：写 `internal/tools/budget_check.go`（只读 ogsm.yaml，不写任何外部副作用）+ `budget_check_test.go` + 在 `internal/tools/registry.go` 注册。
- 验收：`go test ./internal/tools/ -run BudgetCheck -v` 全绿；30 条封存旧样例重跑 ≥27 仍过。
- harness 侧：`VHS_PROVIDER=mock voxsign run "核对 p1 本月预算"` → mock 回执符合新 schema。

**⑥ Register（注册但暂不激活）**
- 人工：在 `~/.voicesign/harness.json` 的 `tools` 节加 `"budget_check@1.0": {"active":false}`。
- harness：启动渲染工具契约块时，`active:false` 的契约**不进 prompt**——模型看不到它，只注册了 schema 供测试。
- 回执：`voxsign tools list` 里它显示 `status:registered-inactive`。

**⑦ Pilot（限定任务激活）**
- 人工：改 `active:true`，但 `pilot_projects:["p1"]`——只在 p1 项目下可用。
- harness：`voxsign run "核对 p1 本月预算"` → 模型这次在能力目录里看到 budget_check@1.0 → ActionPlan 调用 → receipts：
```json
{"request_id":"req-1051","tool":"budget_check@1.0","ok":true,"project_id":"p1","month":"2026-10","cap":50000,"used":31200,"remaining":18800}
```
- 轨迹：完整 `input_raw→…→receipts→final`，且 `tool_contract_hash` 与 notes.add 时代一致（只增不改生效）。

**⑧ Learn（认知目录更新）**
- 人工：往 `cognition/lexicon.seed.yaml` 或能力示例里加一条：「'核对预算/还剩多少预算' → budget_check@1.0，不是 notes.list」。
- harness：下次首条 user 消息前缀注入新示例。

**⑨ Benefit（验证复用价值）**
- 人工：记一笔对比——「手工核对 15min vs harness 2min，省 13min/次」。
- harness：北极星指标落账（每次合格结果的人工注意力分钟数）。若 3 次 Pilot 内无越权/错误副作用 → 全项目激活；否则 Revise 回 Triage。

## D. 一个完整可运行示例会话（REPL 逐轮）

启动：`voxsign repl`。提示符 `voxsign>`。

```
voxsign> 记一条，美墅报价待复核预算
[轮1·低置信回问轮]
input_raw:  "记一条，美墅报价待复核预算"        → trajectory: input_raw
input_correct: corrections:[{from:"美墅",to:"Mansour",rule:"dict_candidate"}]
intent: {intent:"NOTES_ADD", slots:{text:"美墅报价待复核预算"},
         confidence:0.45, ask:"词典里「美墅→Mansour」尚未在 p1 确认，
         你是指 Mansour（美墅）吗？确认后我记到 p1。"}
→ harness 不执行任何动作，只打印 ask。
落盘: input_raw/input_correct/intent 三条；receipts 为空。

voxsign> 对，就是 Mansour
[轮2·确认/纠错轮]
input_raw: "对，就是 Mansour"
harness: 命中上一轮 ask 的待确认上下文 → 确认别名 → 写 dictionary.json
         {term:"Mansour", variants:["美墅"], project:"p1", source:"user_confirmed"}
intent: {intent:"NOTES_ADD", slots:{project_id:"p1", text:"Mansour报价待复核预算",
         idempotency_key:"idem-88a1"}, confidence:0.9, ask:""}
落盘: input_raw/intent/dict_write(receipt) 三条。

voxsign> （重说一遍）记一条，美墅报价待复核预算
[轮3·执行轮·幂等]
harness: input_correct 直接替换 美墅→Mansour（已确认，不再回问）
         → notes.add@1.0 执行 → SQLite 事务写入 → receipts:
{"request_id":"req-1044","note_id":"n-1042","tool":"notes.add@1.0",
 "ok":true,"duplicate":false,"idempotency_key":"idem-88a1"}
final: "已记到 p1：Mansour报价待复核预算（编号 n-1042）。"
落盘: 完整六段；本地打印回执原文。

voxsign> 核对一下这个月预算还剩多少
[轮4·Gap 轮]
harness: → receipts {ok:false, reason:"no_such_tool"}
         → 自动写 gap{g-7, raw:"核对一下这个月预算还剩多少", stage:Gap}
final: "我还没有预算核对能力，已登记为缺口 g-7。"
落盘: intent/actions/receipts/final/gap 五条。

voxsign> attrib req-1044
[轮5·归因轮]
harness: 打印 req-1044 全链路回放 + 归因建议：
  输入格: OK（美墅已正确纠错）
  上下文格: OK（p1/Mansour 已注入）
  契约格: 本次无关（notes.add@1.0 正常）
  模型格: OK（正确选了 notes.add）
  执行格: OK（SQLite 事务提交）
  外部格: 无
  → 结论：req-1044 成功，无错误需归因；g-7 另案归「契约不足」。
落盘: attribution{request_id:req-1044, result:"clean"} 一条。
```

验证幂等：`voxsign run "记一条，美墅报价待复核预算" --idempotency idem-88a1` → 返回 `duplicate:true` + note_id n-1042，不产生第二条。

## E. 边界：1.0 明确不支持什么

**1.0 运行时（harness 进程内）硬不支持：**
1. 不能自改发布：正在运行的二进制不得自行编译、装载、给自己增权（模型可起草契约与代码，但编译/合并全走人工 git 流程）。
2. 不能任意 shell：shell 工具高危命令（rm/sudo/重定向>/open 等）默认拦截；交互式命令（vim/ssh/top）一律拦截；超时钳制 15s/上限 120s。
3. 不能自动改契约：已发布的 `notes.add@1.0.json` 不可覆写；修改只能新增 `@1.1`/`@2.0` 文件。
4. 不能从「报价/希望少操心」推断预算/授权——OGSM 未知字段就是未知，必须回问。
5. 不能跨端点盲目重跑：工具已执行或 OUTCOME_UNKNOWN 时，禁止换模型重发整段计划。
6. 不能发外部消息/动远端写：V0 副作用仅限本地 SQLite 与本地文件。

**2.0 开发中人工必须保留的环节（hard-stop）：**
1. 契约签署：Draft→Verify 之间，新契约的入参/失败语义/权限边界由人读一遍拍板。
2. 验收判定：30 条样例「是否符合人工预期」由人判，不是 harness 自评。
3. 合并与发布：git commit/merge/release tag、编译、部署容器——人工执行；harness 永不碰。
4. Register→Pilot→全量的激活翻转：`active:true`、`pilot_projects` 范围由人决定。
5. 付钱/对外承诺/突破价带等人类保留清单：底座只提示，不执行。
6. Benefit 算账：「这周少花了多少注意力」由人复盘，harness 只提供轨迹数据。

> 一句话：1.0 负责「记得准、错有账、轨迹可回放、契约只增不改」；2.0 的每一次生长，都是人用普通开发流程、踩着这四条复利资产长出来的。
