# VoxSign Harness 设计评审

**1) 指代×域结合的真价值 / 高估点**
真价值：域把"指什么"和"能不能做"合二为一——"那个文件"的候选集被收窄到域内最近实体，消解不再是全局NLP检索，而是带权限语义的子集查找，一次解析同时完成实体定位和权限预判。
最容易高估：域作为"认知切片"的干净性。实际场景里指代频繁跨域（上句在 sandbox 建的文件，这句问 project 里同名文件），"最近"（时间维度）和"域"（空间维度）会打架，谁优先是脆弱启发式，容易显得诡异或迟钝。把域当唯一实体来源，还会漏掉合法跨域引用（如 vault 密钥被 project 使用），过度隔离=过度回问。

**2) 三级消解分工 / 最大坑**
分层（词典硬匹配→规则→模型兜底）方向对，符合"能确定性解决的不交给模型"。最大坑是**层间边界不可观测**：规则层若无显式置信度阈值，会"自信地吃掉"本该转交模型层的 case，产生静默误判——比模型回问更危险，因为用户不知道系统猜错了。另一个坑是**词典固化后的腐化**：一次确认即 100% 命中，但语境会漂移，若无失效/版本机制，错误绑定会被永久固化，且用户无感知。

**3) 多模态是真增益还是复杂度**
输入截图是真增益，是消解的第四路信号源，但当前三级体系里没纳入，是设计缺口。输出图形摘要代价陡增（渲染管线+图语义抽取），且与"语音控制"的免视觉主场景错位——纯语音终端用不上，带屏场景又削弱了语音交互的核心卖点。建议明确为**可选呈现层**，不进入 M1/M2 主闭环。

**4) M2 顺序调整**
现顺序：域注册表→域校验→风险分级→verify→指代消解→四元缓存
问题：风险分级和 verify 都需要先知道"指的是哪个实体"，指代消解排在它们之后是倒置的。
建议：
域注册表 → 指代消解（先上词典+规则两层，模型推断层可延至 M2.5）→ 域校验 → 风险分级 → verify → 四元缓存（必须最后，因其依赖前四者产出稳定结构）。
