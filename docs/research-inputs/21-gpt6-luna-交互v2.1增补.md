# VoxSign 交互设计 v2.1 增补

## 一、业界模式参考

以下提炼的是可观察的交互模式，不代表各产品实现完全相同：

- **Grok、豆包**：对话流与语音连续进行；适合借鉴“边听边答、可打断、自然续接”，但语音回答仍应同步显示可扫读文本和操作控件。
- **ChatGPT（含 Mac 客户端）**：对话主界面承载多种任务，语音、文件和桌面上下文可从对话中进入；Mac 快捷唤起体现“低成本召回助手”。可借鉴统一入口、上下文可见，避免把关键操作藏进模态切换。
- **Claude Code**：计划与执行分层，工具调用及权限请求显式呈现；可借鉴先看计划、再审批高风险动作，以及保留可审阅的操作结果。
- **Cursor**：Agent 处理代码时以变更集、差异审阅和接受/拒绝承接对话；可借鉴“结果落在可审阅对象上”，而非只给自然语言总结。
- **OpenAI AgentKit**：可视化构建、运行追踪与交接等模式，强调流程可检查；可借鉴把多步任务显示为阶段和事件，不让 Agent 间交接变成黑箱。

**对 VoxSign 的判断：**保留对话作为入口，但执行过程采用任务卡；计划、工具调用、差异、审批都应是可展开的结构化对象，不能只依赖聊天气泡。

## 二、对 v2 六条共识的评审与增补

### 规则 1｜一屏一决策，但允许安全预览
- **触发条件：**需要补充信息、授权或选择方案。
- **交互行为：**每次只突出一个必须完成的决策；可并列展示方案差异、预计影响和默认推荐。可跳过的偏好设为非阻塞项。
- **视觉：**主按钮明确写动作，如“允许修改 3 个文件”，不用“确定”。
- **异常处理：**问题含糊时先给可编辑理解摘要；低风险信息不足可采用保守默认，并标记假设。
- **缺口与修正：**“一屏一决策”可能把多项相关授权拆成疲劳弹窗。对同一任务的同一风险域可合并审批，但逐项列出范围；不可合并不同后果的动作。

### 规则 2｜打断、暂停、撤销必须有不同语义
- **触发条件：**用户说“停/等一下/撤销”，或点击对应控件。
- **交互行为：**停=立即取消当前执行；暂停=保留进度并等待继续；撤销=补偿已完成且可逆的动作。三者使用独立 API 状态和回执。
- **视觉：**任务卡展示“停止中→已停止”，并标注最后一个完成步骤。
- **异常处理：**取消令牌超时或工具不可中断时，立即停止后续步骤，提示“当前步骤仍在收尾”，禁止假报已停止。
- **缺口与修正：**补充部分成功语义、取消超时和工具不可中断处理；语音与文字必须操作同一任务 ID，互相同步状态。

### 规则 3｜角色折叠，以任务为主线
- **触发条件：**Planner、Executor、Verifier 参与同一任务。
- **交互行为：**默认自动折叠已完成角色，只保留当前角色及待决策项；角色交接时不新建任务，不丢失滚动位置、草稿和审批状态。
- **视觉：**任务卡固定显示当前角色、阶段和任务名；时间线可展开查看计划、执行、验证及工具事件。顶部切换器切换的是视图，不改变任务归属。
- **异常处理：**角色失败时停留在失败角色，展开错误及可恢复操作；禁止悄悄切换角色继续执行。
- **缺口与修正：**规定自动折叠条件、失败时强制展开，以及角色切换不重置上下文；详见第三节。

### 规则 4｜状态可见，回执可验证
- **触发条件：**执行开始、工具调用、文件变更、验证完成。
- **交互行为：**步骤按发生顺序追加；回执四行固定为动作/文件/结果/撤销，并链接到差异、日志或验证证据。
- **视觉：**区分“进行中、完成、失败、跳过”；长日志默认折叠，当前步骤置顶。
- **异常处理：**证据缺失写“未验证”，不得把模型陈述显示为已验证事实。
- **缺口与修正：**增加耗时、重试和证据来源；允许展开原始输出，但不让日志淹没当前状态。

### 规则 5｜风险分级，确认不等于放行
- **触发条件：**动作触及文件、命令、网络、权限或外部系统。
- **交互行为：**默认拒绝未授权范围；按影响显示具体资源、范围与后果。不可逆动作始终要求人工执行或人工逐步确认；BOUNDARY_VIOLATION 无“继续”按钮。
- **视觉：**以动作描述授权，不以抽象权限名授权；高风险动作与普通继续分区。
- **异常处理：**无法判定风险时按更高等级处理；授权范围变化即重新询问。
- **缺口与修正：**补充授权的范围、时效、撤回方式；确认只对展示过的具体动作有效，计划变更后失效。

### 规则 6｜把“爽感”变成可测量门槛
- **触发条件：**每次任务完成或用户中止。
- **交互行为：**记录首次有效反馈、纠正次数、误操作、停止生效时间，并区分语音与文本入口。
- **视觉：**运行界面不展示指标；内部面板按任务类型、风险等级查看分布。
- **异常处理：**区分网络/工具延迟与 Agent 延迟；样本不足标记“不确定”，不以平均值掩盖长尾。
- **缺口与修正：**定义“有效反馈”为确认理解并给出下一步/可用结果；另跟踪误听率、重复播报率和授权后越界率。

## 三、多角色折叠专项

### 规则 7｜按任务状态决定角色展开
- **触发条件：**角色启动、交接、等待输入或失败。
- **交互行为：**当前角色默认展开；已完成角色自动折叠；需要用户决策、角色失败、边界阻断或验证不通过时强制展开。用户可手动展开历史角色，执行中不自动抢回焦点。
- **视觉：**顶部显示“执行中 · Executor”及进度；交接以时间线事件呈现。Planner 显示计划，Executor 显示步骤/工具，Verifier 显示检查项与证据。
- **异常处理：**角色无响应显示超时与重试/停止选项；Verifier 未完成时不得显示任务成功。

### 规则 8｜切角色不丢状态
- **触发条件：**用户点选角色或展开其历史记录。
- **交互行为：**保存各角色滚动位置、筛选、草稿和展开状态；切换只改变查看内容，不取消任务、不重新授权。
- **视觉：**当前执行角色有持续标识；查看历史角色时另标“正在查看”，避免误以为它仍在执行。
- **异常处理：**历史状态与当前状态不同步时显示最后更新时间和“刷新”；过期审批不可直接复用。

## 四、语音专属增补

### 规则 9｜ASR 不确定时先纠错，不擅自执行
- **触发条件：**人名、路径、命令等关键实体置信度低，或不同识别结果会改变动作。
- **交互行为：**短候选用点选；长句提供可编辑转写；简单口误可提示“重说这一段”。执行前复述关键实体和动作。
- **视觉：**只高亮不确定词，候选按钮不复述整句。
- **异常处理：**连续两次不确定则转文字编辑/键盘输入；危险动作不以“我听起来像……”作为确认。

### 规则 10｜一份任务状态，语音文字双通道同步
- **触发条件：**用户在语音与文字之间切换，或任一通道发出停止/暂停/撤销。
- **交互行为：**所有输入和控制作用于同一任务；一方停止后另一方立即显示状态。语音被打断时停止播报；是否继续后台执行须明确提示并遵守任务授权。
- **视觉：**显示听写内容、当前任务状态和最后操作结果；麦克风状态与执行状态分开。
- **异常处理：**通道断连时保留任务并提示“仍在执行/已停止”，重连后恢复同一任务，不重复提交指令。

### 规则 11｜屏幕容量匹配语音节奏
- **触发条件：**语音播报长内容、连续步骤或等待用户回答。
- **交互行为：**每轮语音只讲结论和当前所需决策；细节按任务卡分段，支持暂停后从断点继续。屏幕内容可多于播报，但明确标注当前播报段。
- **视觉：**当前句或步骤跟随高亮；选项与语音顺序一致，关键按钮始终可见。
- **异常处理：**用户插话即暂停播报并优先处理新输入；识别失败时不从头重播长段，提供重听、看文字或重说。
