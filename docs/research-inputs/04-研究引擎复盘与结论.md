### 2. 入队协议（research-opc = `/opt/research-auto/run_loop.py` v2）
三件套，缺一即被付费门 `BLOCKED_PAID_EXECUTION`：
1. **提示词文件** `/opt/research-auto/prompts/{ID}.md`（ubuntu 可写）。正文必须自带 `REPORT_BEGIN`…`REPORT_END` 标记——run_loop 截取最长(>100字)的一段落盘。
2. **任务条目** 写进 `/opt/research-auto/tasks.json`，`status:"queued"`、`attempts:0`、`priority` 越小越先。
   ⚠️ **tasks.json 被 `chattr +i` 锁死**（control-drift 治理）。 sanctioned 写法 = `chattr -i → 追加 → chattr +i`（pool_picker/reconcile 就这么干）。直接 open 写会 `EPERM`。
3. **付费契约** `/etc/research-opc/paid-approvals/{ID}.json`，必须 root:root、mode 600（不可 group/other 可写）：
   ```json
   {"approved":true,"task_id":"<ID>","model":"gpt-6-astra",
    "prompt_sha256":"<prompt文件字节sha256>","max_attempts":1}
   ```
   门校验：目录+文件均 root 所有、无可写位、prompt_sha256 与当前 prompt 逐字节一致、model 恒为 `gpt-6-astra`、max_attempts=1、仅 attempts==0 放行。

### 3. 怎么触发 / 怎么取回
- root crontab 的 `run_pool_cycle.sh`（pool_picker→run_loop→reconcile）当前**整段 OPC_HOLD 注释**，不会自动接单。需手动：
  `sudo HOME=/home/ubuntu setsid /usr/bin/python3 /opt/research-auto/run_loop.py &`
- run_loop 自己 `save_tasks` 会撞 +i 崩（**设计如此，正常**），但结果文件已先落盘。
- 取回：`/opt/research-auto/results/{ID}-{YYYYMMDD}.md`（world-readable，直接 scp/cat）。

## 二、研究引擎核心结论（忠实转述，【原文】=照录，【摘要】=压缩）

### ① 定位与设计哲学
【原文】“VoxSign 应当成为一套由你拥有、能持续降低下一次工作成本的个人生产系统……10 倍效率只能作为经营目标，不能作为架构成立的前提。”
- 底座最小定义 = “能完成真实任务，并让下次同类任务少解释、少操作、少犯错的闭环”；缺“把确认经验用于下次”则只是自动化工具。
- 复利=四类资产（认识/能力/证据/验证），且**错误也会复利**——必须内置纠错、撤销、淘汰机制。
- 五把尺子：复用证据 / 净节省 / 迁移能力 / 可验证性 / 维护负担。经营公式 `净收益=重复次数×每次节省−建设−维护−错误损失`。
- 北极星指标：**每个合格结果消耗多少分钟人工注意力**（不是延迟/token）。

### ② 三层生长架构
【摘要】三层是**责任边界**，不是三个进程：认知层=可修订的判断（画像/OGSM/规则，禁自带可执行脚本）；接口层=可检验的承诺（契约/schema，不藏业务判断）；执行层=受约束的动作（输入/路由/校验/工具/存储，禁猜用户意图）。
- 目录建议：`cmd/voxsign` + `cognition/`(md/yaml 数据) + `contracts/`(types.go+各版本 schema) + `internal/{engine,input,context,model,policy,tools,store}` + `eval/cases.jsonl`。**不用 Go plugin**（跨平台单二进制不适合），模块可插拔=编译时注册+配置启停。
- 生长回路独立成状态机：Use→Gap(记缺口)→Triage(归因/价值筛选)→Draft(契约+失败样例)→Verify→Register(暂不激活)→Pilot→Learn(能力目录+示例)→Benefit(验复用价值)→回退。
- **关键纠偏**：“认知慢变”不等于所有认知材料同周期——价值/规则慢变，项目状态/预算/会话事实快变。归因分六格（输入/上下文/契约/模型判断/执行/外部），不是“模型错vs执行错”两格。
- 安全：权限判断由代码做（模型只建议）；确认绑定动作摘要+参数散列+契约版本+有效期；`OUTCOME_UNKNOWN` 状态必须先核对再重放；本地用 SQLite(modernc, 免 CGo) 事务包幂等凭证+回执。

### ③ 模型中心 / 多端点演进
【原文】“模型中心应该是默认后端，而不应该成为底座的所有者。”
- 个人上下文（画像/词典/契约/回执/eval）全部留本地；模型中心只管鉴权/路由/计量。
- 抽象就一个接口 `ModelBackend.Infer(ctx, ModelRequestV1)(ModelReplyV1,error)` + **能力声明**（结构化输出/工具调用/流式/上下文容量）；差异（如 Anthropic 工具调用放 content block）由适配器吸收，工具执行权留本地。
- 三条独立版本轴：模型边界版本 / 工具契约版本 / 认知版本，互不混同。兼容要语义兼容（非仅 JSON 可解析）；警惕 `additionalProperties:false` 让“加字段”也破兼容。
- 灰度分两类：**协议兼容灰度**（解析/超时/关联）过了，**认知行为灰度**（理解/选工具/参数/回问）仍可能挂。个人流量小，不搞 1% 随机——先离线案例对比→影子运行（不产生副作用）→指定低风险任务。切换否决项=越权/错误副作用。

### ④ V0 最小落地路径（两周/10 工作日）
- 最小认知种子只要 5 项：一个当前项目+本周期最重要结果 / 一条优先级规则 / 时间费用授权边界 / 少量已确认实体别名 / 成功与回问定义。**OGSM 未知字段就标未知**，禁止从“报价”推断预算。
- 代码内核预算：**约 2000–3000 行生产 Go + 800–1500 行测试**（不是代码竞赛）。
- 首个闭环：`“记一条，美墅报价待复核预算”`→原文留底→别名未确认则回问→确认 Mansour→写本地记录存回执→下次不再问；再追加 `notes.list` 验“补一次能力、下次少操作”。
- V0 坚决不做：ASR/音频、center WS 全协议、向量库/知识图谱、多智能体、自改代码发布、动态插件、外部发消息、任意 shell。
- 验收硬指标：30 条样例≥27 条符合人工预期（该回问/该拒绝也算对）；幂等重复提交只一条；人工操作时间降 ~30% 且复查成本不升。

### ⑤ 风险与最大分歧
【原文·五大失败模式】①积累未验证认识却把“攒得多”当“理解深”（自我强化叙事）；②把 Markdown 规则当免维护代码；③接口 schema 全对但语义错（记错人/错项目/错日期）；④工具增长超过维护能力；⑤**“为了高效，先给自己造了个永久维护项目”**——最危险指标是“本周新增多少模块”，最有用是“本周少花多少注意力”。
【原文·对作者的提醒】“你可能把自己方法论的一致性，当成了真实需求已被验证的证据……用户模型应解释你的行为，而不是要求你配合它的分类。”
【最大反对/保留】
- 反对“认识/执行分得越清越好”的绝对化：**责任必须清楚，交互必须充分**——彻底隔离会在边界上造出“无人负责的误解”，契约是协作不是免责区。
- 保留“个人化=自建服务”：真正自建的是个人语义/决策规则/上下文组织；DB、协议客户端、schema 校验、认证仍应复用基础设施。
- 第 14 天必须做决定：真在用、重复解释减少、能力增长确有复利→继续；只有漂亮分层+一次顺利演示→冻结扩展，回到那个最值得每天用的场景。
