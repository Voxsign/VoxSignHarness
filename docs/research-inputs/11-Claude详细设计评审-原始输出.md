# 评审：VoxSign Harness v1

**问1：双信号（可逆性+影响面）够吗？**
不够。影响面本质是模型自估的"软判断"，而不可逆性是硬事实。危险场景：模型把高影响面误判为"小"（如把"改错误提示"的 diff 实际波及了被多处依赖的共享函数），此时自动执行会直接跑偏，且没有第三信号兜底。建议加第三轴——**"涉及文件的历史变更频率/被引用面"**（静态可算，不靠模型自评），三轴中任一触发高风险即升级确认。不必每步问：用"影响面"做异步确认（先执行、标记、允许一键撤销），只对"不可逆"硬确认，这样频率可控。

**问2：认知层会不会太重？**
会。project-map/decisions-log/prefs 若由模型"每轮总结 delta 并维护"，本质是让模型在每次调用里做双重任务（执行+自我归档），容易导致：(a) 总结质量随任务漂移退化、(b) 注入长度单调增长拖慢响应。建议：认知层更新是**独立的、低频的异步任务**（比如每日/每 N 次会话批量 reindex），不在主循环里实时写；注入前做相关性检索（只注入与当前 path/模块相关的切片），而不是全量塞入上下文。

**问3：五工具够不够？缺哪个最致命？**
缺 **search/grep 契约**（独立于 file 之外的只读检索能力，用于"这个函数在哪"类 QUERY，当前塞进 file+git 不够精确）；更致命的是缺 **observe/diff 契约**——独立校验器要"读实际状态"，但文档里没有定义这个读取动作本身的契约化接口，它目前被隐含在执行层里，没有版本化、没有审计。这是闭环的关键节点却没契约化，建议补一个 `verify` 契约，独立于 `run`。

**问4：还有什么坑？**
ASR 对代码实体（变量名、路径、API 名）的纠错是无底洞——"美墅→Mansour"这类人名词典可枚举，但函数名/路径空间几乎不可穷举，置信度阈值会频繁触发澄清，体验反而更差。另外"确认疲劳"没设计：强确认太多次用户会无脑点"是"，相当于形同虚设。

**问5：1.0→2.0 自举的充分条件？**
不是"独立校验器"，是**契约注册机制本身可被语音调用**——即"用语音新增一个工具契约"这个动作如果能走通（意图→生成契约 JSON→风险分级→人确认→注册），才是真自举；否则 2.0 仍要人手写 Go。

## 最大反对意见
**这份设计的自动执行范围建立在"模型对影响面的自评"之上，而影响面恰恰是模型最容易算错的东西**（它不知道这段代码被谁依赖、下游还有什么隐式契约）。整个确认策略引擎的安全边界系于一个不可靠的估计值，这是架构性风险，不是细节问题——建议影响面必须有至少一项静态/机械信号（引用计数、测试覆盖、历史改动热度）参与判定，不能纯靠模型"觉得"。
