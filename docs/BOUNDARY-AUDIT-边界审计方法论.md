# Boundary Audit 边界审计方法论（长期技能 · v1.0）

> 一句话：**不是靠想，是靠问。** 边界的完整度用"模型提问数"度量，每轮暴露一批盲区，补齐后下一轮提问递减，归零=边界画完。

## 1. 核心思想

"我觉得差不多了"是主观感觉，不可靠。换成三个客观信号：
- **未填字段数**：每个定义必须填满；填不出 → 标 `UNKNOWN`，不许假装清楚
- **无反例定义数**：写不出"什么情况会错"= 还没想清楚
- **模型提问数**：把 SPEC/方案丢给强模型问"你要实现它还缺什么"，它开口要的每一样 = 一个盲区

## 2. 四层完整性判据（每个模块必须过）

| 层 | 判据 | 没过 = 盲区 |
|---|---|---|
| schema 层 | 每字段：类型 / 必填 / 示例 / 反例 | 数据结构没说清 |
| 边界五轴 | 范围 / 排除 / 权限 / 验收 / 上下文 五项显式 | 边界没画全 |
| 判断层 | 什么算错 / 代价 / 怎么反问（六强制字段） | 机器遇新情况不会选 |
| 用例层 | 每行为：正例 + 反例 + 边界用例 | 干完不知对错 |

## 3. 盲区发现循环（每次讨论 / 每份文档执行）

```
产出 v0（按四层判据填，填不出标 UNKNOWN）
  → 丢给强模型："你要实现它，还缺什么？"
  → 它的提问清单 = 盲区清单 → 回填 UNKNOWN 项
  → 再丢 → 直到零提问（此时才可开工）
```

## 4. 主动沟通协议（系统对用户的反问）

系统每次讨论结束，主动给用户一轮盲区提问，规则：
- 只问**会改变下一步动作**的问题（不问琐事）
- 每题给**建议默认值**——用户不回答就按默认走（少让用户拍板）
- 自己能定的绝不上报（载体、优先级、词典范围等自己定）
- 涉及资金 / 不可逆 / 外部动作才必须让用户明确拍板

## 5. 典型盲区来源（写 SPEC 时的固定检查）

- 现有代码基线清单（已有什么、接续点在哪）
- 数据 schema 完整字段（类型 / 必填 / 示例 / 反例）
- 验收用例覆盖（正例 / 反例 / 边界）
- 初始数据（词典第一版、域注册表第一版、OGSM 目标值）
- 错误处理与中断准则（代价超预期怎么办）
- 里程碑定义（"完成"到底长什么样）

## 6. 使用位置

- 本方法论：随 VoxSign Harness 设计文档长期参照（docs/ 下）
- 对话层：每轮讨论结束由 MainAgent 主动执行一轮盲区提问
- SPEC 层：写规格书时逐模块按四层判据填，填不出即 UNKNOWN
- 评审层：SPEC 每版丢强模型（Codex 实现向 / Claude 逻辑向）计提问数

## 7. 伪代码层规范（描述代码 · v1.0，Claude 评审定稿）

写代码前，在"定义语言（VSL）"和"真实代码"之间增加一层**伪代码/描述代码**——用注释形式写清模块内部逻辑（控制流、分支组合、拒绝路径、异常处理），评审通过后再写真代码。

**分级强制（不全局强制）**：
- **必写**：判断/裁决类模块（意图解析、冲突仲裁、拒绝逻辑、space_check、指代消解、风险分级、verify、缓存、REGISTER_TOOL）——分支多、错判代价高
- **豁免**：适配器、胶水代码、简单 CRUD / 薄封装——逻辑线性，伪代码无增量价值

**定位**：一次性评审关卡，不是长期维护文档——评审通过后归档为设计记录（可精简），不要求与代码永久同步（否则必然腐化）。

**与 VSL 分工（不重复）**：
- VSL 管"做什么"：意图 / 域 / 契约 / 判断语义——跨模块、面向业务、相对稳定
- 伪代码管"怎么做"：单模块内部控制流 / 分支 / 异常路径——随实现变动
- 判断标准：伪代码里出现"意图判断规则"= 写错层，搬回 VSL；伪代码只引用 VSL 契约点，不重新定义语义

**落地规则**：
- 只对**尚未动笔**的模块强制（编码前先过伪代码评审）
- 已完成的核心裁决模块可选补"事后伪代码审查"查漏，不追求长期维护
- 评审通过后归档为 PR 描述 / 设计记录即可，不建需持续同步的文档体系
