## 1. 这个项目是什么

**voice-sign-harness（`vhs`）**：一个 Go 单二进制、**零第三方依赖**的语音驱动开发 harness。

```
语音 → ASR 文本 → [纠错/标点] → 意图 → 规划 → 域门禁 → 执行 → 独立校验 → 回执
```

**核心红线**：`Ask != '' → 绝不执行`；**域=权限交集，默认拒绝**；**不可逆必须人工确认**。

### 2.4 L-01 多轮逼近目标架构（2026-10-03 上线，commit de52ff0）

**参照系**：DeepSeek 官方开源 harness（`github.com/deepseek-ai/deepseek-harness`，dsh-0.1.0-rc.7）goal-round-driver 轮次状态机 + round-limit block 语义。逐维度对照见 `docs/参照系-DeepSeekHarness-vs-VoiceSignHarness.md`。

**任务状态机（新增 `blocked`）**：

```
running ──▶ need_ask ──▶ need_confirm ──▶ running（多轮）──▶ done
   │                          │                                  ▲
   │                          └─ canceled（澄清不收敛/用户取消） │
   └─ canceled（错误/取消）                                     │
   └─ blocked（round-limit：证据门达上限仍 FAIL）──（不复跑）───┘
```

**轮次语义**（对齐 dsh round driver）：
- 每个任务 `max_rounds=20`、`rounds_used` 递增；实现类任务（ORCHESTRATE kind=implement）每轮末过**证据门**。
- **证据门**（`pipeline.EvidenceGaps`，真装配不许桩）：产物目录存在 + `main.go` 非空 + 无 TODO/占位/"code generated by" 标记 + P0 关键字存在性（dictionary/correct/intent/feedback/jsonl/append/v1/health/v1/process）+ **`go build -C <implRoot> ./...` 真编译**。
- 证据门 **PASS → done（唯一成功出口）**；**FAIL 且未超上限** → 记录 fail 轮次、缺口（`round_log` / `last_round_gaps`）回喂下一轮 LLM（`skip_confirm=true` 免二次确认）；**FAIL 且超上限 → blocked（round-limit）**——**杜绝"骨架也 done"**（历史洞：LLM 超时 → 骨架兜底 → 假 done）。
- 非实现类任务直接 done（防普通任务被证据门误锁循环）。
- GET `/v1/task/{id}` 现返回 `max_rounds` / `rounds_used` / `blocked_reason` / `round_log`（每条含 round/status/evidence/elapsed_ms）。

**LLM 网关实测约束（2026-10-03 裸调证据）**：
- 请求 >60s → 网关 504（客户端超时设多大都救不了）；`MaxTokens` 上限会让模型用满 token → 超 60s → **harness 不传 MaxTokens**（自然收敛，裸调 36s/11913 字符成功）。
- 顶层 `use_max_completion_tokens` 字段 → 网关 502（0.9s）→ **已从 aiops providers Params 移除**。
- 需求文档全文（7966 字符）直接喂 → 必然超时 → **逐文件生成 + 能力清单摘要化**是正解（llmGenerateImplement 已逐文件化）。

### 4.2 角色分工（**不许混**）

### 4.3 ⭐ 9 条「等价是假设，不是事实」（**最耐用的一页**）

| # | 看起来等价 | 真跑暴露 |
|---|---|---|
| 1 | 有 `defer Unlock` ⇒ 安全 | `unlock of unlocked mutex` |

### 4.3b ⭐ 第 10 条实例 · **「我确信我在测 X」**（2026-10-03 一天内犯了两次）

| # | 看起来等价 | 真跑暴露 |
|---|---|---|
| **10** | **起了服务、打了请求 ⇒ 测的就是新代码** | **读到的是旧进程的响应** |

**同一天两次，形状相同：我拿到的数据，不是我以为的那个来源。**

```
第一次：验证 /v1/task 的 refused 字段
        我在顶层读 d["refused"] ⇒ None ⇒ 差点报"接口没返回"
        真相：字段在 d["plan"]["refused"]
        ⇒ 数据源错了（读的层不对），不是接口错

第二次：验证"错误归因"修复
        起新进程 → 打请求 ⇒ 收到旧文案 ⇒ **报了 FAIL**
        真相：8765 被上一轮没杀干净的 PID 占着，新进程没起来
        ⇒ 数据源错了（打的是旧进程），不是修复失败
```

**两次都是"差点报一个不存在的 bug"。第二次已经报出去了，随后撤回。**

**第三次（2026-10-03 同日，由实现方各自发现）**：
```
实现方贴给测试方的 sha `0504560…` **从未落在远端**
原因：流程是 commit → fetch → **rebase** → push，而它在 **rebase 之前取的 sha**
⇒ 贴了一个不存在的 commit ⇒ 等于让测试方测一个漂移对象
```

**⇒ 三次形状相同：我拿到的 / 我贴出的，不是我以为的那个。**
**（第一次读错层 · 第二次打错进程 · 第三次贴错 sha）**

**⇒ 纪律（写进流程，不靠记性）**：

```
① 起服务后，**先确认监听进程是我刚起的那个**
     lsof -nP -iTCP:<port> -sTCP:LISTEN      # 记 PID、比对时间
     或让服务用它自己的 bind 回显（日志里的 "listening on ..."）
② 杀进程要杀到干净：
     pkill -f "vhs-asr" 之外，**还要 pkill -f "exe/voicesign"**
     （`go run` 的子进程名不是 `go run`，`pkill -f` 匹配不到）
③ **读到"预期之外"的结果时，第一件事是查数据源，不是报 bug**
④ **贴 sha 的唯一合法时机：push/rebase 完成之后，从远端取**
     ⇒ 贴 Issue 前先 `git ls-remote origin <sha>` 回读；**回读不到 ⇒ 不许贴**
⑤ **回读不到"我预期的东西"时，先怀疑"我是不是拿错了"，再怀疑对方**
```

> **一般形式**：**凡"我确信我在测 X"的地方，都要有一次"确认我测的真的是 X"。**
> **这与那 9 条同源 —— 等价是假设，不是事实。**



| 例 | 标的是什么 |
|---|---|
| `WM-1` | "**在什么口径下**成立"（依赖 `DemandFloor` 推断） |
| `SCOPE-PROFILE-01b` | "**将来**才可能被触发"（前瞻守卫 `forward-guard`） |
| `ASR-EXEC-05` v2 | "**现在只证明了哪一面**"（文件系统已断言，出网/进程 UNCOVERED） |

> **一条绿判据，要么能被真实数据触发，要么标明"前瞻守卫 / 当前无数据"。**

## 7. 关键坑（**我们踩过，别再踩**）

| 坑 | 怎么避 |
|---|---|
| **猜 API 路径** | **读调用方/规范的 `fetch`**，别猜（我们猜过 4 个端点全 404） |
| **静默失败** | **任何失败都要可见**（`/v1/testpage` 曾点处理啥都不显示） |
| **`refused` 读顶层** | `/v1/task` 的字段**嵌在 `plan.*` 里**——**先读结构表** |
| **`&` 后台化整条链** | shell 里 `cmd &` 会后台化 pipe 里全部——**服务没起来就 curl** |
| **锚点打偏** | 改代码时**锚点要唯一**，否则补丁静默不生效（grep 回读） |
| **英文引号截断** | 嵌引号一律用 `「」`；**commit message 用 `-F 文件`**，不用 `-m` |
| **白名单必然漏** | 别维护步骤名/词表白名单，**用类型或"零副作用"断言** |
| **别名两用途混用** | **路由可全别名；改写只许专名**（否则"文件"→`file-store`） |
