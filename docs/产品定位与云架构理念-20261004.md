# VoiceSign 产品定位与云架构理念

> 状态：Proposed（2026-10-04 用户口述定稿，作为公司级项目方向）
> 性质：**理念基准文档**——所有后续架构/产品决策以此为锚，冲突时先回看本文。

## 一、产品定位：公司级云服务

VoiceSign 从"个人自托管工具"升级为**公司项目**：语音 Agent 云平台。

- 每个用户：找一台服务器自己装（自托管），**或**直接接入统一云平台——两种形态并存，云端为默认、本地端为可选增强。
- 云端默认存在：用户无需运维服务器，即开即用。

## 二、身份范式：谷歌账户 = 唯一管控标准（无注册体系）

**核心决策**：云端身份只用**谷歌账户登录**，谷歌账户是唯一的管控标准。

- **不提供任何用户注册/密码/用户名体系**——没有"注册"概念，登录即身份。
- Google OAuth 登录（ID token）→ 谷歌账户即租户 ID（sub / email）。
- 好处：
  1. 零注册摩擦，获客门槛最低；
  2. 认证安全由谷歌负责，不自建认证栈（不存密码、不背泄露责任）；
  3. 跨设备天然跟随（换手机/换电脑，同一谷歌账户，个性化自动跟着走）；
  4. 为免费额度/配额/未来付费提供天然挂点（挂谷歌账户即可）。

## 三、云端网关：统一入口 + 本地端可选

- 云端只暴露**一个统一处理入口**（云端 Harness 网关），承接所有谷歌账户的语音请求。
- 本地端是可选增强形态：自托管单租户（default），面向隐私敏感/离线/定制需求的用户；可后续绑定谷歌账户实现个性化同步。

## 四、免费额度与商业化模型

- 基础服务**免费额度**（按谷歌账户）：如每日语音时长/ASR 调用/执行次数配额。
- 超出免费额度 → 付费解锁（订阅/充值），计费挂谷歌账户。
- 设计含义：免费额度即"试用即转化"，无注册漏斗；配额与计量是商业化地基，**从第一天就做**。

## 五、架构影响（多租户 = 谷歌账户）

| 原设计（多租户通用） | 新设计（谷歌账户即租户） |
|---|---|
| 管理端创建租户 tk_租户_密钥 | 无需管理端——**谷歌登录即租户** |
| 租户认证：自定义 token 路由 | Google ID token 验证 → sub 作 tenant_id |
| 配额/计量按租户 | 按谷歌账户（免费额度/付费） |
| 个性化热词按租户目录 | `data/tenants/<google_sub>/`（隔离不变） |
| iOS 设置填"云端账号" | iOS 用 GoogleSignIn 一键登录 |

- 本地端兼容：`default` 租户保留，自托管用户零迁移。
- 验证器/契约（/v1/tasks、/v1/asr）**不变**，只增加认证层。

## 六、关键决策记录（ADR 式）

| # | 决策 | 为什么 | 放弃的选项 |
|---|---|---|---|
| D1 | 谷歌账户为唯一身份标准 | 零注册摩擦、认证安全外包、跨设备跟随、免费额度/付费天然挂点 | 自建用户体系（注册/密码/找回，成本高且无差异化） |
| D2 | 云端默认 + 本地端可选 | 模型/算力成本高需共享、维护负担下沉云端、隐私用户保留自托管 | 纯本地（维护重、无商业空间）/ 纯云端（失去隐私与离线价值） |
| D3 | 免费额度起步，计费挂谷歌账户 | 试用即转化，无注册漏斗；配额/计量从第一天做（商业化地基） | 直接付费墙（门槛高）；纯免费（无法支撑公司化） |
| D4 | 云端单一统一网关 | 一个入口好管控、好扩容、好计量 | 多入口分散（难管、难计） |
