# 实现规格 · 上下文槽（指代固化，含 conversation_id 概念）

> 依据：需求说明书 §4.3 L2 指代消解第三层「固化复用」；评审报告-指代固化与线C（§二 方案 C）。
> 供实现方 deepseek 使用。时间：2026-10-03

---

## 1. 核心概念（重要）

**conversation_id 必加**（用户明确：未来一定要有这个概念，哪怕默认带一个也要）。

- 所有涉及指代/上下文/记忆的接口请求必须带 `conversation_id`
- 缺省时使用默认会话 `"default"`（不报错、不拒绝——向后兼容）
- 上下文槽按 conversation_id 隔离：同会话命中、跨会话不串

## 2. 数据模型

```
DisambiguationSlot {
  conversation_id string   // 必填，缺省 "default"
  mention         string   // 指代词（如 "那个"、"它"）
  target          string   // 解析目标（如 "AIOps"）
  confirmed_at    string   // ISO 时间
  source          string   // "confirm" | "dictionary"
}
```

## 3. 存储（数据驱动，不写死）

- 文件：`<dataDir>/disambiguation.jsonl`，**append-only**（复用 Tracer 写盘模式，0600）
- 每次确认追加一条；查询时按 (conversation_id, mention) 取**最新**一条
- 可选：沉淀跨会话高频指代 → 词典条目（term=mention, target=target, scope=global）复用词典机制

## 4. 行为闭环（L-01.5 验收链）

1. process 输入含指代且多候选 → `need_disambiguate:true` + 候选列表（现状已有 ✅）
2. 用户确认 → **确认接口**（需实现方确认：复用 /v1/feedback 或新增 confirm 参数）写入槽
3. 同会话再次输入 → **先查槽**：命中 → 直接解析目标（无 need_disambiguate）；未命中 → 正常候选/回问

## 5. 验收判据（测试方补测闭环）

- L-01.5a：多候选 → need_disambiguate=true
- L-01.5b：确认后写入 disambiguation.jsonl（append-only 可审计）
- L-01.5c：同会话再次输入 → 直接命中（无 need_disambiguate）
- L-01.5d：跨会话不串（conversation_id 不同 → 无记忆）
- L-01.5e：缺省 conversation_id 不报错（默认 "default"）
