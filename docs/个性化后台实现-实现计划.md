# 个性化后台实现-实现计划

## 一、目标与范围

构建一个独立运行的 Go 后台服务，实现 ASR 识别文本的个性化纠错与学习闭环。服务需记住用户教过的词（词典）、标错的词（黑名单）、确认过的映射（反馈），并在后续纠错中持续应用，达到“越来越懂你”的效果。

本计划覆盖 P0 全部能力的实现、持久化设计、接口定义、任务拆解与验收判据。

## 二、技术约束

- 开发语言：Go。
- 依赖限制：仅标准库，零第三方依赖，不允许引入外部包。
- 运行方式：可独立运行；通过 flag 或环境变量配置监听地址（默认 `127.0.0.1`）与数据目录（默认 `./data`）。
- 数据持久化：
  - feedback 使用 JSONL append-only；
  - dictionary / blacklist 使用 JSON 文件。
- 代码质量：不留 TODO、占位或伪代码；自包含，可直接 `go build` 通过。
- 文本处理：支持中文 UTF-8，响应中文不乱码。

## 三、总体架构与模块划分

建议按以下模块组织实现：

1. **配置模块**：解析 flag / 环境变量，产出监听地址、数据目录、可选鉴权 token。
2. **HTTP 路由模块**：注册并分发 `/v1/*` 端点，统一 JSON 响应与错误处理。
3. **持久化模块**：
   - 词典读写（dictionary.json）；
   - 黑名单读写（blacklist.json）；
   - 反馈追加（feedback.jsonl）。
4. **纠错引擎**：基于词典 variants→term 映射执行替换，结合黑名单跳过指定词。
5. **意图分类模块**：对输入文本分类为 NOTE / QUERY / EDIT 等意图，并叠加纠错结果。
6. **鉴权中间件**：当环境变量配置 token 时，校验 `Authorization: Bearer <token>`；未配置则关闭。

## 四、数据模型与持久化设计

| 数据文件 | 格式 | 读写模式 | 关键字段 |
|---|---|---|---|
| `data/dictionary.json` | JSON | 全量读写 | `terms` 数组，元素含 `term`、`variants`、`category`、`source` |
| `data/blacklist.json` | JSON | 全量读写 | `term`、`note` |
| `data/feedback.jsonl` | JSONL | 仅追加 | `raw`、`corrected`、`accepted`、`reason` |

持久化要求：

- 词典与黑名单在服务重启后仍可读取，保证跨重启生效。
- feedback 每次请求追加一条独立 JSON 行，不覆盖历史。
- 未接受（accepted 为否定）的反馈必须携带 `reason`。

## 五、接口清单（P0）

| # | 方法与路径 | 行为 | 依赖数据 |
|---|---|---|---|
| 1 | `GET /v1/health` | 健康检查，返回 `{"ok":true}` | 无 |
| 2 | `GET /v1/dict` | 返回全量词典 JSON，`terms` 数组含 `term/variants/category/source` | dictionary.json |
| 3 | `POST /v1/term` | 增词，请求体含 `term/variants/source`，写回词典并持久化 | dictionary.json |
| 4 | `POST /v1/correct` | 个性化纠错：输入 `{text}`，应用词典映射（如 曼苏→Mansour）与黑名单拦截，返回 `{corrected, applied:[…]}` | dictionary.json、blacklist.json |
| 5 | `POST /v1/process` | 意图分类 + 纠错：输入 `{text}`，返回 `{intent, corrected}`，intent ∈ NOTE/QUERY/EDIT/… | dictionary.json、blacklist.json |
| 6 | `POST /v1/feedback` | 反馈学习：输入 `{raw, corrected, accepted, reason}`，追加 feedback.jsonl；未接受时必带 `reason` | feedback.jsonl |
| 7 | `POST /v1/blacklist` | 黑名单：输入 `{term, note}`，写入 blacklist.json；纠错时跳过该词 | blacklist.json |
| 8 | 鉴权（可选） | 环境变量配置 token 时，校验请求头 `Authorization: Bearer <token>`；未配置则关闭 | 无 |

## 六、实现任务拆解

### 阶段 1：工程骨架

- 创建 `go.mod`，声明模块名与 Go 版本。
- 实现配置解析：监听地址、数据目录、可选 token。
- 初始化 HTTP Server 与基础路由。
- 封装统一 JSON 响应辅助函数，确保中文 UTF-8 输出。

### 阶段 2：持久化层

- 实现 dictionary.json 的加载、保存与结构体映射。
- 实现 blacklist.json 的加载、保存。
- 实现 feedback.jsonl 的追加写入，保证每行一条完整 JSON。
- 处理数据目录不存在时的自动创建。

### 阶段 3：基础端点

- `GET /v1/health`：返回健康状态。
- `GET /v1/dict`：读取并返回全量词典。
- `POST /v1/term`：解析请求体，追加或更新词条，持久化后返回结果。

### 阶段 4：纠错引擎与意图分类

- `POST /v1/correct`：
  - 读取词典与黑名单；
  - 按 variants 匹配输入文本，替换为 term；
  - 黑名单中的词跳过替换；
  - 返回 corrected 与 applied 列表。
- `POST /v1/process`：
  - 复用纠错逻辑；
  - 增加轻量意图分类，输出 NOTE / QUERY / EDIT 等；
  - 返回 intent 与 corrected。

### 阶段 5：反馈与黑名单

- `POST /v1/feedback`：
  - 校验字段；
  - 未接受时强制要求 reason；
  - 以 append-only 方式写入 feedback.jsonl。
- `POST /v1/blacklist`：
  - 写入 term 与 note；
  - 持久化到 blacklist.json；
  - 后续纠错时跳过该词。

### 阶段 6：鉴权与收尾

- 实现可选 Bearer Token 校验中间件。
- 补充 README，说明启动命令、端点清单、数据文件位置。
- 执行本地验收用例，确认 `go build` 与运行行为。

## 七、验收判据

2. 服务启动后，`GET /v1/health` 返回 `{"ok":true}`。

6. 重启服务后，词典与黑名单仍存在，证明持久化跨重启。
7. 所有端点返回 JSON 响应，中文不乱码。
