## 2. 项目定位与北极星目标

### 2.1 一句话定义

VoiceSign 个性化 ASR 后台是一套用 Go 编写的独立后台服务，接收手机端传来的语音转写文本及原始音频，完成纠错、理解、个性化增强与标准化意图输出，并在使用中持续学习用户口语、专名、习惯与偏好，越用越懂用户。

### 2.2 与 VoiceSign Harness 的关系

本模块是纯粹独立后台，不并入 VoiceSign Harness 二进制，不与其耦合。

- ASR 后台：语音输入理解层，把用户说的变成机器能执行的意图。
- Harness：任务执行层，把意图变成真实结果。
- 两层职责不同、迭代节奏不同，必须解耦。
- ASR 后台通过标准接口输出意图 JSON，Harness 只是消费方之一。
- 未来手机 App、桌面端、其他设备等任何语音入口，都可复用同一个 ASR 后台。
- 两套代码独立仓库、独立部署、独立数据目录。
- 仅共享一套“意图 JSON 契约”，契约版本化、只增不改。

### 2.3 北极星目标

1. 越来越懂你：唯一理由。持续沉淀口语说法、专有名词、指代习惯、项目背景与偏好，个性化逐日增强，不依赖一次性配置。
2. 语音能力很强：纠错、标点、意图理解、控制语义、语音文字双通道都要可用可靠，体验对标豆包语音体系。
3. 响应极快：本地规则优先，模型兜底，处理链路微秒到毫秒级，说完即出结果。
4. 面向未来全双工：第一天就为全双工实时语音交互预留接口与数据模型，未来实现边说边理解、随时打断、实时反馈。

## 3. 核心设计思想：个性化三层递进

“越来越懂你”由三层能力逐层递进，每层都沉淀数据，数据反过来增强下一层。

| 层级 | 要解决的问题 | 沉淀的个性化数据 |
|---|---|---|
| L1 听清：文本纠错层 | 错字、同音字、口语碎片、专名错误。例如“季总”实际是“冀总”，“那个 module”实际是某项目名 | 自定义词典、纠错经验库、语音置信度标记 |
| L2 听懂：语义理解层 | 意图是什么，“它”指什么，“那个文档”是哪个，需结合上下文与历史 | 指代消解缓存（意图/域/权限/指代四元组）、对话上下文记忆、意图置信度 |
| L3 懂你：个人画像层 | 同一个词在不同人嘴里含义不同，同一件事在不同人场景下期望不同 | 用户偏好 prefs、项目地图 project-map、决策日志 decisions-log、领域知识、使用模式统计 |

核心公式：个性化 = 数据 × 规则 × 反馈闭环。

- 数据：每一次语音输入、用户确认、纠错都 append-only 留痕，形成私有复利资产。
- 规则：本地规则优先，包括词典、缓存、模式，零模型调用，保证速度与确定性。
- 反馈闭环：用户改一个字、确认一个指代、纠正一次识别，系统立即学习并固化，下次直接用。

## 4. 系统架构与处理管线

### 4.1 总体架构

手机端 App 采集音频，交给系统级或第三方 ASR 引擎（豆包/系统语音转文字），得到转写文本 input_raw。转写文本进入 VoiceSign 个性化 ASR 后台。后台按固定管线处理：

1. 留底 input_raw
2. 清洗语气词与口语碎片
3. 词典纠错
4. 上下文相关性匹配
5. 指代消解
6. 意图解析
7. 域建议与控制语义
8. 输出标准化意图 JSON

个性化数据层由 custom-dictionary、context-memory、user-profile、project-knowledge、exceptions-knowledge 等组成。最终通过 HTTP/WS 输出意图 JSON，交给 VoiceSign Harness 或其他消费方执行。

### 4.2 分层设计原则

- 单向依赖：管线 1→8 顺序固定，每层只依赖前一层输出，不反向调用。
- 本地规则优先，模型兜底：只有本地规则无法解决时才调用模型中心；模型调用带超时，超时即降级，绝不阻塞。
- 个性化数据与代码分离：全部个性化知识存 JSON/JSONL 文件，代码只提供处理逻辑，两者独立演进。
- 输出契约稳定：对外只输出标准意图 JSON，任何消费方按契约接入。

## 6. 关键模块实现计划

### 6.1 基础服务

- 交付 Go 单二进制、独立进程部署。
- 提供 HTTP 接口，预留 WebSocket。
- 所有配置使用 JSON，支持热加载。
- input_raw 永久 append-only 留底，不可篡改。
- 全链路轨迹 JSONL，记录每步耗时与命中来源。
- 本地规则路径 <1ms；模型兜底默认 3s 超时并并发保护，超时降级。

### 6.2 个性化词典

- 条目结构：raw_speech、target、scope、priority、source。
- 典型场景：人名纠错、项目名、专有名词、口头禅映射、方言口音修正。
- 支持语音指令动态增删改，例如“记住，冀总是冀中的冀”“删掉这个词”。
- 匹配策略：全词优先、最长匹配优先；同词多条命中取最高优先级；命中后标记来源与置信度。
- 纠错安全：高置信直接替换；低置信输出疑似纠错标记，交上层回问，绝不静默改错。
- 支持导出/导入，版本可回溯，采用 append-only + 快照。

### 6.3 文本清洗与纠错

- 去除 ASR 常见语气词、重复词、口误碎片，保留语义。
- 标点恢复必须闭环，作为 M7 真机遗留项处理。
- 对 ASR 低置信片段打标，进入纠错或回问流程，不直接执行。
- 清洗全过程保留原始输入，并输出清洗说明：改了哪里、为什么。

### 6.4 指代消解

- 第一层：词典/实体库。本地实体索引，零模型调用，100% 确定才替换。
- 第二层：上下文规则。读取最近 N 轮对话上下文，四元组缓存为意图、域、权限、指代，按规则匹配。
- 第三层：模型兜底。前两层无法解决时调用，输出带置信度。
- 低置信指代输出 need_disambiguate，触发回问确认，一屏一决策，只问一次。
- 用户确认后自动固化进缓存，下次复用；缓存带过期策略，如 7 天，并设容量上限。
- “打断/暂停/撤销”三个控制语义必须识别，并优先于普通指代处理。

### 6.5 上下文个性化记忆

- 数据源：user-preferences.json、project-map.json、decisions-log.jsonl、领域知识库。
- 用法：根据当前输入做相关性检索，只把相关片段注入解析过程，绝不全量加载历史。
- 检索结果只做理解增强，不直接改写原始输入；输出中携带命中的上下文来源。
- 异步低频更新，偏好/项目知识变更后增量更新索引，不阻塞实时请求。
- 使用模式统计：高频说法、常见意图、活跃时段、确认率，反哺词典权重与确认策略。

### 6.6 意图解析与标准化输出

- 输出标准化意图 JSON，字段包括 type、path、params、confidence、need_disambiguate、domain_suggestion、control。
- 意图类型对齐 Harness 现有 8 类加 ORCHESTRATE：EDIT、DEBUG、QUERY、TEST、COMMIT、DEPLOY、NOTE、ASK、ORCHESTRATE，兼容现有消费方。
- 控制语义独立输出，识别到“停/暂停/撤销”等直接返回控制意图，不进入业务执行。
- 规则优先分类，关键词/词典/模式先行，模型兜底；置信度低于阈值则回问或转 ASK。

### 6.7 域建议

- 根据意图与资源路径输出候选域建议，如 project、sandbox、vault-notes、global。
- 交由上层权限门禁裁决。
- 原则：默认拒绝；未知意图落到 global 只读域，绝不猜测高权限域。
- ASR 后台只建议、不授权；权限校验永远在消费方执行，本服务不绕过。

### 6.8 反馈学习闭环

| 反馈来源 | 学习动作 |
|---|---|
| 用户手动修改识别结果 | 差异分析，生成/强化词典条目，带来源与时间，下次直接命中 |
| 用户确认/纠正指代 | 固化四元组缓存，提升对应指代规则权重 |
| 用户确认/否认纠错建议 | 调整词典条目优先级；否认次数超阈值则降权或移除 |
| 下游执行反馈 | 写入异常知识库/使用模式统计，反哺词典与意图权重 |
| 高频反复确认 | 记录确认行为，缓存确认结果，限制重复弹窗；不可逆操作仍强制确认 |

所有学习动作均需 append-only 留痕，可审计、可回滚。

## 8. 接口契约与输出规范

- 传输：HTTP 接口；未来 WebSocket 支持全双工。
- 契约版本化、只增不改。

- 控制语义独立输出，不进入业务执行。
- 域建议只作为候选，最终权限由消费方裁决。
