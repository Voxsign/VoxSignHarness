# 个性化后台实现 · 实现计划

## 1. 文档目标

生成一个**独立运行的 Go 后台服务**，实现 ASR 识别文本的**个性化纠错与学习闭环**：用户教过的词（词典）、标错的词（黑名单）、确认过的映射（反馈），服务要能记住并在后续纠错中应用，做到"越来越懂你"。

本服务独立部署、自包含，不依赖任何外部框架或第三方服务。

## 2. 技术约束

- **语言**：Go。
- **依赖**：仅标准库，零第三方依赖，不允许引入外部包。
- **独立运行**：通过 flag 或环境变量配置
  - 监听地址（默认 `127.0.0.1`）
  - 数据目录（默认 `./data`）
- **数据持久化**：
  - `feedback` 使用 **JSONL append-only** 追加写入；
  - `dictionary` / `blacklist` 使用 JSON 文件读写。
- **代码质量**：不留 TODO / 占位 / 伪代码，自包含，可直接 `go build` 通过。
- **文本处理**：完整支持中文（UTF-8），响应中文不乱码。

## 3. 数据持久化设计

| 数据文件 | 格式 | 写入方式 | 说明 |
|---|---|---|---|
| `data/dictionary.json` | JSON | 全量覆盖写回 | 词典词条，含 `term` / `variants` / `category` / `source` |
| `data/blacklist.json` | JSON | 全量覆盖写回 | 黑名单词条，含 `term` / `note`；命中的词在纠错时跳过 |
| `data/feedback.jsonl` | JSONL | append-only 追加 | 每条反馈一行，含 `raw` / `corrected` / `accepted` / `reason` |

要求：**跨重启持久化**——服务重启后词典与黑名单数据仍然存在并可继续生效。

## 4. P0 能力清单（全部必须实现，逐条验收）

| # | 端点 | 行为 | 依赖数据 |
|---|---|---|---|
| 1 | `GET /v1/health` | 健康检查，返回 `{"ok":true}` | 无 |
| 2 | `GET /v1/dict` | 返回全量词典 JSON（`terms` 数组，元素含 `term` / `variants` / `category` / `source`） | `dictionary.json` |
| 3 | `POST /v1/term` | 增词，请求体 `{term, variants, source}`，写回词典并持久化 | `dictionary.json` |
| 4 | `POST /v1/correct` | 个性化纠错：输入 `{text}`，应用词典映射（如 `曼苏 → Mansour`）与黑名单拦截，返回 `{corrected, applied:[…]}` | 读 `dictionary` / `blacklist` |
| 5 | `POST /v1/process` | 意图分类 + 纠错：输入 `{text}`，返回 `{intent, corrected}`（`intent ∈ NOTE / QUERY / EDIT / …`，含纠错结果） | 读 `dictionary` / `blacklist` |
| 6 | `POST /v1/feedback` | 反馈学习：输入 `{raw, corrected, accepted, reason}`，**追加**写入 `feedback.jsonl`（append-only；`accepted=false` 时必带 `reason`） | `feedback.jsonl` |
| 7 | `POST /v1/blacklist` | 黑名单：输入 `{term, note}`，写入 `blacklist.json`（"这个改错了" → 后续纠错时跳过该词） | `blacklist.json` |
| 8 | 鉴权（可选） | 环境变量配置 token 时，校验请求头 `Authorization: Bearer <token>`；未配置则关闭鉴权 | 无 |

所有端点均返回 JSON 响应。

## 5. 核心行为说明

- **词典映射**：`/v1/correct` 与 `/v1/process` 在纠错阶段读取词典的 `variants → term` 映射关系，命中的替换项记入响应中的 `applied` 列表，便于调用方追溯哪些规则被应用。
- **黑名单拦截**：命中黑名单的词不做纠正（用户已明确"这个改错了"），避免重复修正错误。
- **反馈闭环**：`/v1/feedback` 仅做追加记录，不做就地修改；反馈数据是后续优化词典/黑名单的依据。
- **意图分类**：`/v1/process` 在纠错之外额外输出意图标签（`NOTE` / `QUERY` / `EDIT` 等），供上层路由使用。

## 6. 验收判据（真装配，不许桩）

1. `go build` 零错误（仅标准库）。
2. 服务启动后 `GET /v1/health` 返回 `{"ok":true}`。
3. `POST /v1/correct {"text":"你好 曼苏"}` → `corrected` 中含 `Mansour`（词典生效）。
4. `POST /v1/feedback` 后，`data/feedback.jsonl` **追加**一条记录（含 `raw` / `corrected` / `accepted` / `reason`）。
5. `POST /v1/term {"term":"Mansour","variants":["曼苏"]}` 后，`data/dictionary.json` 中含该词条（持久化）。
6. 重启服务后，词典 / 黑名单仍在（持久化跨重启）。
7. 所有端点 JSON 响应，中文不乱码。
