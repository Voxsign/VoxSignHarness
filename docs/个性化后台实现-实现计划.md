## 项目定位与核心目标

### 一句话定义

VoiceSign 个性化 ASR 后台是一套用 Go 编写的独立后台服务，接收手机端传来的语音转写文本及原始音频，完成“纠错 → 理解 → 个性化增强 → 输出标准化意图”，并在使用过程中持续学习用户的口语、专名、习惯与偏好，做到越用越懂用户。

### 与 VoiceSign Harness 的关系

- 本模块是纯粹独立后台，不并入 VoiceSign Harness 二进制，也不与其耦合。
- ASR 后台是语音输入理解层，负责把用户说的变成机器能执行的意图。
- Harness 是任务执行层，负责把意图变成真实结果。
- 两层职责不同、迭代节奏不同，必须解耦。
- ASR 后台通过标准接口对外输出意图 JSON，Harness 只是消费方之一。
- 未来任何语音入口，包括手机 App、桌面端、其他设备，都可以复用同一个 ASR 后台。
- 两套代码独立仓库、独立部署、独立数据目录。
- 仅共享一套意图 JSON 契约，契约版本化、只增不改。

### 北极星目标

- 越来越懂你：这是后台存在的唯一理由。系统在使用中持续沉淀口语说法、专有名词、指代习惯、项目背景与偏好，个性化能力逐日增强，不依赖一次性配置。
- 语音能力很强：识别结果纠错、标点、意图理解、控制语义、语音文字双通道都要可用、可靠，体验对标豆包语音体系。
- 响应极快：本地规则优先，模型兜底，处理链路微秒到毫秒级，语音说完即出结果，不出现长等待。
- 面向未来全双工：架构从第一天就为全双工实时语音交互留好接口与数据模型，未来实现边说边理解、随时打断、实时反馈。

## 核心设计思想

### 个性化三层递进

| 层级 | 要解决的问题 | 沉淀的个性化数据 |
| --- | --- | --- |
| L1 听清：文本纠错层 | 语音转写常有错字、同音字、口语碎片、专名错误。例如“季总”实际是“冀总”，“那个 module”实际是某个项目名 | 自定义词典，包括口语到标准写法的映射、纠错经验库、语音置信度标记 |
| L2 听懂：语义理解层 | 一句话意图是什么，“它”指什么，“那个文档”是哪个，需要结合上下文与历史 | 指代消解缓存，包括意图、域、权限、指代四元组；对话上下文记忆；意图置信度 |
| L3 懂你：个人画像层 | 同一个词在不同人嘴里含义不同，同一件事在不同人场景下期望不同，需要结合个人偏好、项目知识、决策历史做个性化理解 | 用户偏好 prefs、项目地图 project-map、决策日志 decisions-log、领域知识、使用模式统计 |

### 核心公式

个性化 = 数据 × 规则 × 反馈闭环

- 数据：每一次语音输入、每一次用户确认、每一次纠错都留痕，append-only，形成私有复利资产。
- 规则：本地规则优先，包括词典、缓存、模式，零模型调用，保证速度与确定性。
- 反馈闭环：用户改一个字、确认一个指代、纠正一次识别，系统立即学习并固化，下次直接用，越用越准。

### 实现原则

- 单向依赖：处理管线顺序固定，每一层只依赖前一层输出，不反向调用。
- 本地规则优先，模型兜底：只有本地规则无法解决时才调用模型中心。
- 模型调用带超时，超时即降级，绝不阻塞主流程。
- 个性化数据与代码分离：全部个性化知识存 JSON 或 JSONL 文件，代码只提供处理逻辑。
- 输出契约稳定：对外只输出标准意图 JSON，任何消费方按契约接入。

## 系统架构与模块划分

### 总体架构

手机端 App 负责语音交互界面，音频进入系统级或第三方 ASR 引擎，例如豆包或系统语音转文字。ASR 引擎输出转写文本 input_raw，进入 VoiceSign 个性化 ASR 后台。

后台处理管线如下：

1. 留底 input_raw
2. 清洗语气词
3. 词典纠错
4. 上下文相关性
5. 指代消解
6. 意图解析
7. 域建议与控制语义
8. 输出标准化意图 JSON

个性化数据层包括 custom-dictionary、context-memory、user-profile、project-knowledge、exceptions-knowledge。

后台通过 HTTP 或 WebSocket 向 VoiceSign Harness 或其他消费方输出意图 JSON。

### 处理管线

- 留底：每次输入永久保存 input_raw，append-only，不可篡改。
- 清洗：去除语气词、重复词、口误碎片，保留语义。
- 词典：执行个性化词典纠错，标记纠错来源与置信度。
- 上下文：读取最近对话上下文，做相关性检索。
- 指代：消解“它”“这个项目”“那个文档”等指代。
- 意图：解析用户意图，识别控制语义。
- 域建议：输出候选域，交由上层权限门禁裁决。
- 输出：生成标准化意图 JSON，包含 type、path、params、confidence、need_disambiguate、domain_suggestion、control 等字段。

### 分层设计原则

- 管线顺序固定，局部失败可降级，不反向依赖。
- 本地规则优先，模型兜底，模型调用必须设超时。
- 个性化数据独立于代码，支持独立演进、导入导出、版本回溯。
- 对外契约只增不改，确保 Harness、测试、未来应用稳定接入。

### 个性化词典 P0

实现要点：

- 条目结构包括 raw_speech、target、scope、priority、source。

- 典型场景包括人名、项目名、专有名词、口头禅映射、方言口音修正。

- 命中后标记纠错来源与置信度。
- 高置信纠错直接替换。
- 低置信纠错输出“疑似纠错”标记，交上层回问，绝不静默改错。
- 词典可导出、可导入，版本可回溯，append-only 加快照。

- 词典数据结构与存储。
- 词典匹配引擎。
- 语音指令词典增删改。

验收标准：

### 文本清洗与纠错 P0

实现要点：

- 去除 ASR 常见语气词、重复词、口误碎片，例如“嗯”“那个”“就是就是”。
- 保留语义，不改变用户原意。
- 标点恢复：为转写文本补全标点，提升下游意图解析准确率。
- M7 真机遗留项必须闭环。
- 识别置信度标记：对 ASR 引擎返回的低置信片段打标，进入纠错或回问流程，不直接执行。
- 清洗全过程保留原始输入。
- 输出带清洗说明，标明改了哪里、为什么。

交付物：

- 清洗规则引擎。
- 标点恢复模块。
- 置信度标记模块。
- 清洗说明输出。

验收标准：

- 语气词与碎片清理有效。
- 标点恢复提升意图解析准确率。
- 低置信片段不直接执行。

### 指代消解 P1

实现要点：

- 第一层：词典与实体库。例如“它等于最近提到的实体”“这个项目等于当前域项目”。
- 本地实体索引，零模型调用。
- 100% 确定才替换。
- 第二层：上下文规则。读取最近 N 轮对话上下文，四元组缓存包括意图、域、权限、指代，按规则匹配指代对象。
- 第三层：模型兜底。仅前两层无法解决时调用模型推断，输出带置信度。
- 低置信度指代输出 need_disambiguate 标记，触发回问确认。
- 回问原则：一屏一决策，只问一次。
- 用户确认后自动固化进缓存，下次直接复用。
- 缓存带过期策略，例如 7 天，并设容量上限。
- “打断”“暂停”“撤销”三个控制语义必须识别，并优先于普通指代处理。

交付物：

- 实体索引。
- 四元组缓存。
- 上下文规则匹配。
- 模型兜底与置信度。
- 回问确认与固化。

验收标准：

- 高确定指代本地消解。
- 低置信指代不猜测，触发回问。
- 确认后可复用。
- 控制语义优先识别。

### 上下文个性化记忆 P1

实现要点：

- 数据源包括 user-preferences.json、project-map.json、decisions-log.jsonl、领域知识库。

- 异步低频更新，偏好或项目知识变更后增量更新索引，不阻塞实时请求。
- 使用模式统计包括高频说法、常见意图、活跃时段、确认率。
- 统计结果反哺词典权重与确认策略。

交付物：

- 增量索引更新。
- 使用模式统计。

## 测试与验收计划

- 单元测试：词典匹配、清洗规则、标点恢复、指代消解、意图分类、域建议。
- 集成测试：HTTP 接口、未来 WebSocket、热加载、模型超时降级、并发保护。
- 数据测试：input_raw 留底、轨迹 JSONL 复现、词典导入导出、快照回溯。
- 个性化测试：用户纠正后下次命中、指代确认固化、否认降权、确认疲劳控制。
- 权限测试：未知意图落 global 只读、高权限域不猜测、权限裁决在消费方。
- 性能测试：本地规则路径小于 1ms，模型兜底超时降级。
- 验收重点：L1 听清准确，L2 听懂可用，L3 懂你持续增强，控制语义优先，回问不重复。

## 风险与待确认项

- 模型兜底依赖外部模型中心，需明确超时、并发、降级与失败策略。
- 意图 JSON 契约需要冻结首发版本，后续只增不改。
- 低置信纠错与指代回问可能造成确认疲劳，需要阈值与频控。
- 个性化数据持续增长，需要容量、归档、快照与清理策略。
- 全双工实时交互需要提前定义流式数据模型与打断语义。
- 域建议与权限边界必须持续保持“只建议、不授权”。
- 源材料末尾关于学习动作的完整策略需在评审中补充确认。
