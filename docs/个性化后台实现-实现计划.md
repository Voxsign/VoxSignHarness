## 2. 项目定位

VoiceSign 个性化 ASR 后台是一套用 Go 编写的独立后台服务。它接收手机端传来的语音转写文本及原始音频，完成“纠错 → 理解 → 个性化增强 → 输出标准化意图”，并在使用过程中持续学习用户的口语、专名、习惯与偏好，实现“越来越懂你”。

一句话定义：做一套“越来越懂你”的语音输入理解后台，独立服务、Go 实现、持续个性化、面向未来全双工。

## 3. 核心目标

- 越来越懂你：本后台存在的唯一理由。系统在使用中持续沉淀用户的口语说法、专有名词、指代习惯、项目背景与偏好，个性化能力逐日增强，不依赖一次性配置。
- 语音能力很强：识别结果的纠错、标点、意图理解、控制语义（打断/暂停/撤销）、语音文字双通道都要做到可用、可靠，体验对标豆包语音体系。
- 响应极快：本地规则优先，模型兜底，处理链路微秒到毫秒级，语音说完即出结果，不出现长等待。
- 面向未来全双工：架构从第一天就为“全双工实时语音交互”留好接口与数据模型，未来实现边说边理解、随时打断、实时反馈。

## 4. 与 VoiceSign Harness 的关系

本模块是纯粹独立的后台，不并入 VoiceSign Harness 二进制，也不与其耦合。

- ASR 后台 = 语音输入理解层：把用户说的变成机器能执行的意图。
- Harness = 任务执行层：把意图变成真实结果。
- 两层职责不同、迭代节奏不同，必须解耦。
- ASR 后台通过标准接口对外输出意图 JSON，Harness 只是它的一个消费方。
- 未来任何语音入口（手机 App、桌面端、其他设备）都可以复用同一个 ASR 后台。
- 两套代码独立仓库、独立部署、独立数据目录。
- 仅共享一套“意图 JSON 契约”，契约版本化、只增不改。

## 5. 核心设计思想：个性化的三层递进

“越来越懂你”不是口号，而是三层能力逐层递进、每一层都在沉淀数据、数据反过来增强下一层的闭环。

| 层级 | 要解决的问题 | 沉淀的个性化数据 |
| --- | --- | --- |
| L1 听清（文本纠错层） | 语音转写常有错字、同音字、口语碎片、专名错误。例：“季总”实际是“冀总”；“那个 module”实际是某个项目名。 | 自定义词典（口语→标准写法）、纠错经验库、语音置信度标记。 |
| L2 听懂（语义理解层） | 一句话的意图是什么？“它”指什么？“那个文档”是哪个？结合上下文与历史才能正确理解。 | 指代消解缓存（意图/域/权限/指代 四元组）、对话上下文记忆、意图置信度。 |
| L3 懂你（个人画像层） | 同一个词在不同人嘴里含义不同；同一件事在不同人场景下期望不同。需要结合个人偏好、项目知识、决策历史做个性化理解。 | 用户偏好 prefs、项目地图 project-map、决策日志 decisions-log、领域知识、使用模式统计。 |

核心公式：个性化 = 数据 × 规则 × 反馈闭环。

- 数据：每一次语音输入、每一次用户确认、每一次纠错都留痕（append-only），形成私有复利资产。
- 规则：本地规则（词典、缓存、模式）优先，零模型调用，保证速度与确定性。
- 反馈闭环：用户改一个字、确认一个指代、纠正一次识别，系统立即学习并固化，下次直接用，越用越准。

## 6. 系统架构

总体链路：

手机端 App（语音交互界面）→ 音频 → 系统级/第三方 ASR 引擎（豆包/系统语音转文字）→ 转写文本 input_raw → VoiceSign 个性化 ASR 后台（Go，独立服务）→ 意图 JSON（HTTP/WS）→ VoiceSign Harness（执行层）/ 其他消费方。

后台内部处理管线：

1. 留底 input_raw
2. 清洗语气词
3. 词典纠错
4. 上下文相关性
5. 指代消解
6. 意图解析
7. 域建议 + 控制语义
8. 输出标准化意图 JSON

个性化数据层：

- custom-dictionary
- context-memory
- user-profile
- project-knowledge
- exceptions-knowledge

输出标准意图对象字段包括：type、path、params、confidence，以及可选 need_disambiguate、domain_suggestion、control。

## 7. 分层设计原则

- 单向依赖：管线 1→8 顺序固定，每一层只依赖前一层输出，不反向调用。
- 本地规则优先，模型兜底：只有本地规则无法解决时，才调用模型中心；模型调用带超时，超时即降级，绝不阻塞。
- 个性化数据与代码分离：全部个性化知识存 JSON/JSONL 文件，代码只提供处理逻辑，两者独立演进。
- 输出契约稳定：对外只输出标准意图 JSON，任何消费方（Harness、测试、未来应用）按契约接入。

## 8. P0 基础服务能力实现计划

需求目标：

- Go 编写、独立进程/二进制部署，与 Harness 无代码耦合。
- 提供 HTTP 接口，并预留未来 WebSocket。

- 配置全部 JSON 文件，不用 YAML；支持热加载，词典/偏好变更即时生效。

2. 实现 HTTP 服务骨架，预留 WebSocket 接口抽象。
3. 实现 input_raw append-only 留底模块。
4. 实现全链路轨迹 JSONL 记录器，统一耗时、命中来源、处理结果字段。
5. 实现 JSON 配置加载与热加载机制。
6. 实现模型调用超时、并发保护与降级策略。
7. 建立性能基线测试，验证本地规则路径 < 1ms。

验收标准：

- 服务可独立启动、独立部署。
- input_raw 不可篡改，处理轨迹可复现。
- 配置变更无需重启即可生效。
- 模型超时不阻塞主链路。

## 10. P0 文本清洗与纠错实现计划

- 识别置信度标记：对 ASR 引擎返回的低置信片段打标，进入纠错或回问流程，不直接执行。

实现任务：

3. 接入 ASR 置信度字段，对低置信片段打标。

- 每次清洗可解释、可归因。

## 11. P1 指代消解实现计划

层级机制：

- 第一层：词典/实体库。“它=最近提到的实体”“这个项目=当前域项目”，本地实体索引，零模型调用，100% 确定才替换。
- 第二层：上下文规则。读取最近 N 轮对话上下文（四元组缓存：意图、域、权限、指代），按规则匹配指代对象。
- 第三层：模型兜底。仅前两层无法解决时调用模型推断，输出带置信度。

实现任务：

1. 实现本地实体索引与明确指代替换。
2. 实现最近 N 轮对话上下文缓存，采用四元组结构。
3. 实现上下文规则匹配引擎。
4. 实现模型兜底接口，带超时与置信度输出。
5. 低置信度指代输出 need_disambiguate 标记，触发回问确认（一屏一决策，只问一次）。
6. 用户确认后自动固化进缓存，下次直接复用。
7. 缓存带过期策略（如 7 天）与容量上限。
8. “打断/暂停/撤销”三个控制语义必须识别，并优先于普通指代处理。

验收标准：

- 明确指代零模型调用即可消解。
- 上下文可支持最近 N 轮规则消解。
- 低置信指代触发一次确认，不重复打扰。
- 控制语义优先于普通指代。

- 使用模式统计：高频说法、常见意图、活跃时段、确认率，反哺词典权重与确认策略。

实现任务：

1. 建立 user-preferences.json、project-map.json、decisions-log.jsonl 读取与索引。
2. 实现相关性检索模块，按当前输入召回相关片段。
3. 在解析过程中注入相关片段，并记录命中来源。
4. 实现异步增量更新索引任务。
5. 实现使用模式统计模块，输出高频说法、常见意图、活跃时段、确认率。
6. 将统计结果反哺词典权重与确认策略。

验收标准：

- 不全量加载历史，只注入相关片段。
- 上下文增强不污染原始输入。
- 索引更新不阻塞实时请求。
- 使用模式统计可影响词典权重与确认策略。

## 14. P1 域（Space）建议实现计划

3. 未知意图默认建议 global 只读域。
4. 与 Harness 的 Space.Check 通过契约对接，明确职责边界。

验收标准：

- 域建议不越权、不授权。
- 未知意图不猜测高权限域。
- 权限校验始终在消费方执行。

- 个性化数据全部使用 JSON/JSONL，代码与数据分离。
- input_raw append-only，不可篡改。
- 轨迹日志 JSONL，记录每一步处理、耗时、命中来源。
- 词典支持 append-only + 快照，可导出/导入、版本回溯。
- 指代缓存四元组：意图、域、权限、指代；带过期策略（如 7 天）与容量上限。
- 学习动作 append-only，携带来源、时间、置信度。

## 18. 性能与可靠性基线

- 本地规则路径（无模型调用）：目标 < 1ms。
- 含模型兜底路径：默认超时 3s，带并发保护。
- 超时自动降级，绝不阻塞主链路。
- 异步低频更新索引，不阻塞实时请求。
- 高置信纠错直接替换；低置信输出“疑似纠错”或 need_disambiguate，交上层回问。
- 权限默认拒绝；未知意图落 global 只读域。

## 19. 验收标准汇总

- 独立服务：Go 单二进制、独立部署、与 Harness 无代码耦合。
- 契约稳定：意图 JSON 只增不改，消费方可按契约接入。
- 个性化闭环：数据留痕、规则优先、反馈学习、越用越准。
- 语音能力：纠错、标点、意图理解、控制语义、双通道可用可靠。
- 响应极快：本地规则路径 < 1ms，模型兜底不阻塞。
- 安全边界：ASR 后台只建议域、不授权；权限校验在 Harness 的 Space.Check。
- 可复现：全链路轨迹 JSONL，带耗时与命中来源。
- 可演进：全双工接口与数据模型预留。

## 20. 风险与后续评审关注

- 模型兜底路径的选型、超时参数与降级策略需在联调阶段校准。
- 标点恢复作为 M7 真机遗留项，必须专项验证闭环。
- 指代缓存过期与容量上限需结合实际使用频率调参。
- 确认疲劳策略需与不可逆操作强制确认规则做冲突评审。
- 全双工实时交互的接口细节与数据模型需按架构预留章节继续展开。
- 意图 JSON 契约变更必须版本化，只增不改，避免破坏 Harness 等消费方。
