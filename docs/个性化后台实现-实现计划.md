## 1. 项目定位与核心目标

**一句话定义**

VoiceSign 个性化 ASR 后台是一套用 Go 编写的独立后台服务，接收手机端传来的语音转写文本及原始音频，完成「纠错 → 理解 → 个性化增强 → 输出标准化意图」，并在使用过程中持续学习用户的口语、专名、习惯与偏好，越用越懂用户。

**与 VoiceSign Harness 的关系**

本模块是纯粹独立的后台，不并入 VoiceSign Harness 二进制，也不与其耦合。

- ASR 后台 = 语音输入理解层：把用户说的变成机器能执行的意图。
- Harness = 任务执行层：把意图变成真实结果。
- 两层职责不同、迭代节奏不同，必须解耦。
- ASR 后台通过标准接口对外输出意图 JSON，Harness 只是消费方之一。
- 未来手机 App、桌面端、其他设备等任何语音入口，都可复用同一个 ASR 后台。
- 两套代码独立仓库、独立部署、独立数据目录；仅共享「意图 JSON 契约」。
- 契约版本化，只增不改。

**北极星目标**

1. **越来越懂你**：系统持续沉淀口语说法、专有名词、指代习惯、项目背景与偏好，个性化能力逐日增强，不依赖一次性配置。
2. **语音能力很强**：纠错、标点、意图理解、控制语义、语音文字双通道均可用、可靠，体验对标豆包语音体系。
3. **响应极快**：本地规则优先，模型兜底，处理链路微秒到毫秒级，语音说完即出结果，不出现长等待。
4. **面向未来全双工**：架构从第一天就为全双工实时语音交互预留接口与数据模型，支持边说边理解、随时打断、实时反馈。

## 2. 核心设计思想：个性化三层递进

「越来越懂你」不是口号，而是三层能力逐层递进、每层沉淀数据、数据反哺下一层的闭环。

| 层级 | 要解决的问题 | 沉淀的个性化数据 |
|---|---|---|
| L1 听清：文本纠错层 | 语音转写常有错字、同音字、口语碎片、专名错误。例如「季总」实际是「冀总」，「那个 module」实际是某个项目名。 | 自定义词典（口语→标准写法）、纠错经验库、语音置信度标记。 |
| L2 听懂：语义理解层 | 一句话的意图是什么？「它」指什么？「那个文档」是哪个？需结合上下文与历史。 | 指代消解缓存（意图/域/权限/指代 四元组）、对话上下文记忆、意图置信度。 |
| L3 懂你：个人画像层 | 同一个词在不同人嘴里含义不同；同一件事在不同人场景下期望不同。需结合偏好、项目知识、决策历史。 | 用户偏好 prefs、项目地图 project-map、决策日志 decisions-log、领域知识、使用模式统计。 |

**核心公式**

个性化 = 数据 × 规则 × 反馈闭环。

- 数据：每一次语音输入、用户确认、纠错都留痕（append-only），形成私有复利资产。
- 规则：本地规则（词典、缓存、模式）优先，零模型调用，保证速度与确定性。
- 反馈闭环：用户改一个字、确认一个指代、纠正一次识别，系统立即学习并固化，下次直接命中。

## 3. 系统架构（独立服务）

**总体架构**

管线顺序固定为：

手机端音频 → 系统级/第三方 ASR 引擎 → 转写文本 `input_raw` → VoiceSign 个性化 ASR 后台 → 意图 JSON → Harness / 其他消费方。

后台内部处理链路：

1. 留底 `input_raw`
2. 清洗语气词
3. 词典纠错
4. 上下文相关性
5. 指代消解
6. 意图解析
7. 域建议 + 控制语义
8. 输出标准化意图 JSON：`{type,path,params,confidence}`

个性化数据层包括：

`custom-dictionary` / `context-memory` / `user-profile` / `project-knowledge` / `exceptions-knowledge`。

**分层设计原则**

- 单向依赖：管线 1→8 顺序固定，每一层只依赖前一层输出，不反向调用。
- 本地规则优先，模型兜底：只有本地规则无法解决时才调用模型中心；模型调用带超时，超时即降级，绝不阻塞。
- 个性化数据与代码分离：全部个性化知识存 JSON/JSONL 文件，代码只提供处理逻辑，两者独立演进。
- 输出契约稳定：对外只输出标准意图 JSON，任何消费方按契约接入。

## 4. 功能需求与开发范围

### 4.1 基础服务能力 P0

| 需求项 | 具体要求 |
|---|---|
| 独立服务 | Go 编写、独立进程/二进制部署，与 Harness 无代码耦合；提供 HTTP 接口 + 未来 WebSocket。 |
| 原始留底 | 每次输入永久保存 `input_raw`，append-only，不可篡改；后续纠错/清洗均为派生，便于归因。 |
| 全链路日志 | 每一步处理写入轨迹 JSONL，带耗时与命中来源，可完全复现。 |
| 性能基线 | 本地规则路径无模型调用，目标 < 1ms；含模型兜底路径设超时，默认 3s，并发保护，超时自动降级。 |
| 配置 | 全部 JSON 文件，不用 YAML；支持热加载，词典/偏好变更即时生效。 |

### 4.2 个性化词典 P0：L1 听清核心

- 条目结构：`{raw_speech: 口语/错词, target: 标准写法, scope: 全局|项目, priority: 优先级, source: 来源}`。
- 典型场景：人名、项目名、专有名词、口头禅映射、方言口音修正。
- 支持语音指令动态增删改：用户说「记住，冀总是冀中的冀」「删掉这个词」，后台解析为词典操作并落盘。
- 匹配策略：全词优先、最长匹配优先；同词多条命中取最高优先级；命中后标记纠错来源与置信度。
- 纠错安全：高置信纠错直接替换；低置信纠错输出「疑似纠错」标记，交上层回问，绝不静默改错。
- 词典可导出/导入，版本可回溯，采用 append-only + 快照。

### 4.3 文本清洗与纠错 P0

- 去除 ASR 常见语气词、重复词、口误碎片，保留语义。
- 标点恢复：为转写文本补全标点，提升下游意图解析准确率；M7 真机遗留项必须闭环。
- 识别置信度标记：对 ASR 引擎返回的低置信片段打标，进入纠错或回问流程，不直接执行。
- 清洗全过程保留原始输入，输出带清洗说明：改了哪里、为什么。

### 4.4 指代消解 P1：L2 听懂核心

| 层级 | 机制 |
|---|---|
| 第一层 | 词典/实体库：本地实体索引，零模型调用，100% 确定才替换。 |
| 第二层 | 上下文规则：读取最近 N 轮对话上下文，按四元组缓存 `{意图, 域, 权限, 指代}` 匹配指代对象。 |
| 第三层 | 模型兜底：仅前两层无法解决时调用模型推断，输出带置信度。 |

- 低置信度指代输出 `need_disambiguate` 标记，触发回问确认；一屏一决策，只问一次。
- 用户确认后自动固化进缓存，下次直接复用；缓存带过期策略，如 7 天，并有容量上限。
- 「打断/暂停/撤销」三个控制语义必须识别，并优先于普通指代处理。

### 4.5 上下文个性化记忆 P1：L3 懂你核心

- 数据源：`user-preferences.json`、`project-map.json`、`decisions-log.jsonl`、领域知识库。
- 用法：根据当前输入做相关性检索，只把相关片段注入解析过程，绝不全量加载历史。
- 检索结果只做理解增强，不直接改写原始输入；输出 JSON 中携带命中的上下文来源。
- 异步低频更新：偏好/项目知识变更后增量更新索引，不阻塞实时请求。
- 使用模式统计：高频说法、常见意图、活跃时段、确认率，反哺词典权重与确认策略。

### 4.6 意图解析与标准化输出 P0

- 输出标准化意图 JSON：`{type, path, params, confidence, need_disambiguate?, domain_suggestion?, control?}`。
- 意图类型对齐 Harness 现有 8 类 + ORCHESTRATE：EDIT / DEBUG / QUERY / TEST / COMMIT / DEPLOY / NOTE / ASK / ORCHESTRATE，兼容现有消费方。
- 控制语义独立输出：识别到「停/暂停/撤销」等，直接返回控制意图，不进入业务执行。
- 规则优先分类：关键词/词典/模式；模型兜底；置信度低于阈值 → 回问或转 ASK。

### 4.7 域建议 P1

- 根据意图与资源路径输出候选域建议，如 project / sandbox / vault-notes / global，交由上层权限门禁裁决。
- 原则：默认拒绝；未知意图落到 global 只读域，绝不猜测高权限域。
- ASR 后台只建议、不授权；权限校验永远在消费方 Harness 的 Space.Check 执行，本服务不绕过。

### 4.8 反馈学习闭环 P1：越用越懂你的机制

| 反馈来源 | 学习动作 |
|---|---|
| 用户手动修改识别结果，语音文字双通道 | 差异分析 → 生成/强化词典条目，带来源与时间 → 下次直接命中。 |
| 用户确认/纠正指代 | 固化四元组缓存，提升对应指代规则权重。 |
| 用户确认/否认纠错建议 | 调整词典条目优先级；否认次数超阈值 → 条目降权或移除。 |
| 下游执行反馈，Harness 报错/成功 | 写入异常知识库 / 使用模式统计，反哺词典与意图权重。 |
| 高频反复确认，确认疲劳 | 记录确认行为，缓存确认结果、限制重复弹窗；不可逆操作仍强制确认。 |

所有学习动作必须 append-only 留痕，支持审计、回滚与来源追踪。
