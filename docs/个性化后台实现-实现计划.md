## 三、缺口清单（下一轮必须补齐）

1. **POST `/v1/correct`**：接收 `{text}` → 应用词典映射（如 曼苏→Mansour）+ 黑名单拦截 → 返回 `{corrected, applied}`。
2. **POST `/v1/term`**：接收 `{term, variants, source}` → 写入并持久化 `dictionary.json`。
3. **GET `/v1/dict`**：返回全量词典 JSON。
4. **POST `/v1/feedback`**：接收 `{raw, corrected, accepted, reason}` → 追加写入 `feedback.jsonl`（append-only）；`reason` 必带，为空时记为 `user_marked_wrong`。
5. **POST `/v1/blacklist`**：接收 `{term, note}` → 写入 `blacklist.json`；纠错时跳过该词。
6. **持久化跨重启**：`dictionary.json` / `blacklist.json` 在服务启动时加载，重启后数据不丢。
7. **process 纠错生效**：教词（曼苏→Mansour）后，`/v1/process` 对包含"曼苏"的文本，其 `corrected_text` 应返回 "Mansour"。

## 四、接口实现规格

### 4.1 GET /v1/health

- 现状：已实现，返回 HTTP 200 / OK。
- 要求：保持可用，不得在改造中回归。

### 4.2 POST /v1/correct

- 请求：`{text}`
- 逻辑：套用词典映射（如 曼苏→Mansour），并按黑名单进行拦截（命中黑名单的词不纠错）。
- 响应：`{corrected, applied}`

### 4.3 POST /v1/term

- 请求：`{term, variants, source}`
- 逻辑：写入词典并落盘 `dictionary.json`。
- 响应：HTTP 200，语义正确。

### 4.4 GET /v1/dict

- 逻辑：读取并返回全量词典 JSON。

### 4.5 POST /v1/feedback

- 请求：`{raw, corrected, accepted, reason}`
- 逻辑：以 append-only 方式追加写入 `feedback.jsonl`。
- 约束：`reason` 为必带字段；若为空，则记录为 `user_marked_wrong`。

### 4.6 POST /v1/blacklist

- 请求：`{term, note}`
- 逻辑：写入 `blacklist.json`；纠错流程在遇到该词时跳过。

### 4.7 POST /v1/process

- 现状：返回 HTTP 200，纠错引擎在位但无词典数据源可供调用。
- 目标：教词（曼苏→Mansour）后，对含"曼苏"文本，`corrected_text` 返回 "Mansour"；`intent` 等既有字段行为保持不变。

## 五、数据持久化要求

| 文件 | 写入方 | 读取时机 | 关键约束 |

| `dictionary.json` | POST `/v1/term` | 服务启动时加载 | 重启后词典不丢 |
| `blacklist.json` | POST `/v1/blacklist` | 服务启动时加载 | 重启后黑名单不丢，纠错时跳过命中词 |
