## 2. 项目目标

生成一个独立运行的 Go 后台服务，实现 ASR 识别文本的个性化纠错与学习闭环。用户教过的词（词典）、标错的词（黑名单）、确认过的映射（反馈），服务要能记住并在后续纠错中应用——“越来越懂你”。

## 3. 技术约束

- Go 语言，仅标准库，零第三方依赖（不许用外部包）。
- 可独立运行：通过 flag 或环境变量配置监听地址（默认 127.0.0.1）与数据目录（默认 ./data）。
- 数据持久化：feedback 用 JSONL append-only；dictionary/blacklist 用 JSON 文件。
- 代码不留 TODO/占位/伪代码，自包含、可直接 go build 通过。
- 中文文本处理（UTF-8）。

## 5. 接口与数据契约

### 5.1 健康检查

- `GET /v1/health`
- 响应：`{"ok":true}`

### 5.2 词典读取

- `GET /v1/dict`
- 返回全量词典 JSON
- terms 数组项字段：`term`、`variants`、`category`、`source`
- 数据文件：`dictionary.json`

### 5.3 词典增词

- `POST /v1/term`
- 请求体：`term`、`variants`、`source`
- 行为：写回词典并持久化
- 数据文件：`dictionary.json`

### 5.4 个性化纠错

- `POST /v1/correct`
- 请求体：`{text}`
- 行为：应用词典映射（如 曼苏→Mansour）与黑名单拦截
- 响应：`{corrected, applied:[…]}`
- 读取：`dictionary.json`、`blacklist.json`

### 5.5 意图分类与纠错

- `POST /v1/process`
- 请求体：`{text}`
- 行为：意图分类 + 纠错
- 响应：`{intent, corrected}`
- intent 取值：`NOTE`、`QUERY`、`EDIT`、`…`
- 读取：`dictionary.json`、`blacklist.json`

### 5.6 反馈学习

- `POST /v1/feedback`
- 请求体：`{raw, corrected, accepted, reason}`
- 行为：追加写入 `feedback.jsonl`（append-only）
- 约束：`accepted` 为假时必带 `reason`
- 数据文件：`feedback.jsonl`

### 5.7 黑名单

- `POST /v1/blacklist`
- 请求体：`{term, note}`
- 行为：写入 `blacklist.json`；纠错时跳过该词
- 数据文件：`blacklist.json`

### 5.8 鉴权（可选）

- 环境变量配置 token 时启用
- 请求头校验：`Authorization: Bearer <token>`
- 未配置则关闭鉴权

## 6. 数据持久化设计

- `dictionary.json`：存储词典词条，字段包括 `term`、`variants`、`category`、`source`。
- `blacklist.json`：存储黑名单词条，字段包括 `term`、`note`。
- `feedback.jsonl`：每行一条 JSON 记录，append-only，字段包括 `raw`、`corrected`、`accepted`、`reason`。
- 数据目录默认 `./data`，可通过 flag 或环境变量配置。
- 重启服务后词典/黑名单仍在，满足持久化跨重启要求。

## 7. 运行与配置

- 监听地址：默认 `127.0.0.1`，可通过 flag 或环境变量配置。
- 数据目录：默认 `./data`，可通过 flag 或环境变量配置。
- 鉴权 token：通过环境变量配置；未配置时不校验。
- 所有端点返回 JSON 响应，中文不乱码。
