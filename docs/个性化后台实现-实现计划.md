# 个性化后台实现-实现计划

## 1. 项目定位与核心目标

### 1.1 一句话定义
VoiceSign 个性化 ASR 后台：一套用 Go 编写的独立后台服务，接收手机端传来的语音转写文本（及原始音频），完成「纠错 → 理解 → 个性化增强 → 输出标准化意图」，并且在使用过程中持续学习用户的口语、专名、习惯与偏好，越用越懂用户。

### 1.2 与 VoiceSign Harness 的关系
本模块是纯粹独立的后台，不并入 VoiceSign Harness 二进制，也不与其耦合。ASR 后台负责语音输入理解，Harness 负责任务执行，两者职责不同、迭代节奏不同，必须解耦。

### 1.3 北极星目标
- **越来越懂你**：系统在使用中持续沉淀用户的口语说法、专有名词、指代习惯，个性化能力逐日增强。
- **语音能力很强**：识别结果的纠错、标点、意图理解等要做到可用、可靠。
- **响应极快**：处理链路微秒到毫秒级，语音说完即出结果。
- **面向未来全双工**：架构为全双工实时语音交互留好接口与数据模型。

## 2. 核心设计思想：个性化的三层递进

### 2.1 三层能力
- **L1 听清（文本纠错层）**：处理语音转写中的错字、同音字、口语碎片。
- **L2 听懂（语义理解层）**：理解一句话的意图，结合上下文与历史。
- **L3 懂你（个人画像层）**：结合个人偏好、项目知识、决策历史进行个性化理解。

### 2.2 核心公式
个性化 = 数据 × 规则 × 反馈闭环

## 3. 系统架构（独立服务）

### 3.1 总体架构
```
┌──────────────────┐ 音频 ┌────────────────────────────┐
│ 手机端 App │ ────────────→ │ 系统级/第三方 ASR 引擎 │
└──────────────────┘ └────────────┬───────────────┘
 │ 转写文本 (input_raw)
 ▼
┌─────────────────────────────────────────────────────────────────┐
│ VoiceSign 个性化 ASR 后台（Go，独立服务） │
│ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌──────────┐ │
│ │ 1 留底 │→│ 2 清洗 │→│ 3 词典 │→│ 4 上下文 │→│ 5 指代 │ │
│ └─────────┘ └─────────┘ └─────────┘ └─────────┘ └──────────┘ │
│ ┌─────────┐ ┌─────────┐ ┌──────────────────────────────────┐ │
│ │ 6 意图 │→│ 7 域建议 │→│ 8 输出标准化意图 JSON │ │
│ └─────────┘ └─────────┘ └──────────────────────────────────┘ │
│ 个性化数据层：custom-dictionary / context-memory / user-profile │
│ / project-knowledge / exceptions-knowledge │
└────────────────────────────────────┬────────────────────────────┘
 │ 意图 JSON（HTTP/WS）
 ▼
 VoiceSign Harness（执行层） / 其他消费方
```

### 3.2 分层设计原则
- 单向依赖：管线顺序固定，每一层只依赖前一层输出。
- 本地规则优先，模型兜底：只有本地规则无法解决时，才调用模型中心。
- 个性化数据与代码分离：个性化知识存 JSON 文件，代码只提供处理逻辑。
- 输出契约稳定：对外只输出标准意图 JSON。

## 4. 功能需求清单（开发实施范围）

### 4.1 基础服务能力 P0
- **独立服务**：Go 编写、独立进程/二进制部署。
- **原始留底**：每次输入永久保存，append-only。
- **全链路日志**：每一步处理写入轨迹 JSONL。
- **性能基线**：本地规则路径目标 < 1ms。

### 4.2 个性化词典 P0
- **条目结构**：包含口语/错词、标准写法、优先级等。
- **支持动态增删改**：用户可通过语音指令操作词典。
- **匹配策略**：全词优先、最长匹配优先。

### 4.3 文本清洗与纠错 P0
- **去除语气词**：保留语义，提升意图解析准确率。
- **标点恢复**：补全标点，提升下游意图解析准确率。

### 4.4 指代消解 P1
- **层级机制**：本地实体索引、上下文规则、模型兜底。

### 4.5 上下文个性化记忆 P1
- **数据源**：用户偏好、项目地图、历史决策等。
- **用法**：相关性检索，增强理解。

### 4.6 意图解析与标准化输出 P0
- **输出标准化意图 JSON**：包含类型、路径、参数等。

### 4.7 域（Space）建议 P1
- **候选域建议**：根据意图与资源路径输出。

### 4.8 反馈学习闭环 P1
- **反馈来源**：用户手动修改、确认指代、下游执行反馈等。
