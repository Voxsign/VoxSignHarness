## 项目定位与核心目标

### 一句话定义

VoiceSign 个性化 ASR 后台是一套用 Go 编写的独立后台服务，接收手机端传来的语音转写文本及原始音频，完成“纠错 → 理解 → 个性化增强 → 输出标准化意图”，并在使用过程中持续学习用户的口语、专名、习惯与偏好，越用越懂用户。

### 与 VoiceSign Harness 的关系

本模块是纯粹独立的后台，不并入 VoiceSign Harness 二进制，也不与其耦合。

- ASR 后台是语音输入理解层，把用户说的变成机器能执行的意图。
- Harness 是任务执行层，把意图变成真实结果。
- 两层职责不同、迭代节奏不同，必须解耦。
- ASR 后台通过标准接口对外输出意图 JSON，Harness 只是其中一个消费方。
- 未来任何语音入口，包括手机 App、桌面端、其他设备，都可以复用同一个 ASR 后台。
- 两套代码独立仓库、独立部署、独立数据目录。
- 仅共享一套“意图 JSON 契约”，契约版本化、只增不改。

### 北极星目标

1. 越来越懂你：系统在使用中持续沉淀口语说法、专有名词、指代习惯、项目背景与偏好，个性化能力逐日增强，不依赖一次性配置。
2. 语音能力很强：识别结果纠错、标点、意图理解、控制语义、语音文字双通道都要可用可靠，体验对标豆包语音体系。
3. 响应极快：本地规则优先，模型兜底，处理链路微秒到毫秒级，语音说完即出结果，不出现长等待。
4. 面向未来全双工：架构从第一天就为全双工实时语音交互留好接口与数据模型，未来实现边说边理解、随时打断、实时反馈。

## 核心设计思想：个性化三层递进

“越来越懂你”由三层能力逐层递进构成，每一层都在沉淀数据，数据反过来增强下一层。

| 层级 | 要解决的问题 | 沉淀的个性化数据 |
|---|---|---|
| L1 听清：文本纠错层 | 语音转写常有错字、同音字、口语碎片、专名错误。例如“季总”实际是“冀总”，“那个 module”实际是某个项目名。 | 自定义词典、纠错经验库、语音置信度标记。 |
| L2 听懂：语义理解层 | 一句话的意图是什么，“它”指什么，“那个文档”是哪个，需要结合上下文与历史。 | 指代消解缓存，包含意图、域、权限、指代四元组；对话上下文记忆；意图置信度。 |
| L3 懂你：个人画像层 | 同一个词在不同人嘴里含义不同，同一件事在不同人场景下期望不同，需要结合个人偏好、项目知识、决策历史做个性化理解。 | 用户偏好 prefs、项目地图 project-map、决策日志 decisions-log、领域知识、使用模式统计。 |

核心公式：个性化 = 数据 × 规则 × 反馈闭环。

- 数据：每一次语音输入、每一次用户确认、每一次纠错都留痕，append-only，形成私有复利资产。
- 规则：本地规则优先，包括词典、缓存、模式，零模型调用，保证速度与确定性。
- 反馈闭环：用户改一个字、确认一个指代、纠正一次识别，系统立即学习并固化，下次直接用，越用越准。

## 系统架构与分层原则

### 总体架构

手机端 App 将音频交给系统级或第三方 ASR 引擎，例如豆包或系统语音转文字。ASR 引擎输出转写文本 input_raw，进入 VoiceSign 个性化 ASR 后台。

后台处理管线固定为：

1. 留底 input_raw
2. 清洗语气词与口语碎片
3. 词典纠错
4. 上下文相关性
5. 指代消解
6. 意图解析
7. 域建议与控制语义
8. 输出标准化意图 JSON

个性化数据层包括 custom-dictionary、context-memory、user-profile、project-knowledge、exceptions-knowledge。最终通过 HTTP 或 WebSocket 将意图 JSON 输出给 VoiceSign Harness 执行层或其他消费方。

### 分层设计原则

- 单向依赖：管线 1→8 顺序固定，每一层只依赖前一层输出，不反向调用。
- 本地规则优先，模型兜底：只有本地规则无法解决时，才调用模型中心。模型调用带超时，超时即降级，绝不阻塞。
- 个性化数据与代码分离：全部个性化知识存 JSON 或 JSONL 文件，代码只提供处理逻辑，两者独立演进。
- 输出契约稳定：对外只输出标准意图 JSON，任何消费方按契约接入。

## P0 基础服务能力实现计划

### 独立服务

- 使用 Go 编写。
- 独立进程或独立二进制部署。
- 与 Harness 无代码耦合。
- 提供 HTTP 接口，未来增加 WebSocket。

### 原始留底

- 每次输入永久保存 input_raw，即原始转写文本。
- 采用 append-only，不可篡改。
- 后续所有纠错与清洗都是在其上的派生，便于归因。

### 全链路日志

- 每一步处理都写入轨迹 JSONL。
- 处理步骤包括：留底、清洗、纠错、上下文、指代、意图、域建议。

- 要求可完全复现。

### 性能基线

- 本地规则路径，无模型调用，目标小于 1ms。
- 含模型兜底路径设置超时，默认 3s，并做并发保护。
- 超时自动走降级。

### 配置与热加载

- 配置全部使用 JSON 文件，不用 YAML。
- 支持热加载，词典与偏好变更即时生效。

## P0 文本清洗与纠错实现计划

### 语气词、重复词、口误碎片清理

- 去除 ASR 常见语气词、重复词、口误碎片，例如“嗯”“那个”“就是就是”。
- 清理过程必须保留语义。

### 标点恢复

- 为转写文本补全标点。
- 提升下游意图解析准确率。
- 标点恢复属于 M7 真机遗留项，必须闭环。

### 识别置信度标记

- 对 ASR 引擎返回的低置信片段打标。
- 低置信片段进入纠错或回问流程。
- 不直接执行低置信内容。

### 原始输入保留与清洗说明

- 清洗全过程保留原始输入。
- 输出带清洗说明，说明改了哪里、为什么。

## P1 指代消解实现计划

### 三层机制

第一层：词典或实体库。处理“它=最近提到的实体”“这个项目=当前域项目”。使用本地实体索引，零模型调用，100% 确定才替换。

第二层：上下文规则。读取最近 N 轮对话上下文，四元组缓存包含意图、域、权限、指代，按规则匹配指代对象。

第三层：模型兜底。仅前两层无法解决时调用模型推断，输出带置信度。

### 低置信度回问

- 低置信度指代输出 need_disambiguate 标记。
- 触发回问确认。
- 原则是一屏一决策，只问一次。

### 确认固化与缓存策略

- 用户确认后自动固化进缓存，下次直接复用。
- 缓存带过期策略，例如 7 天。
- 缓存带容量上限。

### 控制语义优先

- “打断”“暂停”“撤销”三个控制语义必须识别。
- 控制语义优先于普通指代处理。

## 验收标准与测试要点

### P0 验收

- 独立服务可部署、可启动、可热加载。
- input_raw 永久留底且不可篡改。
- 全链路轨迹 JSONL 完整，带耗时与命中来源。
- 本地规则路径小于 1ms。
- 模型兜底路径超时默认 3s 且可降级。
- 词典支持增删改、导入导出、版本回溯。
- 清洗与纠错保留原始输入与清洗说明。
- 意图 JSON 字段完整，兼容现有消费方。

### P1 验收

- 指代消解三层机制可运行。
- 低置信指代触发 need_disambiguate。
- 用户确认后缓存固化并可复用。
- 控制语义优先于普通指代。
- 上下文记忆只注入相关片段。
- 域建议默认拒绝，不猜测高权限域。
- 反馈学习闭环可落盘、可追溯、可回滚。

### 性能与可靠性验收

- 本地规则路径无模型调用。
- 模型调用有超时与并发保护。
- 超时自动降级。
- 实时请求不被异步更新阻塞。

### 数据审计验收

- 每次学习动作保留来源与时间。
- 词典与知识可导出导入。
- 轨迹可复现处理全过程。

## 待确认与后续决策

- 文档状态为定稿待评审，仍可修改。
- 全双工章节需在后续版本补充完整接口与数据模型。
- 模型中心接入方式、超时策略、并发上限需参数化。
- 缓存过期时间、容量上限、确认阈值需配置化。
- 域建议与权限门禁的边界需与 Harness 对齐。
- 所有学习动作必须落盘、可追溯、可审计。
