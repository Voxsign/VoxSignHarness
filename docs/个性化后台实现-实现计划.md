## 2. 项目目标

生成一个**独立运行的 Go 后台服务**，实现 ASR 识别文本的**个性化纠错与学习闭环**：

- 用户**教过的词**进入词典（dictionary）；
- 用户**标错的词**进入黑名单（blacklist）；
- 用户**确认过的映射**沉淀为反馈（feedback）；
- 服务要能记住这些信息，并在后续纠错中持续应用——让系统"越来越懂你"。

## 3. 技术约束

- **语言与依赖**：Go 语言，**仅标准库，零第三方依赖**（禁止引入外部包）。
- **可独立运行**：通过 flag 或环境变量配置监听地址（默认 `127.0.0.1`）与数据目录（默认 `./data`）。
- **数据持久化**：
  - `feedback` 使用 **JSONL append-only** 写入；
  - `dictionary` / `blacklist` 使用 **JSON 文件**存储。
- **代码质量**：**不留 TODO / 占位 / 伪代码**，自包含、可直接 `go build` 通过。
- **文本处理**：支持中文（UTF-8）。

## 4. 接口规格（P0 能力清单）

下列能力**全部必须实现，逐条验收**：

| # | 端点 | 行为 | 依赖数据 |
|---|---|---|---|
| 1 | `GET /v1/health` | 健康检查，返回 `{"ok":true}` | 无 |
| 2 | `GET /v1/dict` | 返回全量词典 JSON（`terms` 数组：`term` / `variants` / `category` / `source`） | `dictionary.json` |
| 3 | `POST /v1/term` | 增词（body：`term` / `variants` / `source`），写回词典并持久化 | `dictionary.json` |
| 4 | `POST /v1/correct` | 个性化纠错：输入 `{text}`，应用词典映射（如 `曼苏 → Mansour`）与黑名单拦截，返回 `{corrected, applied:[…]}` | 读 `dictionary` / `blacklist` |
| 5 | `POST /v1/process` | 意图分类 + 纠错：输入 `{text}`，返回 `{intent, corrected}`（`intent ∈ NOTE / QUERY / EDIT / …`，含纠错结果） | 读 `dictionary` / `blacklist` |
| 6 | `POST /v1/feedback` | 反馈学习：输入 `{raw, corrected, accepted, reason}`，**追加**写入 `feedback.jsonl`（append-only；`accepted=false` **必带** `reason`） | `feedback.jsonl` |
| 7 | `POST /v1/blacklist` | 黑名单：输入 `{term, note}`，写入 `blacklist.json`（语义为"这个改错了" → 纠错时跳过该词） | `blacklist.json` |
| 8 | 鉴权（可选） | 当环境变量配置 token 时，校验请求头 `Authorization: Bearer <token>`；未配置则关闭鉴权 | 无 |

## 5. 数据模型与持久化设计

### 5.1 数据文件位置

统一置于数据目录下（默认 `./data`，可通过 flag / 环境变量覆盖）：

| 文件 | 格式 | 写入语义 |
|---|---|---|
| `data/dictionary.json` | JSON | 全量读写（增词后写回） |
| `data/blacklist.json` | JSON | 全量读写（新增黑名单后写回） |
| `data/feedback.jsonl` | JSONL | **append-only**，每行一条记录，不覆写历史 |

### 5.2 词典条目结构

- `term`：标准词（目标正确形式，如 `Mansour`）
- `variants`：变体 / 误识别形式（如 `曼苏`）
- `category`：分类
- `source`：来源

### 5.3 反馈记录结构

- `raw`：原始识别文本
- `corrected`：纠错后文本
- `accepted`：是否被用户接受
- `reason`：原因（`accepted=false` 时必填）

### 5.4 黑名单条目结构

- `term`：被标记为"改错了"的词
- `note`：备注说明

## 6. 配置与鉴权

- **监听地址**：默认 `127.0.0.1`，通过 flag 或环境变量配置。
- **数据目录**：默认 `./data`，通过 flag 或环境变量配置。
- **鉴权开关**：
  - 环境变量配置 token → 开启校验，校验 `Authorization: Bearer <token>`；
  - 未配置 token → 关闭鉴权，直接放行。

## 7. 验收判据（真装配，不许桩）

1. `go build` 零错误（仅标准库）。
2. 服务启动后 `GET /v1/health` 返回 `{"ok":true}`。
3. `POST /v1/correct {"text":"你好 曼苏"}` → `corrected` 中含 `Mansour`（词典生效）。
4. `POST /v1/feedback` 后，`data/feedback.jsonl` **追加**一条记录（含 `raw` / `corrected` / `accepted` / `reason`）。
5. `POST /v1/term {"term":"Mansour","variants":["曼苏"]}` 后，`data/dictionary.json` 含该词条（持久化）。
6. **重启服务后**词典 / 黑名单仍在（持久化跨重启）。
7. 所有端点返回 JSON 响应，中文不乱码。

## 10. 风险与注意事项

- **零依赖红线**：纠错、JSON 解析、路由分发全部使用标准库实现，禁止引入任何第三方包。
- **append-only 语义**：`feedback.jsonl` 只追加不覆写，需确保并发写入下的行完整性（单行一条 JSON）。
- **持久化跨重启**：字典与黑名单必须在服务启动时从磁盘加载，避免重启后丢失学习成果。
- **中文编码**：全链路按 UTF-8 处理，响应头与响应体均需保证中文不乱码。
- **无桩交付**：所有端点为真实装配实现，禁止占位函数、TODO 与伪代码。
