## 项目定位与北极星目标

VoiceSign 个性化 ASR 后台是一套用 Go 编写的独立后台服务，接收手机端传来的语音转写文本及原始音频，完成“纠错 → 理解 → 个性化增强 → 输出标准化意图”，并在使用过程中持续学习用户口语、专名、习惯与偏好，越用越懂用户。

与 VoiceSign Harness 的关系：

- ASR 后台 = 语音输入理解层，把用户说的变成机器能执行的意图。
- Harness = 任务执行层，把意图变成真实结果。
- 两层职责不同、迭代节奏不同，必须解耦。
- ASR 后台通过标准接口输出意图 JSON，Harness 只是消费方之一。
- 未来手机 App、桌面端、其他设备均可复用同一个 ASR 后台。
- 两套代码独立仓库、独立部署、独立数据目录；仅共享“意图 JSON 契约”，契约版本化、只增不改。

北极星目标：

- 越来越懂你：持续沉淀口语说法、专有名词、指代习惯、项目背景与偏好，不依赖一次性配置。
- 语音能力很强：纠错、标点、意图理解、控制语义、语音文字双通道可用可靠，体验对标豆包语音体系。
- 响应极快：本地规则优先，模型兜底，链路微秒到毫秒级，语音说完即出结果。
- 面向未来全双工：架构第一天就为全双工实时语音交互预留接口与数据模型，未来支持边说边理解、随时打断、实时反馈。

## 个性化三层递进与实现映射

核心公式：个性化 = 数据 × 规则 × 反馈闭环。

| 层级 | 要解决的问题 | 沉淀的个性化数据 | 实现模块 |
|---|---|---|---|
| L1 听清：文本纠错层 | 错字、同音字、口语碎片、专名错误，如“季总”实际是“冀总” | 自定义词典、纠错经验库、语音置信度标记 | 个性化词典、文本清洗与纠错 |
| L2 听懂：语义理解层 | 意图是什么，“它”指什么，“那个文档”是哪个，需结合上下文与历史 | 指代消解缓存四元组、对话上下文记忆、意图置信度 | 指代消解、意图解析 |
| L3 懂你：个人画像层 | 同一个词在不同人嘴里含义不同，同一件事在不同人场景下期望不同 | 用户偏好 prefs、项目地图 project-map、决策日志 decisions-log、领域知识、使用模式统计 | 上下文个性化记忆、域建议、反馈闭环 |

实现要求：

- 数据：每一次语音输入、用户确认、纠错都留痕，append-only，形成私有复利资产。
- 规则：本地规则优先，零模型调用，保证速度与确定性。
- 反馈闭环：用户改一个字、确认一个指代、纠正一次识别，系统立即学习并固化，下次直接用。

## 系统架构与处理管线

总体架构：

- 手机端 App 采集音频。
- 系统级 / 第三方 ASR 引擎完成语音转文字，如豆包 / 系统语音转文字。
- 转写文本 input_raw 进入 VoiceSign 个性化 ASR 后台。
- 后台处理管线输出标准意图 JSON。
- 意图 JSON 通过 HTTP / WebSocket 交给 VoiceSign Harness 或其他消费方。

后台内部处理管线 1→8：

1. 留底：保存 input_raw。
2. 清洗：去语气词、重复词、口误碎片。
3. 词典：纠错、专名替换。
4. 上下文：相关性检索。
5. 指代：消解。
6. 意图：解析。
7. 域建议 + 控制语义。
8. 输出标准化意图 JSON：type、path、params、confidence 等。

个性化数据层：

- custom-dictionary
- context-memory
- user-profile
- project-knowledge
- exceptions-knowledge

分层设计原则：

- 单向依赖：管线 1→8 顺序固定，每一层只依赖前一层输出，不反向调用。
- 本地规则优先，模型兜底：本地规则无法解决时才调用模型中心；模型调用带超时，超时即降级，绝不阻塞。
- 个性化数据与代码分离：全部个性化知识存 JSON / JSONL 文件，代码只提供处理逻辑，两者独立演进。
- 输出契约稳定：对外只输出标准意图 JSON，任何消费方按契约接入。

## 接口契约与输出规范

- 输入：手机端语音转写文本 input_raw，原始音频可选。
- 输出：标准意图 JSON，字段包括 type、path、params、confidence、need_disambiguate、domain_suggestion、control。
- 意图类型：EDIT、DEBUG、QUERY、TEST、COMMIT、DEPLOY、NOTE、ASK、ORCHESTRATE。
- 控制语义：停、暂停、撤销，独立输出，优先于普通指代与业务执行。
- 域建议：仅候选，权限由 Harness 的 Space.Check 裁决。
- 契约版本化，只增不改。

## 数据文件、配置与热加载

- 词典：custom-dictionary，含 raw_speech、target、scope、priority、source。
- 上下文缓存：context-memory，四元组 {意图, 域, 权限, 指代}。
- 用户画像：user-profile、user-preferences.json。
- 项目知识：project-map.json、project-knowledge。
- 决策日志：decisions-log.jsonl。
- 异常知识：exceptions-knowledge。
- 全链路轨迹：JSONL，带耗时与命中来源。
- 原始留底：input_raw，append-only，不可篡改。
- 配置全部 JSON，不用 YAML；支持热加载，词典 / 偏好变更即时生效。
- 词典 append-only + 快照，可导出 / 导入，版本可回溯。

## 性能、降级与安全

- 本地规则路径目标 < 1ms。
- 含模型兜底路径默认超时 3s，带并发保护，超时自动降级。
- 模型兜底绝不阻塞主链路。
- 低置信纠错不静默改错，输出“疑似纠错”或 need_disambiguate，交上层回问。
- 一屏一决策，只问一次；不可逆操作仍强制确认。
- 缓存带过期策略，如 7 天，及容量上限。
- 域建议默认拒绝，未知意图落 global 只读域。
- ASR 后台只建议、不授权，权限校验在消费方执行。
