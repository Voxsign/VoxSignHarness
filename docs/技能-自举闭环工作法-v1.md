# 技能：语音产品 harness 的自举闭环工作法（v1）

> **适用范围**：voicesign-harness（以及任何"手机说→系统理解→调度执行→真实反馈"的个人底座）。
> **来源**：2026-10-01 ~ 10-03 两轮实战（9 条缺口修复 + 1 份架构级桩 + 1 次版本收敛）。
> **一句话**：**用测试桩当尺子，用异源校正者当裁判，用长任务当考场；人只保留两个动作——批注与合并。**

---

## 0. 三条不可妥协的原则

| 原则 | 含义 | 反面案例（真实发生过） |
|---|---|---|
| **判据先于实现** | 先写得出"怎么算过"，再动手改 | 用"字数 ≤8"当元指令判据 → 漏判与误判**两个方向都错** |
| **异源判分** | 判分者不得是建造者；判分只读产物，不读自述 | 只用自测 → 「8/8 通过」其实**没有样本** |
| **缺证据 ≠ 通过** | 没测到只能记 `unverified`，不得折算成好或坏 | 校验器空转被当成"标准被遵守" |

## 1. 三角色编队（本法的核心）

```
        ┌─────────────┐
        │  测试员工    │  产出：测试桩（判据的机器形态）
        │  (Stubsmith)│  只加不改；桩由他拥有
        └──────┬──────┘
               │ 红/绿看板
        ┌──────▼──────┐        ┌─────────────┐
        │   开发员工   │◄───────│  校正员工    │
        │  (Builder)  │  裁决   │ (Calibrator) │
        └──────┬──────┘        └─────────────┘
               │ 提交                  ▲
        ┌──────▼──────┐               │
        │ 人：批注/合并 │───────────────┘
        └─────────────┘   只读产物+规格，不读自述
```

| 角色 | 唯一职责 | 禁止 |
|---|---|---|
| **测试员工** | 把"承诺"翻译成可执行判据；维护红绿看板 | 不得为了让开发好过而放宽判据 |
| **开发员工** | 让红灯变绿；补回归保护 | 不得修改测试桩 |
| **校正员工** | 输入隔离盲评：只看「规格 + 产物」，判 PASS/修订/驳回 | 不得看开发的自述、不得运行代码（只静态判） |
| **人** | 批注真值库、决定合并 | —— |

**为什么要异源**：第一轮实测中，最尖锐的发现全部来自盲评，而不是自查 ——
`llmIntentFallback` 会清空 `Ask` 从而绕过安全红线（同类缺口**连踩三次**）、
否定词表漏收导致缺口**根本没闭合**。自查发现不了自己的盲区。

## 2. 单圈循环（一次"打怪升级"）

```
① 取缺口   → ② 写判据（桩，先红） → ③ 开发实现（补丁）
                                    ↓
⑧ 回写真值库 ← ⑦ 人合并 ← ⑥ 异源盲评 ← ⑤ 全量门禁 ← ④ 应用补丁
```

**两条铁律**：
- 每圈**必须**跑全量门禁（`go test ./...`）。第一轮有两次"我的设计直觉"被既有回归挡住，
  都是全靠全量门禁发现的，不是靠推理。
- 每圈**必须**有盲评。无盲评的圈不算完成。

### 缺口分级

| 层级 | 例子 | 谁来测 |
|---|---|---|
| **输入层** | `不要删除` 被判成可执行删除 | 分类器单测 |
| **行为层** | 澄清续跑死循环 | 端到端测试 |
| **架构层** | 自举链路断、校验器信自报、编排不幂等 | **架构级桩**（跨模块、破坏后无法靠补丁补救） |

> 教训：修完 9 条**输入层**缺口后，"缺口看板全绿"给人**虚假的安全感** ——
> 真正决定成败的**架构承诺**（自举充分条件、独立校验器）一条都没被测过。

## 3. 判据写法（从三次翻车里提炼）

**❌ 脆弱代理**：用代理量代替真特征
> 用"整句 ≤8 字"判元指令 → `开始部署到沙特`(7字) 是真实指令却被拦，
> `我们先开始测试吧好不好`(11字) 是元指令却漏判。

**✅ 找真特征**：判据必须能说清"为什么这个特征就是承诺本身"
> 真特征是"**元词后除动作本身没有别的实质内容**" → 两个方向同时正确。

**四条硬要求**：
1. **可机械判定** —— 不得含"合理""友好"这类形容词。
2. **可观测** —— 不得依赖被测方自述（回执 ≠ 验证）。
3. **有阈值** —— "明显改善"不是判据。
4. **双向反例** —— 至少给一个"该收未收"和一个"不该收却收了"的例子。
   > 只给单向例子 → 会写出"两个方向都错"的判据。

### 判据本身也会错

第一版 A3 判据把"没有回执"当成"没有拒绝"，实际上**系统是对的**（没有回执 = 什么都没跑 = 默认拒绝生效）。

**处置规则**：发现判据错了 → **改判据并说明理由**，**不得改系统去迁就跑偏的判据**。

## 4. 结构性守卫 > 逐条登记

同一类缺口连踩三次（G1-P4 / G3-P3 / G5-P0-1），都是：
> 「新增一条靠 `Ask` 拦住的安全分支，却忘了登记下游会清空 `Ask` 的路径」

**处置**：不再逐个登记，改立**结构性不变式**：

> 任何 `Conflict` 非空的意图，其 `Ask` 必须非空。

推论落到实现上：下游豁免逻辑应写成「**Conflict 非空即豁免**」，而不是「白名单 switch」。
**白名单必然漏 —— 结构性条件才不会漏。**

## 5. 校准闭环（本轮最值钱的一段）

**事件**：`rubric-v0` 把"安全"窄定义为 `intent == UNKNOWN`。G1 修好后系统改用 `ASK`
（**更安全**），却被 v0 判成违规。

**处置**：
1. 承认**是仪器错，不是系统错**；
2. 按反博弈要求**升版**（v0 → v1），理由必须能说清"v0 测的不是它想测的东西"；
3. **旧标准、旧哈希、旧判定全部留档，不回溯修改**；
4. 判定随之从 `support` 变成 **`refute`** —— 事前白纸黑字赌"系统做不到"，
   八条缺口修完后系统做到了，**预注册被自己的实测推翻**。

> **`refute` 往往比 `support` 更有价值**：它证明尺子在工作，而不是在自我确认。

## 6. 真值库必须能被复算

`eval/cases/cases.jsonl` 是人维护的外部真理源，但**放久了会腐烂**：
代码修好了它不会知道，`not_met` 会一直挂着。

**必备机制：漂移探测器**
```
逐条跑每行的 verify_cmd，比对声明状态与实测：
  met      → 必须退出 0
  not_met  → 必须非 0
  unverified → 不判，只报告
一致 = 可信；不一致 = 漂移，须**人工**重签（agent 不得自行改状态）
```

> 首跑就抓到真值库自身的缺陷：某行 `verify_cmd` 里未加引号的 `|`
> 被 shell 当**管道**，**这条命令根本跑不通** —— 一个声明 `met` 的条目长期无法复算。

## 7. 版本收敛（多 AI 并行时的必修课）

**症状**：两条线各自改同一批文件；`git status` 里几百行"归属不明"的改动。

**处置流程**：
1. `git fetch` → 比对 `origin/main` 与工作分支的**双向**提交差；
2. 在**独立 worktree** 里试合并（绝不污染主工作区）；
3. 冲突时先问"**哪边是超集**"，而不是逐行挑；
4. `.gitignore` / 打包修复这类**两边都做过的同一修复**，让 git 自动合并；
5. 合并后**必跑全量门禁**再推。

> 实测：26 个提交、57 个文件，**只有 1 个文件真冲突** —— 因为一边是另一边的超集。

## 8. 每圈的交付物清单（缺一不可）

- [ ] 测试桩（判据的机器形态，**先红**）
- [ ] 实现（补丁）
- [ ] 全量门禁通过（`go test ./...` + gofmt + vet）
- [ ] 异源盲评结论（PASS / 修订 / 驳回）
- [ ] 按评审修订（若有）
- [ ] 推送到远端 + **远端回读校验**
- [ ] 真值库回写**提案**（状态改动由人签）

---

## 9. 反模式清单（本法的解毒剂）

| 反模式 | 为什么致命 |
|---|---|
| 自称完成，无远端回读 | GitHub-first：本地文件不算交付 |
| 判据含形容词 | 不可判定 = 实际上没有标准 |
| 校验器信自报 | 回执 ≠ 验证 |
| 用 SKIP 当 PASS | 缺证据 ≠ 通过 |
| 无样本就报绿 | 「没有错误」可能只是「没有样本」 |
| 让被测方自填 `approved_by` | 反博弈红线 |
| 为通过而改判据 | 必须能说清"旧判据测错了什么" |

## 10. 本技能的最小可执行版本

```bash
# 1. 取缺口 → 写判据（先红）
go test -tags archstub ./e2e -run TestArch -v      # 架构层
go test -tags asrsimgap ./e2e ./server -run TestASRSimGap -v  # 输入层

# 2. 开发实现后 → 全量门禁
go test ./... && gofmt -l . && go vet ./...

# 3. 真值库复算
go test -tags evaldrift ./eval/cases -run TestTruthSourceDrift -v

# 4. 盲评（异源，输入隔离：只给规格 + diff）
# 5. 人合并 + 人签真值库
```
