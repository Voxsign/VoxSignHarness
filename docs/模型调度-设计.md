# 模型调度 · 设计文档（ModelRouter）

> 状态：设计定稿，实施中（2026-10-03）
> 触发背景：`aiops.peterzou.com/api/model/chat` 的 DeepSeek 系列上游全部 402 Payment Required
> （欠费/额度断供），而 harness 每次固定 `Get("fast")` 单点调用 → 每轮 60s 空转超时 → 骨架兜底，
> 多轮全部失败。**单点模型 = 卡死**。本设计解决：模型故障自动切换、定期健康探测、最差模型兜底。

## 1. 目标（OGSM 对齐）

- **O**：harness 语义生成永不因"单一模型/上游故障"卡死；总有可用模型继续产出。
- **G**：① 任一模型连续失败 ≤2 次即被标记 down 并跳过（不占业务重试）；② 请求在降级链内自动迁移，
  总尝试 ≤5、总耗时 ≤90s；③ down 模型每 N 分钟自动探测恢复；④ 全线上模型都 down 时落到**最差模型**
  （本地确定性兜底），仍产出可编译产物并如实打日志。
- **S/M**：真跑验证——人为把首选模型指向 402 模型，任务必须自动切到 gpt-4o-mini 并产出非骨架 main.go。
- **T**：本轮（2026-10-03）实施 + 真跑验收。

## 2. 架构（参考对齐：DeepSeek harness 无此能力，vhs 独有；对齐「架构第一原则·能力外置本机极简」）

```
                     ┌─────────────────────────────┐
  pipeline 调用点 ──▶ │  ModelRouter.Chat (降级链)   │
 (llmSummarize/       │  fast → center → strong     │
  llmGenerate/        │  → 线上最弱 → 本地兜底       │
  intent/回答层)       └─────────────┬───────────────┘
                                    │
                     ┌──────────────▼───────────────┐
                     │  HealthRegistry（内存状态）   │
                     │  per-provider: ok / down /   │
                     │  probing + consecFail +      │
                     │  nextProbeAt                 │
                     └──────────────┬───────────────┘
                                    │
                  ┌─────────────────▼─────────────────┐
                  │  ProbeScheduler（定时探测协程）     │
                  │  每 PROBE_INTERVAL=5min 对 down/   │
                  │  probing 模型发最小 ping（1 token） │
                  └─────────────────┬─────────────────┘
                                    │
              ┌─────────────────────▼───────────────────┐
              │  provider.OpenAIClient（现有单点客户端） │
              │  + 402/429/5xx 错误分类（快速短路）       │
              └─────────────────────────────────────────┘
```

**关键设计决定**：

1. **降级链 = 配置声明 + 运行时健康裁剪**：每个调用点声明 `pref []string`（如 `["fast","center","strong"]`）；
   Router 按序跳过 `down` 模型。**配置即可调整链**（`providers` 顺序 = 默认优先级）。
2. **健康状态机**：`ok` →（连续 2 次失败）→ `down` →（定时探测成功 1 次）→ `ok`；`down` 期间请求**跳过**（不试）。
3. **快速短路**：解析错误信封 `{"code":"model_upstream","detail":"HTTP 402"}` → 归类 `ErrModelDown`（**不可重试**，
   不消耗 harness 业务重试预算，直接降级）。网络超时/5xx → `ErrTransient`（可重试一次后降级）。
4. **最差模型兜底（两层）**：
   - 线上最弱：`gpt-4o-mini`（10s 生成、成本低）——配置里恒为链尾；
   - 本地确定性：`deterministicSkeleton`（现有骨架）——全部线上 down 时仍产出**可编译**产物，且 round_log
     如实记 `llm_all_down → deterministic fallback`（绝不给假 done，证据门继续把关）。
5. **不引入新依赖**：Router 用标准库，复用现有 `openaiClient`；健康状态内存态（进程内，重启自愈探测）。

## 3. 状态机与判据（每条可测）

| 判据 | 实现 | 验证 |
|---|---|---|
| 连续 2 次失败 → down | HealthRegistry: `consecFail>=2 → status=down` | 单测：注入失败 2 次后 IsHealthy=false |
| down 模型被跳过 | Router.Chat 遍历时 `if !Healthy(name) {continue}` | 单测：链 [bad,good] 只调 good |
| 402/计费错误快速短路 | 解析 body `code=model_upstream` → ErrModelDown（不重试） | 单测：mock 返回 502+body，断言不重试直接降级 |
| 定时探测恢复 | probe 协程每 5min ping down 模型，成功 → ok | 单测：手动触发 probe，断言恢复 |
| 全 down → 本地兜底 | 链尾无可用 → 返回明确错误（调用点落 deterministic） | 真跑：全部 402 → 产出骨架 + 日志说明 |
| 业务总预算 | 每次调用 ≤5 次尝试、≤90s（60s 超时 + 2 降级） | 真跑观测 elapsed |

## 4. 配置变更

```yaml
providers:
  - {name: fast,   model: deepseek-flash,  endpoint: aiops/chat}   # 首选
  - {name: center, model: deepseek-flash,  endpoint: aiops/chat}   # 次选
  - {name: strong, model: deepseek-v4-pro, endpoint: aiops/chat}   # 强模型
  - {name: gpt-mini, model: gpt-4o-mini,   endpoint: aiops/chat}   # 线上最弱（链尾兜底）
  - {name: gpt-4o,  model: gpt-4o,         endpoint: aiops/chat}   # 可用备用
# 降级链默认：调用点 pref = [fast, center, strong, gpt-mini]
```

## 5. 边界与诚实声明

- 健康状态是**进程内内存态**：harness 重启后重新探测（30s 内自动收敛），不持久化。
- `down` 判断基于**业务失败**（402/5xx/超时），不代表网络层健康；探测用最小 1-token ping 不污染业务日志。
- 最差模型兜底只保证**可编译**，不保证语义完整——证据门（go build + P0 关键字）继续为最终判据。
