设计要点

  1. 默认打开设置页即「云道 · 默认」——大部分用户永远不需要离开这个页面。
  2. 极简云道页只有 Google 登录一项，无服务器地址、无 Token 输入，登录态即服务状态。
  3. 隔离云道登录态（JWT）独立存储，与自建服务器列表互不干扰。
  4. 自建自建页默认空列表（什么都不预置），添加服务器两种方式：IP 地址 / 机器码。
  5. 机器码Harness 装机生成的机器码校验关联，自动带入地址与 Token，无需手填。
  6. 检测保存前必检连通性，不通不能保存；内网地址自动提示「通过云端转发访问」开关（外网手机经云道中转）。
  7. 状态主页连接胶囊继续沿用：云道=账户状态，自建=服务器连通性。
  8. 实现改动集中在 SettingsView + SettingsStore（新增 cloudMode 存储），不碰任务/识别逻辑。

VoxSign 连接逻辑设计 · v3

云道只做「目录 + 应急转发」，不常驻中转 —— 日常使用 90% 场景直连，云端消耗趋近于零。

1. 三种连接方式

同网直连

手机与 Harness 在同一局域网（同 Wi-Fi / 公司网 / VPN）。云道只在绑定时返回内网地址，之后手机直连内网 IP，完全不经云端。

云端消耗：零
异网 · 按需转发

手机在外网（蜂窝等），无法直达内网。仅在使用时由云道临时拉起转发通道，用完即断，空闲零占用。

云端消耗：仅使用时
组网 P2P（未来）

机器可选装轻量组网（Tailscale 类），手机装同一网络后外网也 P2P 直连，云道只做首次引导。

云端消耗：零

2. 机器码绑定时序（一次性的）

  1. 装机生成：Harness 首次启动自动生成 12 位机器码（如 AB12-CD34-EF56），保存本地，可随时查看。
  2. 注册：Harness 启动时向云道注册：机器码 + 内网地址 + 状态；此后每 2 分钟心跳，地址变化即上报。
  3. 输码：iOS 输入机器码 → 调云道 POST /v1/devices/lookup。
  4. 校验：云道验证机器码 → 返回机器身份 + 内网地址 + 在线状态。无效/离线 → 提示无法绑定。
  5. 直连探测：iOS 直接探测该内网地址的 /v1/health：通 → 保存为「直连」服务器；不通 → 保存为「云道转发」服务器。
  6. 检测门：保存前必检连通（直连=探测内网；转发=探测转发通道），不通不能保存。
  7. 日常：同网直连不经云道；异网仅在访问时临时建转发通道，用完即断。机器码只在绑定用一次，后续本地缓存。

5. iOS 服务器条目状态机

绑定中 → 在线 · 直连 / 在线 · 转发 / 离线 / 无效机器码

每条自建服务器保存时记录：绑定方式（IP / 机器码）、连接方式（直连 / 转发）、最后检测时间；列表展示状态点（绿=在线直连，蓝=在线转发，灰=离线）。

6. 实施顺序

  1. iOS 全面更新：云道/自建两模式 UI；机器码表单 + lookup 绑定流程 + 直连探测；服务器条目状态化。
