## 一、根本目标（北极星）

**用户原话（逐字，作为北极星引用）：**

> 「我为什么用你这个事就是因为豆包的语音识别效率比较高，用手机比较方便。其实我要的就这么简单个东西……那我的 harness 也比豆包的 harness 要好就行了。」

**北极星一句话：** 语音说 → 系统理解 → 调度执行 → 真实反馈的闭环，体验与效率 ≥ 豆包体系。

**选豆包的唯一理由 = 语音识别效率高 + 手机方便；harness 的意义 = 在语音与手机上比豆包更好用。**

| 要点 | 含义 |
|-|-|
| 竞争力在哪 | 不在语音层（ASR 是及格线），而在 harness 层：理解 → 调度 → 执行 → 验证 → 回执 → 归因 |
| 根本闭环 | 说一句话 → 被正确理解 → 系统替我做该做的事 → 手机上看到「做了什么、对不对」的真实结果 |
| 产品定位 | 手机 = 控制器，电脑 = 执行引擎；目标是「10 倍的自己」，不是短期赚钱 |

## 二、验收标准（"比豆包 harness 好用"的可验收定义）

**五维验收（来自 Claude Code 需求分析）：**

| 维度 | 可验收定义 |
|-|-|
| 真理解 | 同一句只问一次，长口语句不退化成 UNKNOWN |
| 真执行 | 真能替用户做事（改文件 / 跑测试 / 提交 / 记笔记），不是只能说不能做——这是分水岭 |
| 独立 verify | 执行完读实际状态 diff，不读执行器自报 |
| 实质回执 | 回执有实质内容，不靠「OK」空壳糊弄 |
| 归因记忆 | 分得清「理解错 vs 执行错」并沉淀成下次更准的规则 |

**闭环体验指标：**

- 说话 → 回执有实质内容的时延与成功率持续可测。
- 需要用户二次澄清的次数趋近于零；仅「真歧义 + 高风险 / 不可逆」才允许反问。

**性能与门禁红线（保持既有门禁不破）：**

| 红线项 | 标准 |
|-|-|
| 性能基线 | 5.7µs 级基线不被破坏 |
| go test | 全绿 |
| DevCheck | 71/71 |
| 真机 XCTest | 15/15 |

## 四、推进路线（按里程碑，每步带验收标准）

| 阶段 | 里程碑 | 范围 / 交付物 | 验收标准 | 明确不做 |
|-|-|-|-|-|
| 近期 | **M8 · 语音闭环最小集** | 修通 3 个 bug + 四类降级铁律（不卡死 / 不空壳 / 不乱反问 / 低置信强制升风险）+ 规则为主、模型兜底 | 用户真机重测两句通过：复杂问句得真回答、NOTE 绿色回执带撤销；语音标点反差验证通过 | 不做新意图类型、不合 v2.1 规则、不做自生长 |
| 中期 | **M9–M10 · 意图 / 讨论 / 控制三环强化** | 指代消解、风险三信号矩阵、verify 扩面（EDIT/DEBUG）、归因回写自动闭环 | 同类任务一次比一次顺：可测的重复澄清率下降、回执实质内容率上升；至少 3 条「归因→确认→规则更新→下次改善」案例链 | 不做跨 session 长期记忆检索、不做无人工确认的自动改规则 |
| 长期 | **M11+ · 自生长** | 语音注册词典 / 域 / 契约、边界审计循环、认知闭环周期可测缩短 | 用一句话教会系统一个新识别规则 / 新域边界，无需工程师改代码；闭环周期数字可见且持续环比缩短 | **任何新契约 / 新域仍需人工确认，不做无人自治**；不追求「完全不需要人」 |

**铁律：三阶段严格前置不跳步。** M8 先拉到「不比豆包差」（不空壳 / 不乱反问 / 不卡死）→ M9–M10 让豆包没有的能力稳定可用 → M11+ 让「懂你」可量化可加速。若跳过 M8 直接做自生长，只会把「经常空壳、经常反问」放大——这正是要避免的「折腾」。
