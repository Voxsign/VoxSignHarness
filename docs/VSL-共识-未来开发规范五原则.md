# VoxSign 共识 · 未来开发规范五原则

- 版本：consensus-v1.0 · 2026-10-02 · 经用户拍板 + 多模型评审（Codex/Cursor/Claude）
- 状态：**已确认共识**（用户：先保存起来成为我们的共识）
- 适用：VoxSign Harness 及一切后续开发的规范层设计

## 核心命题

> **未来规范 = 可验证的共识协议（Verifiable Consensus Protocol），不是文档。**

时代变化本质：规范的第一读者从"人"变为"LLM"；产出从"人敲代码"变为"模型生成"；评审从"人 Code Review"变为"多模型交叉 + 人拍板"；修改从"改文件"变为"语音对话增量演进"。**规范的作用从"指导人怎么写"变成"约束模型怎么生成"。**

## 五原则

| # | 原则 | 含义 | 反例 |
|---|---|---|---|
| 1 | **约束驱动** | 规定"什么禁止、什么必须验证、什么是完成"；绝不规定实现细节 | "函数应该小于 50 行"（实现规定）|
| 2 | **机器可读优先** | manifest/contract/policy 用 YAML/JSON/DSL 形态（第一读者=模型）；自然语言只是人看的外壳 | 只有散文式需求描述 |
| 3 | **每条规范带验证器** | 规范条目 = 声明 + 可执行断言；无验证器的条目 = 未完成 | "做好边界检查"（无断言）|
| 4 | **活的规范** | 版本 + diff + 失效机制；追求快速共识→快速验证→快速演化，不追求一次性冻结 | 冻结的静态需求文档 |
| 5 | **伪代码层 = 共识层** | 人机对话在伪代码层确认意图、约束生成、完成评审；它是未来开发的主工作面 | 跳过共识层直接生成代码 |

## 落地强化（对照本项目已有体系）

1. **规范条目 ↔ 验证器一一对应**：SPEC 验收用例升级为"验证器清单"，每条可复现
2. **机器可读优先**：VSL 定义块同时给出 YAML 形态（机器执行）+ 一句话人话（人看）；"自然语言优先"原则保留在最外层
3. **伪代码层作为主共识层**：所有开发讨论先在伪代码层达成共识，再生成代码

## 表述规范（配合 BOUNDARY-AUDIT §7）

- 流程/控制流：代码骨架 + 自然语言注释（CLRS 式）
- 语义/规则：自然语言 + 标签（Gherkin 式）
- 状态复杂：补状态图/流程图
- 铁律：伪代码不可编译；写着写着发现是"规则定义"→ 搬回 VSL；说不清 → 画图
