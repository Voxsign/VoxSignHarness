# 评审报告 · 指代固化 × 线 C 技能层（怎么做，评审后安排）

> 评审对象：① 指代固化（ASR 产品 L2 功能，用户强调**不要写死代码、尽量通过机制优化**）；② 线 C 技能层验收（harness 能力验收）。
> 评审原则：需求原文依据 + 代码现状真值 + 候选方案对比（改动量/职责/可扩展/可验证），结论给推荐与编排。

## 一、指代固化：先明确需求本意

需求说明书 L2 指代消解三层（§4.3）：**候选生成 → 低置信回问确认 → 固化复用**。

- 用户说「把**那个**接上」→ 系统产出候选（多候选时 need_disambiguate=true 回问）
- 用户确认（"AIOps"）→ 系统应**记住**：「那个」在**本会话**里 = AIOps
- 下次同会话再说「那个」→ **直接命中，不再回问**

**现状实测**：need_disambiguate=true ✅（回问能力在）；**固化+复用 ❌ 无**（traces 显示每次 ASK，无记忆）。

## 二、指代固化：候选方案评审

| 方案 | 做法 | 改动量 | 职责 | 可扩展 | 可验证 | 评审 |
|---|---|---|---|---|---|---|
| A. 硬编码规则表 | 代码里写死常见指代词→目标映射 | 小 | 错位（指代是数据不是代码） | 差 | 差 | **否决**（用户明确不要写死） |
| B. 词典机制复用（数据驱动） | 确认结果写入词典条目（term=指代词,target=对象,scope=global），复用现有 add/list/持久化/ops.jsonl | 极小（词典已可用） | 词典语义=纠错词对，指代语义=上下文绑定，**语义略偏移** | 中（全局固定指代可沉淀） | 直接（现有接口即测） | ⚠️ 可作**全局高频指代**的沉淀层 |
| C. **上下文槽（数据驱动，推荐）** | `conversation_id → mention → target` 映射，JSONL 持久化（append-only，仿 traces）；确认时写槽，同会话再 input 先查槽命中 | 中（新增一个存储结构，约 30-50 行，复用 Tracer 写盘模式） | **正确**（指代天然是上下文相关的） | 高（槽可扩展为画像 L3 底座） | 直接（确认→复用闭环真跑） | ✅ **主方案** |
| D. 技能化（用 validate-align 等技能处理） | 把指代固化交给技能系统 | 大 | **错位**（产品功能≠技能；技能是 harness 执行能力） | — | — | **否决**（过度设计） |

**评审结论（推荐 C 为主 + B 为辅）**：
1. **主：上下文槽 C**——数据驱动、会话级、持久化、可复现；不写死，靠「确认写入→查槽命中」的数据闭环
2. **辅：B 复用词典**——跨会话高频指代（"那个"长期指 AIOps）可沉淀为词典条目，复用现有机制
3. **不用技能**：指代固化是产品业务逻辑（L2 层），技能是 harness 的调用能力，两者不互换
4. **验证闭环**（L-01.5）：构造多候选→回问→确认→**同会话再次输入直接命中**（无 need_disambiguate）

## 三、线 C 技能层：评审处理路径

**目标**：harness 技能调用链真装配可验（发现→选择→调用→产出证据）。
**现状**：tools/skill 包在 pipeline/server **零接线**（grep 空）→ 现在验收必红。

**评审结论：判据先行 → 接线 → 验收**（三步序，避免"先修后验无标尺"）：

| 步骤 | 内容 | 责任方 |
|---|---|---|
| 1. **判据先行**（线 C 验收标准 C-01..04 定稿） | C-01 技能发现（任务命中技能域）· C-02 技能选择（从技能清单选出正确项）· C-03 技能调用（真装配走技能执行路径，产出可验证结果）· C-04 证据（调用链留痕 traces） | 测试方（本侧） |
| 2. **接线** | harness 接入 skill 包（fetch→select→execute→evidence 链） | 实现方 deepseek（工单） |
| 3. **验收** | 真装配起服务→长程任务→C-01..04 逐条取证 | 测试方（本侧） |

**为什么先定判据**：能力验收必须有标尺（校准的「判据先于实现」原则）——否则 deepseek 接完线没有验收基线，又会"自测算数"。

## 四、编排安排（评审后建议）

1. **P0**：线 C 判据 C-01..04 定稿落盘（测试方，本轮可做）→ 发工单给 deepseek（接线）
2. **P1**：指代固化上下文槽 C 实现（deepseek，vhs-asr 代码）→ 补测闭环（测试方）
3. **P2**：B 辅助沉淀（跨会话高频指代进词典）
4. **P3**：线 C 验收（harness 接线后真装配）

**依赖**：线 C 验收依赖接线；指代固化不依赖线 C（两个独立线，可并行推进）。
