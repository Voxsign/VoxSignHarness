## 3. surfaced finding（#17/#18/#20 想法库碰撞）——**已修复，验证器回正**

**首版现象**：#17「把想法库那几个旧标签改成一个新标签」、#18「上次那个想法库里面记的报价客户是哪家」、#20「把想法库的内容发到外部 markdown 文件」三条，本应是 EDIT / QUERY / DEPLOY，却全部被判成 NOTE（17/20）。

**根因**：`input/taskintent.go` 的冲突仲裁里，`thoughtWords = ["想法","备忘"]` 用**裸子串匹配**，且优先级高于单类触发词与「把 X 改成 Y」。注册空间名 `vaultnotes` 的别名就叫「想法库」——文本里出现「想法库」三字，必然命中「想法」，于是触发 `note_vs_deploy` 仲裁直接返回 NOTE。#18 另有次因：noteTriggers 含裸「记」，「记的」被误触。

**为什么这是好结果**：第一周方向验证的目的就是在写功能前暴露这种「触发词表 vs 真实语料」的碰撞。它正好落在 SPEC v2 缺口 #8（REGISTER_TOOL/子动作归属）与 #10（意图-域冲突）的交叉点。

**修复（组织者已改 input/taskintent.go）**：
1. 文本命中的注册空间名/别名含「想法/备忘」类词时，**跳过 thoughtWords 仲裁**（「想法库」是实体名，不是记想法触发）；
2. noteTriggers **移除裸「记」**，补「记录一下/记录」——子串「记的/记忆/忘记」不再误触 NOTE。

**验证器回正**：`input/taskintent_20sample_test.go` 中 #17/#18/#20 的断言已由 NOTE 改回 EDIT/QUERY/DEPLOY，`go test ./input -run Test20Sample` 转绿，通过率升到 **20/20**。

**分片边界声明**：本分片 A 不改 `input/taskintent.go`（只读消费）；修复由组织者在其地基代码上完成，A 负责把断言与文档同步回正。

## 4. 其它观察（不阻塞 M2，记录备查）

- **#1 EDIT 槽位粗糙**：`把那个错误提示啊改成中文，就 voxbuybot 下单页那个` → `value="中文,就 voxbuybot 下单页"`（`extractReplace` 按第一个「改成」切，未剥尾部补充从句）。意图对，object/value 槽位噪声大。裁定：M2 靠 refer/规划层重抽，不在分类器加 NLP；SPEC v2 缺口 #26 记。
- **#7/#11 词典纠错路径有效**：`季总→冀总`、`彼得周点com→model.peterzou.com` 真发生，且 `Corrections` 记录留痕（归因=input 格）。符合「模糊→精确闭环」预期。
- **时间锚点**：#2「昨天」→2026-10-01、#3「周五」→今天(周五)、#7「下周一」→2026-10-05、#11「今天」→2026-10-02，均正确落 `time_hint`/`time_date`。
- **不可逆基线**：#9/#14 DEPLOY → `confirm=human`（不可逆，永远人工）已由分类器基线给出；risk 包会用机械信号重算。
- **填充词容错**：「帮我…那个…啊」被 Cleaner 正常剥除，不影响分类。
