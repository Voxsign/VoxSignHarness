# 校验与对齐 v2（实证校准版）

## 为什么 v1 错了（2026-10-03 复盘）

v1 只做**文本级三查**（脚本读 criteria 字符串查模糊词），不读实现代码、不真跑、不调用模型 → 给出 90/100 对齐度，但实际值很差。**纸上校准 = 一塌糊涂**。
规则：**没有代码证据和运行证据的评分一律无效**。

## 三层取证（缺一不可，逐层落证据）

| 通道 | 做什么 | 取证手段 | 产出 |
|---|---|---|---|
| **D 文档校准** | 需求文档 ↔ 判据提取：三查（完整性/一致性/可验收性） | 读需求原文，判据 SMART 化（模糊词量化） | 判据清单（可测） |
| **C 代码校准** | 判据 → 实现代码真值：存在性/结构/接线 | git grep + Read 源码：接口、结构、调用链 | 每条判据的代码证据（文件:行） |
| **R 真跑校准** | 判据 → 运行时行为：起服务、打接口、断言 | 真装配（不许桩）：build+serve+curl/脚本 | 每条判据的运行证据（响应/日志/数据） |

**评分规则**：每条判据 PASS = C 证据 + R 证据**双证齐**；只 C 无 R = ◐ 待真跑；只有文档 = ✗。
**对齐度 = PASS/总判据 × 100**；评分必须附证据链（判据→文件:行→响应/日志），无证据链的分数不采信。

## 双向目标（校准必须分对象取证，不许混层）

校准输入必须显式区分两类目标，分开评分：

- **产物验收**（第 11 章）：对产物（如 vhs-asr）取证——文档/代码/真跑三通道
- **能力验收**（H 系列：harness 能否产出）：对执行主体（harness）取证——规划/执行/终态/复跑

**混层 = 判据错误**（v1 把产物验收当能力验收打分，导致 90 分假象）。

## 远程模型调用（语义级判断，不许本地文本猜）

以下判断必须远程调用模型中心（如 deepseek-v4-pro / aiops 网关），不在本地做字符串匹配：

1. 需求语义 ↔ 代码语义是否对齐（"需求说 X" ↔ "代码实现 X" 的语义等价）
2. 意图覆盖判定（任务表述是否落入意图语义范围）
3. 歧义消解（需求歧义 → 模型给出候选并标注影响）
4. 跨文档一致性（需求 v2 ↔ 规格文档 ↔ 验收判据）

调用方式：经 harness 模型中心 / aiops 网关远程执行；模型输出纳入证据链。

## 校准核心要素（理念层 · v2.2 整理）

校准不只是「判据 ↔ 实现」的打分。任何系统/方案按 **三轴** 校准，缺一不可：

### 轴 1 · 对齐轴（需求 ↔ 实现，v2 已建）
目标对齐 → 判据对齐（D/C/R 三层取证 + 双证）→ 语义对齐（远程模型）。

### 轴 2 · 工程轴（实现本身是否健康——七要素必查）
| 要素 | 必问 | 取证方式 |
|---|---|---|
| **架构** | 分层/模块边界是否清晰？依赖方向是否合理（谁依赖谁）？**数据怎么传输**（接口契约、数据流路径、序列化、跨服务边界/网关）？ | 读代码：调用链/接口签名/配置文件；画数据流 |
| **性能** | 关键路径热不热？缓存/IO 是否合理？瓶颈在哪（实测定位，不许猜）？ | 压测 + 分层计时（如 traces 分步 ms） |
| **核心实现逻辑** | 核心机制是否成立、是否串成闭环（如 输入→纠错→记忆→意图→反馈→学习）？ | 读核心链路…
